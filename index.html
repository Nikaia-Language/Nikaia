A programming language · pre-alpha

Write what should happen.
The compiler decides how.

Nikaia reads like a scripting language and compiles like a systems language. No async/await, no garbage collector, no manual memory management, and data races are refused before the program runs.

Good wins.

Two files at once. No async in sight.

Reading a file pauses the function without blocking the program, and you write it as an ordinary call. Where you want things to happen together, you say so: overlap runs its lines at the same time and waits for all of them.

Whether this runs on one core or on all of them is one line in nikaia.toml. The code does not change.

The whole language on one page →

use std::fs

fn size_of(path: ref String) -> i64 throws {
    let text = fs::read_to_string(path, fs::Root::Anywhere)
    return text.len()
}

fn main() throws {
    let (a, b) = overlap {
        size_of("a.txt")
        size_of("b.txt")
    }
    println(f"{a + b} characters in both files")
}

Most languages ask you to pick a side

Easy languages

Python, JavaScript

You write what you mean, quickly, and pay later: slower programs, more machines, and mistakes that show up in production, under load, at night.

Fast languages

C++, Rust

You get the whole machine, and pay up front: much of every program explains to the compiler how memory, waiting and sharing should work.

Nikaia

the explaining is the compiler's job

A compiler that sees the whole program can work that out itself. You write straight, readable code; it translates to Rust and lets Rust's compiler guarantee the rest.

What that looks like

Waiting is not your problem

Code that reads files or talks to the network looks like any other code. No keyword says "this might wait", and the program never sits idle while it does.

Mistakes caught before it runs

Two tasks changing the same data, a value that might be missing, an error nobody handles: refused at compile time, with a message that says what to write instead.

No garbage collector, no free

Memory and files are released at a point you can see in the code. No pauses, and nothing to clean up by hand.

One core or all of them

Whether your code uses one core or every core is one line of configuration, not a rewrite. The same source is correct either way.

Formats are part of the language

Logs, protocols, your own little language: describe the format as a grammar and get a parser, instead of splitting strings by hand.

Errors in plain words

A mistake is explained the way a colleague would: what you wrote, why it cannot work, and what to write instead, with the places it is about underlined. See one below.

When something is wrong, it says so like a person would.

The compiler points at every place the explanation needs: ^ under the line with the mistake, - under the line that explains it. Then it says what to write instead.

No jargon about lifetimes or borrowing, and never an error about generated code you did not write.

Pre-alpha, and honest about it

The compiler builds real programs today: a calculator, a JSON parser, a log analyser, a small HTTP server, the One Billion Row Challenge. There is no package registry, test runner or editor integration yet. The roadmap lists what works, the walls you will hit, and where a bug report helps most.
