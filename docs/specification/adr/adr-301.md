## 1. Question

**What may stand in the head of an `if`, a `while` and a `for`?**

The head has a grammar of its own for one reason: in `for d in whole { … }` the
`{` opens the body, so a head may not contain a form that begins with a brace —
a struct literal above all. That chain was built by copying the ordinary one
and stopping early, and more stopped than the brace-led forms:

```text
if a && b { … }          expected `{`; found unexpected token `&`
if a ?? 0 > 3 { … }      expected `{`; found unexpected token `?`
if a as i64 > 3 { … }    expected `{`; found unexpected token `as`
if a == null { … }       expected one of: `!`, `-`, `false`, `true`; found `null`
if (a, b) == pair { … }  expected `{`; found unexpected token `,`
```

Part I 3.2 wrote a condition as *a `bool`* with no restriction on what may
produce one. A head that takes `false` and refuses `null` is not a restriction
anybody could deduce.

## 2. How others do it

The old records compared nothing outside this language; the question was one of
consistency with its own body grammar, and the comparison that settled it is
the one in §1: the same expression in a body and in a head.

## 3. Options, weighed

| Option | Lost because | Was |
| :--- | :--- | :--- |
| Add only what a program has run into (`&&`, `||`), leave `??` for a reproduction | a reproduction is evidence for adding a construct, not for an inconsistency in where an existing one may stand; waiting only means the next person meets it, and the gap turned out to be four forms, not one | this record's D6, withdrawn by this record's D6 |
| Keep a list of what the head takes (*`&&`, `||` and `!`*) | a list of the same kind produced the defect; the page now states the rule | ADR-301 |
| Make brace-led forms unavailable in a condition | a language restriction needing a justification; the actual constraint is only on the token that opens a body | this record's D5 |
| Order `head_primary` as `primary_expr` orders it | a PEG alternation is ordered, so a rare alternative in front costs every common one behind it (D7) | this record's D7 |

## 4. Decision

### D1 — `&&` and `||` are in the head, mirroring the ordinary chain exactly.

`||` binds looser than `&&`, which binds looser than a comparison, and a range
looser than all of them, as everywhere else: `if a || b && c` is
`a || (b && c)`.

### D2 — What a head must keep out is what stands immediately before the body's `{`.

An operator that cannot begin a block and does not end an expression — after it
comes another operand, which descends to the same brace-free primary — leaves
the token before the body's `{` drawn from the same set as before. That is the
argument for every level the head takes.

### D3 — A head parses the same language as a body, minus exactly the forms a `{` begins.

A head that differs from the ordinary grammar in any other way is a trap rather
than a restriction: the program reads as valid Nikaia and is refused for a
reason no rule states, or accepted with another meaning. So the head chain is a
copy with **one** difference, in `head_primary`, and a level missing for any
other reason is a defect.

### D4 — The head chain holds every level and every primary that is not brace-led. There is no exception.

Top to bottom: `??`, range, `||`, `&&`, comparison, `+`, `*`, `as`, unary,
postfix, primary — the ordinary chain, level for level, with the same
associativity and precedence. `head_primary` is `primary_expr` minus a list that
can be written out: `struct_lit`, `block_expr`, `if_expr`, `match_expr`,
`overlap_expr`, a `dsl … { … } eod`, and `spawn`, whose lambda is a brace.
`null`, a tuple and `dsl … from …` are in it.

### D5 — A brace-led form is excluded from a spelling, not from the position: parentheses reach it.

```nika
if p == (P { x: 1 }) { … }
if (match n { 1 => 10, else => 20 }) > 15 { … }
```

`paren_expr` takes a whole `expr`, so a head may hold anything the language has,
and a form that **starts** with a brace is parenthesised so that the body's `{`
is still the body's. The restriction is *the token that opens a body is the
body's*, with a one-character way round it.

### D6 — What belongs in the head is decided by D3's rule, not by a reproduction.

A reproduction is the right evidence for adding a construct to the language and
the wrong evidence for an inconsistency in where an existing construct may
stand. The question *does this already exist everywhere it should* is answered
by the rule.

### D7 — Where an alternative goes in `head_primary` is measured.

`dsl … from …` goes **last**: at the front it was a failed keyword match before
every primary in every head, and `if { }` answered with `dsl` first in its
expectation list. `null` goes **after the literals**, not beside `false`: third
in the list it cost **0.45 %** of a compile on a head-dense file. Neither word
can be taken by another alternative, since both are reserved. A PEG alternation
is an ordered list, so where a rare alternative sits is a cost paid by every
common one behind it.

### D8 — What it costs, and it is accepted.

Every level is descended for every head, whether used or not. Measured by two
builds differing only in these rules, five runs each, medians
([ADR-276](adr-276.md) D19's method; the baseline for the second step was the
parser as ADR-301 left it, from git, not a hand-edited revert):

* `&&` and `||`: **2,536 instructions per head**, +0.15 % to +0.41 % of a
  compile on `examples/` (this record's D8).
* The complete head: **5,016 instructions per head**, +0.5 % to +1.2 % of a
  compile; `as` and the new primaries are paid per operand, not per head
  (this record's D8).

What is bought is not a few constructs but a position that can be described in
one sentence.

## 5. Consequences

* **Part I 3.2 states the rule**: a condition is an ordinary expression, and an
  expression that starts with a brace is parenthesised. It names no list.
* **[ADR-276](adr-276.md)'s first row measured this gap, not `break`.** With
  `while i < n && running` writable, a flag and a `break` cost the same — 165
  instructions apart over two million turns; the −25 % was the nested `if` the
  head forced. ADR-276's decision did not rest on that row (its `for` row
  decided it), and the benchmark keeps the old shape beside the new one
  ([ADR-301](adr-301.md); that record is now held by [ADR-276](adr-276.md)).
* **`??` binds looser than a comparison in a head exactly as in a body**:
  `a ?? 0 > 3` is `a ?? (0 > 3)`. Whether that precedence is right is a question
  about `??`, not the head's ([#214](https://github.com/Nikaia-Language/Nikaia/issues/214)).
* A parse error in a head is a few frames deeper and offers more in *also
  possible here*, the trade every precedence level makes.
* An `if` statement's head is parsed twice, because `assign_stmt` is tried
  before `expr_stmt` and the ordering is load-bearing (`x = 1`); a per-head
  number for `if` is double a `while`'s for that reason
  ([ADR-301](adr-301.md)).
* Tested in `crates/nikaia/tests/jumps.rs`; `a_head_parses_what_a_body_parses`
  lowers the same expression in both positions and compares, so a missing level
  and a badly mirrored one both fail it.

## 6. What this does not decide

* **`??`'s precedence against a comparison** — [ADR-278](adr-278.md) D15's
  question, on [#214](https://github.com/Nikaia-Language/Nikaia/issues/214) as
  a suspicion with its reproduction.
* **The double parse of an `if` statement's head.** Known and measured, and not
  changed, because the statement order needs it.
