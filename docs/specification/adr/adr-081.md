# ADR-081: A `+` Over Text Is a Call, and an Expression Gets a Span to Key It By

**Status:** Accepted · **Built:** yes — see §6
**Date:** September 15, 2026
**Target Version:** Nikaia 0.0.8
**Related:** [ADR-285](adr-285.md) D1 (the trait that made one index rule work
everywhere — this is that arrangement a third time), [ADR-285](adr-285.md) D5
(the overflow abort, which is what keeps arithmetic out of it),
[ADR-288](adr-288.md) (the channel the checker hands answers over, which this
gives its first expression-level key), [ADR-296](adr-296.md) D17 (the emitter
knows no types)

## 1. Context

Three of the four ways a program can join text went to the language below and
were refused there. Measured, with `s` and `s2` being `String`:

| written | what the language below said |
|---|---|
| `"a" + "b"` | `error[E0369]: cannot add &str to &str` |
| `"a" + s` | `error[E0369]: cannot add String to &str` |
| `s + "b"` | compiled |
| `s + s2` | `error[E0308]: mismatched types` |

Rust's own rule — `String + &str` and nothing else — reached the user unchanged,
about a file nobody wrote, which is [Part III C.1](../30-nikaia-tooling.md)'s
class. This language's `+` says nothing about which side is owned and should not
have to.

**And the checker got it wrong first**, which is the worse half. `"User: " +
self.username` came to a `&str`, so a function declaring `-> String` was refused
as `NK1104` — a **false** refusal, and [Part III C.4](../30-nikaia-tooling.md)
says this compiler never refuses a correct program. Part I 4.7 wrote that line as
its own example.

## 2. Decisions

### D1 — `Expr::Binary` carries a span, and it is the operator's.

The first expression-level span in this AST. `contracts/sync.rs` has called them
open work in its own words since it was written; this is one of them, added
because an answer had to be keyed by **which** `+` rather than by the statement
around it — `a + b + c` is two of them, and every other answer in ADR-288's
channel is keyed by a statement because every other answer is about one thing per
statement.

The **tail's** span — the operator and what stands to its right — rather than the
whole expression's, because that is what the grammar has in hand where the node
is built, and uniqueness is the only property a key needs.

**One variant and not every expression**, because one variant needed it. A field
nobody reads is a field that goes stale, and the next one that needs a span will
know where to put it.

### D2 — A `+` where either side is text lowers to `nikaia_std::concat::plus`, and its result is a `String`.

A trait with an impl per shape, and the language below picks — which is
[ADR-285](adr-285.md) D1's own sentence a third time: *this emitter does not know
types, and a rule applied everywhere cannot be applied to the wrong thing*.

**What that buys is not merely working.** Each shape keeps the lowering that
suits it, so the one that already compiled is unchanged. Three million
concatenations, best of three:

| | time |
|---|---|
| `String + &str`, as it lowered before | 42 ms |
| `format!("{}{}")` for every shape | 250 ms |
| through the trait | **42 ms** |

The obvious single rule — lower every concatenation to a `format!` — would have
been a **sixfold regression** on the one form that already worked. The rule *is*
the table of four cases, written once in `std` instead of four times in the
emitter.

**And the result is a `String`.** That is a decision and not an inference: a
concatenation makes a new value, so there is nothing else it could be, and saying
`&str` is what made `-> String` a false refusal.

### D3 — A number's `+` does not move, and that is what makes D2 narrow.

A trait over `+` would take numbers too, and a number's `+` may not leave this
language's own crates. [ADR-285](adr-285.md) D5 turns `overflow-checks` on **per
Nikaia crate** while the profile turns them off, because a foreign crate's hash
function wraps on purpose — and `nikaia_std` is on the foreign side of that
split. Measured, with the same profile shape:

```text
a + b in the checked crate                    → aborts
the same a + b through an #[inline] helper    → -9223372036854775808, silently
in the unchecked crate
```

**Inlining does not carry the check across**: it is decided where the code is
*written*. So any arithmetic moved into a `std` helper silently loses the abort
this language promises. `index::at` escapes it only because its conversion is an
explicit `try_from`, and `index::set` because it does no arithmetic at all. That
is a trap for the whole family of these decisions and it is written down here
rather than left to be met again.

## 3. Consequences

**Part I 4.7's `"User: " + self.username` is no longer refused by the checker**,
and Part I 6's `println(prefix + "System started")` compiles — the specification
sweep's compile baseline moved one line from `error[E0369]` to `compiles`.

**Three of the four shapes became programs**, and the fourth is unchanged in
speed and in what it allocates.

**The channel has an expression-level key**, which the next answer about a
sub-expression can use instead of inventing a positional one.

## 4. What this does not decide

* **`+=` over text.** `s += "x"` is a compound assignment and goes through a
  different arm; it is not read here.
* **What counts as text.** `String` and `&str`, and deliberately not a `T?`:
  `maybe + "x"` is a member reached off a nullable, which Part I 2.3 answers and
  this must not quietly paper over.
* **A `+` where neither side is known.** It still says nothing and is emitted as
  it was written, which is what stops a `Vec`'s length from being silently
  turned into a string.
* **Spans on every other expression.** D1 adds one where one was needed. The
  rest stay as they are until something needs them.

## 5. What is built

`ast::Expr::Binary::span`, filled by `fold_binary` from each operator tail, and
the eight grammar rules that feed it; `Checked::concatenations` and the
`Propagation` member beside it; `nikaia_std::concat` with four impls and
`concat::plus`; the emitter's arm that writes the call where the checker said so.
Exercised by six programs in `crates/nikaia/tests/concatenation.rs`, one of them
run over all four shapes, and by three tests in `nikaia_std::concat` that hold
the buffer-reuse property by pointer identity rather than by description.
