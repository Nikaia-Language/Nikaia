# ADR-203: An `enum`'s Cases Are a Column of the Ledger, and a Unit-Only `enum` Compares

**Status:** Accepted · **Built:** D1, D2 and D3 at 0.0.179
**Date:** September 23, 2026
**Target Version:** Nikaia 0.0.179
**Related:** [ADR-146](adr-146.md) D1 (a `match` covers every case, and why an
`else` is the expensive way out), [ADR-106](adr-106.md) D3 (the table of ledger
entries), [ADR-028](adr-028.md) D5 (the ledger records what a consumer may
reach), [ADR-160](adr-160.md) D4 (a `match` over a `catch`'s error),
[ADR-158](adr-158.md) D1 (the variant is the kind and it carries the thing),
[ADR-018](adr-018.md) D4 (the request's `Method`)

## 1. Context

A `[type."X"]` entry carries a `struct`'s `fields`. It carried nothing at all
for an `enum` — an `enum` had **no entry**, so a consumer of a package could not
see that its cases were `Yes` and `No`, and

```nika
match verdict::of(word) {
    verdict::Answer::Yes => { println("yes") }
    verdict::Answer::No  => { println("no") }
}
```

was `NK1151`, *this `match` does not cover `else`*. Two things are wrong with
that at once. It is a **correct program refused** ([Part III
C.4](../30-nikaia-tooling.md)) — the two arms are the whole type. And the way out
it offers is the one [ADR-146](adr-146.md) D1 exists to prevent: an `else` makes
*the type gaining a variant* silent in that program forever after, which is the
whole reason the rule is a refusal rather than a warning.

Two smaller things were found by the same program.

**`==` on a declared type has no lowering.** `k == Kind::Post` — for an `enum`
declared in the same file — reached `rustc` as *binary operation `==` cannot be
applied to type `Kind`*, with *consider annotating `Kind` with
`#[derive(PartialEq)]`* as the help: the backend's words about a file nobody
wrote, and a way out the source cannot take ([Part III C.1 and
C.2](../30-nikaia-tooling.md)).

**And a `match` over a `catch`'s error was the backend's too.** A handler that
takes `io::IoError` apart and misses a case got *non-exhaustive patterns:
`IoError::NotText(_)` not covered*, about the generated file.

## 2. Decisions

### D1 — A `[type."X"]` entry carries an `enum`'s cases, in a `variants` column.

```toml
[type."Answer"]
pub = true
variants = ["Yes", "No"]

[type."io::IoError"]
variants = ["NotFound(String)", "PermissionDenied(String)", "NotText(String)", "Outside(String)", "Other(String)"]
```

One line per case, written the way the source writes it: a bare name, a
positional payload `Name(T, U)`, or named fields `Name { a: T }`. A `struct` has
`fields` and an `enum` has `variants`, and neither has the other's.

**A column and not a record of its own**, because it is the same fact as
`fields` for the other shape of type, in the same table
([ADR-106](adr-106.md) D3). There is no second credible spelling: `fields` cannot
be widened to hold a case, and a `[variants."X"]` table would be a second place
to look for what a type is.

**This does not answer the bound question.** *How does a bound reach a caller
across a package boundary?* is on [`open-decisions.md`](../../open-decisions.md)
because it has **two** credible spellings — a key of its own, or the `signature`
language widened — and the choice costs a grammar every ledger reader parses.
This one had one spelling, and the column beside it already existed.

**Read from every ledger, and this unit's own source wins.** A package's ledger
is absorbed under qualified keys, so `verdict::Answer` and a locally declared
`Answer` cannot collide by accident; where they would, the source is what the
file being checked declares.

### D2 — An `enum` whose variants hold nothing derives `PartialEq` and `Eq`.

`Method::Get == Method::Post` is a comparison of two values of one type, and it
lowers to Rust's. **Only where every variant holds nothing**, and that is a
derivation rather than a caution: such a type has no part that could fail to be
comparable, so the derive cannot fail.

A variant **with** a payload is comparable exactly when the payload is, and what
a `Locked[T]` field or a `Mapped` answers to `==` is a question nobody has asked.
Deriving unconditionally would refuse *the declaration* of every type holding
one, which is a worse place to be wrong than the comparison — so the rest is
open work and not a silent half-answer.

### D3 — A `match` over a `catch`'s error is a `match` over the type that arrived, where exactly one arrives.

`error` is a binding with no written type, and it stays one. What this adds is
the answer to **one question**: whether the arms cover every case. The one type
comes from the callee's `throws` column, over both ledgers, and only where that
column names exactly one thing that is not `"?"`.

**It can only move a refusal, never add one.** Where the arms miss a case the
words were `rustc`'s about a generated file, and they are this compiler's now;
where the arms cover everything, nothing was said before and nothing is said now.
That is why it does not need the sweep a *typed* `error` would: giving a binding
a type where it had none can turn a program that compiles into one that is
refused, and this gives it none.

[ADR-160](adr-160.md) D4 is untouched: where **several** error types arrive the
set is open and `else` is still the only answer.

## 3. Consequences

* [ADR-018](adr-018.md) D4's **`Method`** is written. `examples/http` publishes
  `enum Method { Get, Post }` and a handler asks `request.method()`. Two
  variants are the whole type because `std` refuses the rest: `http1` answers
  `400` to any other method before a handler runs, which is what makes the enum
  *total* rather than merely short.
* A handler that takes a `std` failure apart is checked here. Part III 17.1's own
  sentence — *one that takes it apart writes `use std::io` and
  `io::IoError::NotFound(p)`* — now describes a `match` that can be complete.
* **The ledger grows a key, and that costs nothing today**: a reader ignores a
  key it does not know, and no package in this tree is published yet.

## 4. What is not built

* **`==` on a `struct`, and on an `enum` with a payload** (D2's other half).
  [#157](https://github.com/Nikaia-Language/Nikaia/issues/157) carries it, with the shape a fix would take: the compiler
  decides whether every part is comparable, which is the same structural walk
  `contracts::send` already does for *may this cross a thread*, and which needs a
  column on the `std` types whose parts are Rust.
* **A typed `error` binding**, which is what would let every other check see a
  handler's value. D3 deliberately answers one question instead.
* **Ordering.** `<` on an `enum` would be `PartialOrd`, and what an order over
  cases means is a question nobody has asked.
