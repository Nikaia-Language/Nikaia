# ADR-118: `with` Is a Copy of a Value With Named Fields Changed

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 16, 2026
**Target Version:** Nikaia 0.0.8
**Related:** [ADR-298](adr-298.md) D8 (the word was kept for this),
[ADR-298](adr-298.md) (a word is reserved for a construct), [ADR-094](adr-094.md)
and [ADR-282](adr-282.md) (a value is moved or viewed as the compiler decides,
and a copy is written), [ADR-281](adr-281.md) (`update fn(mut v)`, the same
idea for a value behind a lock), Part I 2.1 (`mut`), 4.1 and 4.2 (structs and
their literals), 9.2 (private fields, `NK1110`)

## 1. Context

Every binding in this language is immutable unless it says `mut`, and the
value a program wants most often is *the one it has, with one field
different*. There was no way to write that short of a struct literal naming
every field again:

```nika
let moved = Point(x: p.x + 1, y: p.y, z: p.z)
```

Three fields are bearable; a `Stats` with six is a line nobody reads for its
one change. C# has `with` for records, Kotlin has `copy(x = …)`, Rust has
`Point { x: 1, ..p }` — and this language had the word reserved, unused, for
exactly this shape.

## 2. Decisions

### D1 — `value with { field: expr, … }` is a new value of the same type, with the named fields changed and the rest taken from `value`.

```nika
let moved = p with { x: p.x + 1 }
let stats = old with { count: old.count + 1, sum: old.sum + t }
let named = user with { name }          // shorthand: the local `name`
```

The braces are the struct literal's, with its field list and its shorthand;
a field named twice, a field the type does not have, and a `with` that names
no field at all are refused, the last because a copy that changes nothing is
a line the reader would puzzle over. The left operand is any expression of a
struct type — a name, a field, a call.

### D2 — Only the top level. A nested change is a nested `with`.

`p with { pos.x: 1 }` is not a form. A field of a field is changed by
changing the field: `p with { pos: p.pos with { x: 1 } }`. One rule, one
level, and the question of what a path means through a `T?`, an enum or a
list never has to be answered.

### D3 — The fields not named are moved, never copied unseen.

What `with` does not name it takes from the left operand, by move — Rust's
`..p` below. Where every such field copies (numbers, `bool`, `char`, a view),
the operand is usable afterwards, as it is anywhere. Where one does not — a
text, a list, a handle — and the operand is used again, the refusal names the
copy to write, exactly as a value used after a move is refused elsewhere. No
copy is inserted that the program did not write ([ADR-282](adr-282.md) D7).

### D4 — A field may be named only where a literal could name it.

Across a package boundary `with` reaches `pub` fields and nothing else, the
rule a struct literal has (`NK1110`). A type with a private field can still be
copied with a public one changed, because the private field is not named,
only carried.

## 3. Consequences

* The one-field change is one line, and reads as what it is.
* Nothing new to learn beyond the word: the braces, the field list, the
  shorthand and the privacy rule are the literal's.
* Below it is one struct expression with a base, which every field the
  program did not name comes from.
* **What it costs:** one rule in the grammar after a postfix expression, the
  checker resolving the fields against the operand's type, and the lowering.

## 4. What this does not decide

* **`with` on an enum value.** `m with { x: 1 }` where `m` is a `Message`
  cannot be typed without knowing the variant; whether a `with` inside a
  `match` arm — where the variant is known — should be allowed is left open,
  and today an enum operand is refused with a message that names `match`.
* Whether `with` may one day replace the leading `;` of an options-only call.
  Two meanings for one word is what the language avoids, and this record
  gives it one.

## 5. What is built

All of it, at 0.0.121. One postfix rule and an AST node carrying the byte it
stands at; the checker resolving the fields against the **operand's** type; and
the lowering to Rust's functional update.

* **The braces are the literal's, and so is everything about naming a field.**
  A field the type does not have is `NK1107`, the literal's own refusal, reused
  rather than written again; D4's privacy is `NK1110`, the same. What is new is
  two: **`NK1172`** for a field named twice, and **`NK1174`** for a `with` that
  names none.
* **`NK1172` was a defect one construct over.** `Point { x: 1, x: 2 }` — a
  plain literal — lowered, and `rustc` answered about the generated file
  ([Part III C.1](../30-nikaia-tooling.md)). The rule is the literal's; this
  record restates it for `with`, and both come to one place, because one rule
  written twice is two rules waiting to disagree.
* **`NK1173` is the operand**, which is the whole of what is new here. It has
  one claim and four reasons: an `enum` (§4, and the way out names `match`,
  where a variant is known); a **view**, because D3 takes the unnamed fields by
  move and no copy is inserted that the program did not write
  ([ADR-282](adr-282.md) D7); a type with no fields; and a value whose type
  this compiler did not work out — which matters because the lowering **writes
  the type's name**, `Point { x: 1, ..p }`, and this node carries none. The
  checker records what it worked out and the emitter reads it back, the way it
  is told a `comptime`'s value ([ADR-296](adr-296.md) D17).
* **D3 needed nothing of its own.** `..p` is the move, and the analysis that
  refuses a value used after one is the existing one — `with` puts the operand
  among an expression's parts and the rest follows.

**The corpus example moved, and that is a measurement.** Step 4 above named
`examples/1brc.nika`'s `Stats`. Reading it says no: `Stats` changes in place
through `&mut self` — `add` and `merge` are written that way because they run
inside `par_iter` — and a `with` there would mean returning a new `Stats` from
each, which reads worse and changes the call sites of a benchmark. Nothing else
in the corpus copies a struct with one field changed either. What moved instead
is **Part I 4.2's own block**, which had been a fragment nothing could parse and
is a program this compiler lowers now.
