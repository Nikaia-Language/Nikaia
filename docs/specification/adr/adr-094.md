# ADR-094: The Caller Writes No `&` — Whether a Parameter Is Lent or Kept Is the Callee's, Inferred Into the Ledger

**Status:** Accepted · **Built:** yes — steps 1–4, see §5; D5's narration by [ADR-236](adr-236.md) in 0.0.222
**Date:** September 15, 2026
**Target Version:** Nikaia 0.0.8
**Related:** [ADR-005](adr-005.md) D3 and §3 (the inference this extends, and
the clone that is still never inserted), [ADR-040](adr-040.md) D1 (a borrow is
not a clone), [ADR-027](adr-027.md) (the two spellings `sync` has, copied
here), [ADR-064](adr-064.md) D2 (a hull you can observe, you write — and why a
kept parameter is not one), [ADR-023](adr-023.md) D8 and
[ADR-055](adr-055.md) D1 (the `?` and the `.await` the compiler already writes
off the ledger), [ADR-083](adr-083.md) (`NK1131`, which stays)

## 1. Context

A parameter's type says whether the callee looks at a value or keeps it, and
Nikaia has no overloading, so there is never a second callee for a `&` at the
call to choose between. Whether an argument is lent or handed over is
therefore a fact about the callee — derived from its body, true for every
caller — of exactly the kind the ledger records: `sync` is inferred from a
body and written down with an asserted spelling beside the inferred one
([ADR-027](adr-027.md)); the `?` a failing call carries and the `.await` a
pausing one carries are written by the compiler off the ledger
([ADR-023](adr-023.md) D8, [ADR-055](adr-055.md) D1); a method's receiver is
auto-referenced. A caller that repeats the fact is doing the compiler's
bookkeeping, and a caller that forgets it is refused by `rustc` — *use of
moved value* — about a file nobody wrote, which
[Part III C.1](../30-nikaia-tooling.md) calls a bug in this compiler.

Counted across the 913 non-comment lines of `examples/`: **42** `&` at a call
or a loop head, each repeating what the callee's declaration said. And a
`for e in entries` followed by `entries.len()` type-checks clean and fails
below, reproduced with a nine-line probe.

## 2. Decisions

### D1 — The caller writes no `&`. Whether an argument is lent or handed over is the callee's declaration's, and the compiler writes the reference.

`fs::map(path)`, `serve(db)`, `into.merge(stats)`. What the argument becomes in
the emitted code — `&path`, `&db`, `stats` — is read off the callee's
parameter (D2) and written by the emitter, the way the `.await` is.

A `&` written before an argument is **refused**, with a message that says the
callee already decides it. Not accepted-and-ignored: a redundant spelling that
parses is a second way to say one thing ([ADR-022](adr-022.md)).

There is no callee without a parameter mode to read: a foreign crate is
described before it is called ([ADR-104](adr-104.md)), so the `&` has
nowhere left to stand at a call.

### D2 — A parameter written with a plain type is a view unless the body keeps it, and the ledger says which.

*Keeps* means: stores it into something that outlives the call (a field of
the subject, a struct or collection handed back), returns it by value, gives
it to a task, or passes it to a callee whose own parameter keeps it. Inferred
over the call graph with a fixpoint for recursion — [ADR-005](adr-005.md)
D3's engine, asked one more question — and recorded per parameter in the
ledger as `keeps`, beside `returns`.

**Fail closed.** A use the inference cannot resolve — a call nothing
describes, a method on a receiver of type `?` — counts as keeping. The wrong
answer in the other direction emits a `&T` parameter whose body moves the
value, and that is `rustc`'s error about a file nobody wrote; the wrong answer
in this direction is a caller refused with this compiler's words. Same
polarity as `sync` ([ADR-027](adr-027.md)) and as [ADR-010](adr-010.md) D1.

**`&T` in a parameter stays, as an assertion.** Writing it says *this is a
view; hold me to it*, and a body that then keeps the value is refused — the
counterpart of `sync = true` against `sync = "inferred"`, and of `@borrowed`
([ADR-008](adr-008.md) D6). The ledger spells the two apart for the reason
[ADR-027](adr-027.md) gives: a diff must tell a promise withdrawn from a
consequence of an edit elsewhere.

**Ordinary data is still moved where it is handed on** — to a callee that
keeps it. [ADR-040](adr-040.md) D1 and [ADR-005](adr-005.md) §3 stand: no
clone is ever inserted, and a caller that hands a value to a keeping callee
and uses it again is refused with the clone named as the way out, in the
shape `NK2101` already has for a task.

### D3 — Mutation of a parameter is written in the declaration, never at the call.

`fn fill(mut out: Vec[i64])` is a parameter the callee changes in place, and
the caller's value is what changes — `&mut self`'s rule, for every parameter.
It lowers to `&mut T`. The call, `fill(xs)`, shows nothing, exactly as
`xs.push(1)` shows nothing; a language that hides mutation through a receiver
and shows it through an argument has two rules for one thing.

A callee that wants a mutable *copy* of an owned parameter writes
`let mut v = x` inside, which is what it writes for any other value.

### D4 — A `for` lends, and a `let` over a place is a view of it.

`for x in xs { … }` iterates views of `xs`'s elements and leaves `xs` where it
was; `xs.len()` on the next line is a program. Iteration that takes the
elements away is written — `for x in xs.drain()` — because removing a name
from scope is the rare case and the one worth a word.

`let s = totals.stations[name]` and `let name = config.name` are views: the
language below refuses to move a value out of a container or out of a
borrowed field, so a move there was never what the line meant, and the
compiler writes the `&` it would otherwise have refused. `let y = x` over a
whole variable stays a move — it is a rename — and a `let` whose initialiser
is a call or a literal owns what it is given.

A `&` before the place in either position is refused as in D1.

### D5 — The cleanup point moves with the value, invisibly at the call, and that is accepted and narrated.

This is the one semantic cost, and [ADR-064](adr-064.md) D2's line is what it
has to answer: *a hull you can observe, you write.* A callee that keeps a
`File` runs its `Cleanup` at the end of the callee, not at the end of the
caller's block, and the call site shows nothing.

Accepted, because the language already does this and calls it correct:
`file.close()` takes `self` ([Part III 17.1](../30-nikaia-tooling.md)) and
the call shows nothing; a struct literal that stores a handle moves it and
shows nothing. What is observable is written in the **declaration** and read
from the ledger, not spelled at every use. The difference from a hull is that
a hull changes a value's *type of ownership* for the rest of its life, and a
kept parameter changes only *where one owner ends*.

What is owed is the narration: a change to a parameter's `keeps`, on a type
whose teardown has an effect (`Drop` written in user code, or `Cleanup`), is
a ledger diff that names the callers whose cleanup moved — the `NK2401` shape,
one more thing it narrates.

### D6 — `&` lives in declarations: parameter types, struct fields, result types, the receiver.

Nothing in this record touches those. `fn count(seq: &str) -> HashMap[&str,
Tally]` is still how a result says what it points into
([ADR-005](adr-005.md) D3), a struct field written `&str` is still what names
the buffer ([ADR-008](adr-008.md) D1), `&self` and `&mut self` are unchanged,
and `NK1131` ([ADR-083](adr-083.md)) still refuses a field of a borrowed
subject handed out by value. `NK1102`'s and `NK1104`'s help texts say what the
callee's declaration is, never *write `&`* about an argument.

## 3. Consequences

**What the corpus becomes.** Every `&` in an argument or a loop head in
`examples/` goes. `1brc.nika`'s `merge(&mut self, other: Summary)` keeps
`other: Summary`, because its body drains `other.stations` and a drain is
kept; a body that only read it would make the parameter a view without anyone
editing the signature. `report.nika`'s comment explaining why `count` must be
read before `page(entries, total)` goes, because it need not be.

**What a library author gets.** A signature is a smaller thing to write and a
consumer reads the mode off the ledger, the way they read `sync` and `throws`.
A callee that starts keeping its argument breaks the callers that used the
value again — loudly, with this compiler's words and the ledger's narration —
which is [ADR-005](adr-005.md) D3's action-at-a-distance answered the way it
already is for a borrow that lengthens.

**What a reader loses.** At `fill(xs)` nothing says `xs` changes; at
`keep(file)` nothing says the file is flushed inside. D3 and D5 put both in
the declaration, and a reader who wants them at the call has the ledger. That
is a real cost and it is the same cost method receivers already carry.

**What this costs at run time: nothing.** A view is a pointer and a move is a
copy of a header; the emitted Rust is the signature a person would otherwise
write, written by the compiler instead.

## 4. What this does not decide

* **One text type.** `.to_string()` on a literal put where a `String` is
  declared is the `String`/`&str` split, which is a different axis —
  representation, not mode — and a larger change: [Part I
  6.6](../10-nikaia-light.md)'s three-state view chosen by the compiler,
  applied to text. It is filed in [`open-decisions.md`](../../open-decisions.md).
* **Numeric widening.** A cast between widths is [ADR-060](adr-060.md)'s and
  [ADR-048](adr-048.md)'s question, not this one.
* **A `let` that later escapes.** `let s = totals.stations[name]` followed by
  `return s` is a view returned, which [ADR-005](adr-005.md) D3 and
  [ADR-008](adr-008.md) already answer.
* **An optional marker at the call for readers who want one.** Not offered:
  two spellings of one thing.

## 5. What is built

**Step 1.** `contracts::keeps` infers the column, the ledger records it beside
`returns`, and nothing reads it — which is what that step is for. The caller
still writes the `&` today and `for` still consumes.

*What the corpus says*, which is why the column landed before anything acts on
it: of 39 functions across `examples/`, **6 keep a parameter** — `Stats::add`
and `Stats::new` in `1brc`, `Counts::add` and `Counts::new` in `access-log`,
`Tally::new` and `report_fragment` in `k-nucleotide`. The other 33 read what
they are given. `report.nika`'s `page(entries, total)` is among them, and that
file carries a comment explaining that `count` has to be read first because
`page` *"consumes"* the entries: it does not, and the column says so.

*And `std` says which of its own keep*: six entries of ninety-four —
`Vec::push`, `String::push`, `HashMap::entry`, `Entry::or_insert`, and the two
`set` doors. An absent `keeps` on a *present* entry means it keeps nothing,
which is `std.contracts`' own convention for `sync` said once more; a file that
recorded nothing and made every caller assume the worst would be safe and would
leave the language where it is.

**Step 2**, and this one changes what programs mean. A `for` over a place
lends it, so `xs.len()` after the loop is a program; a `let` over a place is a
view of it where the value would otherwise have to move; `xs.drain()` is the
written form of taking the elements away, lowered as `into_iter`; and a `&`
written in front of a `for`'s list is `NK1137`.

*Three things it met that this record did not say*, each measured on the
corpus rather than reasoned about:

* **`.iter()` and not `&`.** The iterated name may already *be* a view — a
  parameter declared `&Vec[Entry]`, which `examples/inventory/stock.nika`
  writes — and `&entries` is then a `&&Vec<Entry>`, which Rust does not
  iterate. `.iter()` reads the same through any number of references, and the
  emitter has no types to tell the two apart with ([ADR-028](adr-028.md)).
* **`drain()` had to exist.** D4 names `for x in xs.drain()` as the written
  form and `std` had no such entry, so a body that hands an element to a
  callee which *keeps* it had no way to say so — `or_insert(counts)` in
  `access-log.nika`, `all.push(v)` in `json.nika`, four loops in all. It is
  `into_iter` below, because D4's words are *removing a name from scope*.
* **A `let` over a place that *copies* must not lend.**
  `let mi = self.bodies[i].mass` over an `f64` is a copy, and a `&` there is a
  borrow held across the loop that writes the same field — `E0502` about a
  file nobody wrote. Which of the two it is is a question about the type, so
  the checker answers it (`Checked::lent_lets`) with the same `moves_away`
  `NK2101` reads. **Where it cannot type the place, it says nothing**, and the
  written `&` stays the program's way to say it — which is why `NK1137` covers
  the `for` position and not the `let` one yet.

**Step 3**, which is what the first two were built for: D1 and D2 together.
A parameter the callee only reads is declared `&T` and given its `&` at every
call, so `page(entries)` is the line and `page(&entries)` is `NK1137` — the
same code D4's `for` head already carried, now covering both positions. The
answer both halves read is one function, `contracts::keeps::lends`: the
emitter calls it to write the *declaration* and the checker calls it to write
the *argument*, because the two disagreeing is a `&&T` or a moved value in the
language below, which is [Part III
C.1](../30-nikaia-tooling.md)'s `rustc` message about a file nobody wrote.

*What it does not lend*, each of them the polarity being spent rather than a
gap: a parameter the column says is **kept**; a value that **copies**, where a
`&i64` costs a dereference at every use and buys nothing; an argument that is
**already a view**; and a **method's argument**, for the reason `touches` gives
for asking a weaker question — which entry `acc.record(m)` goes to is the type
checker's answer and the emitter has none ([ADR-028](adr-028.md)), so a call
the checker does not walk (a grammar action's fold lambda) would hand a value
into a `&T`.

*Three things it met*, each found by the corpus:

* **Which fit to ask depends on the parameter's kind.** A parameter written
  `&str` is a view in the declaration already, so what has to fit it is the
  argument *with* the reference the compiler writes — a `String` becomes a
  `&String` and reaches `&str` the way the language below reaches it
  ([Part I 6.5](../10-nikaia-light.md)). A parameter written `Stats` and
  *inferred* lent gains its `&` in the declaration too, so both sides move
  together and the fit is the one it always was. Asking the first question
  everywhere refused `count(dna)` in `k-nucleotide.nika`; asking the second
  everywhere refused `record(Stats(2))`.
* **The refusal goes after the fit, and never on a type nothing pinned.** A
  `&i64` handed to a `&Request` is `NK1102` and stays one: saying *the `&` here
  is the compiler's* about an argument that is the wrong value sends the reader
  to fix the punctuation of a line whose type is wrong. `Ty::Unknown` is the
  sharper case — it fits everything, which is the right answer for an absent
  claim ([ADR-024](adr-024.md) D1) and no ground to refuse punctuation on.
* **But `Unknown` may not skip the *writing*.** The declaration is written off
  `lends` alone, so any condition the checker adds before recording the
  argument is a call whose callee takes a `&T` and whose argument does not have
  one. A guard placed one line too early took the `&` off
  `inventory/main.nika`'s `render(entries, total)` while leaving its parameter
  a view; the silence belongs around the refusal, where the source's own `&`
  stands in for what would have been recorded.

*And one hole it made and closed in the same step*, worth writing down because
nothing in the corpus could have found it. The ledger's type language spells a
view `&T` and has **no second spelling for a mutable one**, so `Vec::push` and
`Vec::len` write the same receiver type. That was harmless while nothing read
it; it stopped being harmless the moment the `&` was written off the column,
because `fn fill(out: Vec[i64]) { out.push(1) }` lent `out` and `rustc`
answered *cannot borrow `*out` as mutable*. Every mutating call in `examples/`
is on `self` or on a local, so the corpus was silent. The claim is a column of
its own now — **`mutates`**, seven of `std`'s ninety-four entries — and it is
the **declaration** rather than an inference: `&mut self` is what says it, which
is D3's sentence one position over. A receiver whose method mutates is not
lent, and what makes it a `&mut` instead is D3 itself, in step 4.

*And three holes it exposed elsewhere*, each older than this record and each
fixed here because the corpus could not be rewritten around them:
`contracts::sync` never walked into a `throw`, so
`ConfigError::NotFound(path)` was never seen; a variant constructor was read as
a callee nothing describes, so a `throw` that named one took its argument away;
and the emitter's key for a qualified callee was the *aliased* path while the
checker's was the unaliased one, so `http::route(r)` never found the answer the
checker had recorded — a hole `nullable_args` had shared all along.

**Step 4 is D3**, and it is the only one of the three states an author writes.
`fn fill(mut out: Vec[i64])` lowers to `&mut Vec<i64>`, `fill(xs)` gains its
`&mut`, and `keeps::lends` withholds its own claim on such a position so the
two never both write a reference. The word rides in the signature —
`(mut out: Vec[i64])` — because that is the one key a caller across a package
boundary reads a parameter's kind off, and it is the *parameter's* and not part
of its type: it says who changes the value, which is what `&mut T` says below
and what no type in this language's grammar can.

*And it closes a hole older than this record.* A body that changed an owned
parameter lowered to a Rust declaration with no `mut` on it, and the answer came
from `rustc`. **`NK1138`** is that answer in this compiler's words, raised only
where the change is **certain**: an assignment into the parameter or into a
place rooted at it, or a method every candidate entry marks `mutates`. A name a
`let` has bound has stopped being the parameter — which is D3's own way out
said back — and a method no ledger describes is not one to refuse on
([Part III C.4](../30-nikaia-tooling.md)). One example in the specification
itself was written the old way and now says `mut`; `examples/` had none, because
every mutating call in it is on `self` or on a local.

The rest, each step usable on its own:

1. ~~the `keeps` column: inferred, recorded, diffed~~ **built**
2. ~~D4's `for` and `let`~~ **built**
3. ~~D1 and D2 together — the emitter writes the argument off the column and
   `&` in an argument position is refused~~ **built**
4. ~~D3's `mut` parameter~~ **built**
5. D5's narration.

**What step 1 left for step 3** is settled: a *copy* type reported as kept is
the rule applied rather than a miss — `fn add(&mut self, temp: i32)` keeps
`temp`, and the value does outlive the call — and what it costs is nothing,
because a copy type is not lent whether the column names it or not.

`docs/open-work.md` carries the rest.
