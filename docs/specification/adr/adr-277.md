## 1. Question

How is code passed as a value: how is a lambda written and how many arguments
does it take; how does a function declared in this language say that a
parameter is code and what that code may do; and what does such a parameter
become in the language below, given that the code handed to it may pause?

Without an answer, a lambda's body could swallow the chain after it, a local
named `a` could silently change a lambda's arity, a package could not take a
handler, comparator or hook, and a pausing lambda had no lowering at a
parameter that only runs it.

## 2. How others do it

| Language / tool | Its answer | What it costs there | Source |
| :--- | :--- | :--- | :--- |
| Kotlin, Ruby | an expression-bodied block whose body ends at the end of the line | the language is newline-sensitive at that point | [ADR-022](adr-022.md) §4, from memory |
| Rust (stable, 1.94.1, edition 2021) | `async \|x\| { … }` closures and `AsyncFn`/`AsyncFnMut`/`AsyncFnOnce` bounds, no feature gate | `AsyncFn` is a bound, not a type: a value stored in a field needs a box or a type parameter | measured, [ADR-187](adr-187.md) §1 |
| Rust `std` | `Iterator::map` takes `FnMut`; an `async` closure handed to it yields an iterator of futures | a different program, not a pausing `map` | [ADR-187](adr-187.md) D2 |
| `rayon` | `rayon::join` takes synchronous closures | nothing can `await` inside one | [ADR-187](adr-187.md) D2 |
| Nikaia's own precedent | one written type, a representation chosen per value or per site: `Shared[T]` is `Rc` or `Arc` per value, a struct has up to three layouts, the callee's body decides the caller's `&` | a reader consults the ledger for the representation | [ADR-037](adr-037.md) D7, [ADR-008](adr-008.md) D2-D3, [ADR-094](adr-094.md) D1 |

What does not transfer: Rust's closure *types*. A Nikaia function type is
written once and says what the code may do (`sync`, `throws`); which Rust shape
carries it is the compiler's choice.

## 3. Options, weighed

| Question | Option | Why it lost, or won |
| :--- | :--- | :--- |
| Short lambda | keep `fn: expr` | silent misparse of a following `.method()`; two spellings of one thing; a body that cannot grow (ADR-022 §1) |
| | `fn:` body ends at end of line | newline sensitivity in one place, for four characters (ADR-022 §4) |
| | restrict the body so no chain follows | no restriction keeps `a.message.cmp(b.message)` and refuses `.listen(…)` |
| | keep `fn:`, forbid a chain after it | keeps every other cost and adds a rule |
| | lambda only inside the parentheses | unambiguous, still allowed, but a chain of trailing lambdas reads better (Part II 12.6, Part III 17.1) |
| Arguments | automatic `a`, `b`, `c`, arity read off the body | a local named `a` becomes an argument; every lambda depends on the rule (ADR-041 §1) |
| | keep them, warned (`NK1114`) | visible is not good; the rule stays alive with the warning (ADR-049 §1) — **withdrawn** |
| | announce the withdrawal a release ahead | protects no code outside the repository (ADR-049 D2) |
| Run or kept | a written `@detached` | a word the body already answers; the ledger records it (ADR-102 D3) |
| Pausing parameter's shape | `impl Fn(A) -> R` for a run parameter | a pausing lambda cannot be written into one (ADR-122 §1) |
| | boxed future for run and kept alike (ADR-122 D1) | chosen on a false premise; **11.99 ns/call** against **1.37** for `impl AsyncFn`, on a 0.31 floor (ADR-187 D1) — **narrowed by ADR-192 D1** |
| | `impl AsyncFn` by the body's `keeps` answer (ADR-192 D1) | **chosen**: the run case pays 4.4× the floor instead of 38×; the cost is predictability, answered by the ledger (D15) |

## 4. Decision

### D1 — There is one lambda form, a block. `fn: expression` is removed.

A lambda is `fn(name, …) { … }`; the block is the body whether it holds one
line or several. A block ends at its `}`, so nothing after it can be swallowed
into it.

*Was ADR-022 D1.*

### D2 — A lambda's arguments are the ones it names.

`fn(user) { … }` takes one, `fn(acc, n) { … }` two. A lambda that names none
takes none: `fn { … }` is the zero-argument form, which is what
`.or_insert_with fn { Stats(0) }` takes. There are no automatic names: a body
that uses `a`, `b` or `c` without declaring it names something nothing
declares and meets `NK1117`, with no refusal of its own. `NK1114` is retired
and not reused.

*Was ADR-041 D1 (the named spelling is the normal form) as completed by ADR-049
D1 (the automatic names are withdrawn).*

### D3 — A lambda that is the last argument may stand outside the parentheses.

Where there are no other arguments the parentheses go with it:
`users.map fn(user) { user.id }`. This is where the argument goes, not a second
spelling, and it is what lets a chain read down the page.

*Was ADR-022 D2.*

### D4 — A method may take arguments and a trailing lambda.

`.route("/x") fn { handler(db) }` is one call, and the chain after the `}` is
the outer chain:

```nika
Server()
    .route("/x") fn { handler(db) }
    .listen(":8080")
```

*Was ADR-022 D3.*

### D5 — Writing `fn:` is an error that says what happened.

The message names the block form and the reason the short one went: its body
ran to the end of the expression, so a `.method()` after it landed inside the
lambda.

*Was ADR-022 D4.*

### D6 — `fn(A, B) -> R` is a type, written the way a signature is.

Parameters in parentheses, `-> R` where there is a result, `sync` and `throws`
after the result:

```nika
fn route(&mut self, path: &str, handler: fn(Request) -> Response)   // may pause
fn on_tick(&mut self, handler: fn() sync)                            // never pauses
fn load(&mut self, reader: fn(Path) -> Bytes throws)                 // may fail
```

A function type stands wherever a type does: a parameter, a field, a result, a
`let`, an element. The trailing words are greedy: in
`fn make() -> fn(i64) -> i64 sync` the `sync` belongs to the result type. A
lambda itself carries no promise word; the promise is on the type it is handed
to.

*Was ADR-102 D1, with the greedy reading from its §5.*

### D7 — The type says what the code may do, with the language's defaults.

Without `sync` the code may pause; with it, it never does. Without `throws` it
cannot fail; with it, it may. A lambda that does less fits a type that allows
more. The other direction is refused in the shape of the refusal one level
down: a pausing lambda handed to a `fn() sync` is `NK2206` (`NK2202`'s shape),
a failing one handed to a type without `throws` is `NK2606` (`NK2605`'s shape),
reported alone, since the function around the lambda is not the one that has to
answer for it.

*Was ADR-102 D2.*

### D8 — Whether a code parameter is run or kept is inferred, and run is the absence of `keeps`.

* **Run** — the body calls it and does not keep it. The lambda borrows what it
  captures (Part I 5.4 A); its `touches` and `throws` count for the callee. Its
  pausing is the type's: where the type may pause the lambda is awaited, so the
  callee may pause ([ADR-122](adr-122.md) §5); a function that promises to pause
  only where its lambda does writes `sync(f)` ([ADR-244](adr-244.md) D4).
* **Kept** — stored in a field, handed back, given to a task. The type's promise
  is what the callee's own columns are computed with; the lambda moves what it
  captures (Part I 5.4 B), and a shared handle is duplicated
  ([ADR-040](adr-040.md) D1).

Nothing is written for it; there is no `@detached`. The ledger's existing
`keeps` column records it: `fn runs(f: fn() -> String) { return f() }` carries
no `keeps`, `fn holds(f: fn() -> String) { spawn fn { f() } }` carries
`keeps = ["f"]`. A body that stores *and* runs gets the kept answer.

*Was ADR-102 D3 (its run case's `sync = "from(f)"` narrowed by ADR-122 §5), with
ADR-192 D2.*

### D9 — What a kept handler touches is everything, and what it may lock is anything.

The type carries `sync` and `throws` and no more, so a stored handler's
`touches` is *everything* and its `locks` *may* — the fail-closed answers for an
undescribed call. A run lambda is unchanged: its body is in front of the check.
Where a struct literal fills a function field, the lock column reads what is
stored there instead ([ADR-230](adr-230.md) D1).

*Was ADR-102 D4.*

### D10 — A lambda that pauses fits a parameter whose type allows pausing, run or kept.

There is no refusal of a pausing lambda at a run parameter declared in this
language.

*Was ADR-122 D2.*

### D11 — The shape follows the type, and for a pausing type the body's `keeps` answer.

| parameter's type | run | kept |
| :--- | :--- | :--- |
| says `sync` | plain closure, `impl Fn(A) -> R` | `Kept` of a plain closure ([ADR-217](adr-217.md) D2) |
| may pause | `impl AsyncFn(A) -> R`; the lambda is `async \|a\| { … }`, with no `move` | `Kept` of a closure returning a boxed future ([ADR-217](adr-217.md) D2) |

`AsyncFn` is a bound, and a value a field holds needs a type, which is why the
kept case keeps the box. Where the type says `throws`, the closure's result is
the `Result` a `throws` function's is. A call to a pausing parameter in the
callee's body carries an `.await`.

*Was ADR-102 D5 and ADR-122 D1, as narrowed by ADR-192 D1; the kept form is the
one ADR-217 D2 built.*

### D12 — The shape is written only where the signature was declared in this language.

`std`'s lambda-taking entries are Rust with hand-written signatures, which take
a synchronous closure whatever the ledger's `sync` column says, so D11 does not
apply to them and `map` and its kin pay nothing new. What a pausing lambda
handed to one of them becomes is [ADR-233](adr-233.md)'s.

*Was ADR-122 D3's second half, as its §5 made it a condition on the check.*

### D13 — The shape is measured, not assumed.

`benches/handler` keeps the rows, best of five, control tying: plain closure
**0.31 ns/call**, boxed future **11.99** (38×), `impl AsyncFn` **1.37** (4.4×).
An earlier run measured the boxed future at 15.1 against 0.33. The method is in
[ADR-122](adr-122.md) §3 and [ADR-187](adr-187.md) D1. A premise that rules a
shape out is a measurement too: *Rust has no stable `async` closure* was false
when it was first written.

*Was ADR-122 D3's first half and ADR-187 D1.*

### D14 — The declaration and the call read the `keeps` column the same way, including when it is absent.

A callee this build has no contract for reads as **run** at both ends. The
declaration writes the parameter and the call writes the argument; the two
disagreeing would be one parameter with two shapes, refused by `rustc` about a
file nobody wrote — the rule ADR-094 D1 states for the `&`.

*Was ADR-192 D3.*

### D15 — What D11 trades away is predictability, and the ledger answers for it.

A run parameter's cost is not readable from its signature alone, and a library
author who moves a body from run to kept moves every caller's cost. A `keeps`
change is a `nikaia.contracts` diff in review, and `--locked` fails a build
whose contracts moved unrecorded — the same instrument [ADR-094](adr-094.md) and
[ADR-008](adr-008.md) D6 use. `sync` on the type remains the way to ask for no
future at all.

*Was ADR-192 D4.*

### D16 — A task's body and an `overlap` branch are blocks, not callables.

`spawn fn { … }` and `overlap { … }` lower to `async` blocks: a body is called
once, and wrapping it in a closure adds a call and takes nothing away.
`task::interleave` and the `overlap`/`race` families take futures because a
branch is that same block, and because `rayon::join`, the pool vehicle, takes
synchronous closures.

*Was ADR-187 D2's first two points. Its third — a pausing lambda handed to a
`std` entry is refused at the build — is displaced by ADR-233 D1-D2, which hands
it to `std`'s pausing counterpart.*

## 5. Consequences

* No expression-bodied lambda is left in the grammar, so nothing can swallow a
  chain; a lambda's arity is its parameter list and nothing else.
* A package can take a handler, comparator, retry or panic hook, and the type is
  the contract: a caller handing a pausing lambda where the signature says `sync`
  is told so in this compiler's words.
* A run parameter that may pause costs 1.37 ns/call, not 11.99; a kept one pays
  the box because it is stored. A reader who wants a run parameter's price opens
  the ledger (D15).
* What it costs: a named argument where a letter used to do, and a signature
  whose price for a run parameter is read from the ledger rather than the text.

## 6. What this does not decide

* **Whether a short lambda form should exist in future**, in either direction
  (ADR-049 §4).
* **Whether a function type may carry `touches`** — D9 fails closed; no program
  has asked (ADR-102 §4).
* **A function type with type parameters**, `fn[T](T) -> T` (ADR-102 §4).
* **A trait bound naming a trait in another package**, a namespace question on
  [`open-decisions.md`](../../open-decisions.md) (ADR-102 §3).
* **Whether `AsyncFn`, `AsyncFnMut` or `AsyncFnOnce` is the right bound** for a
  run parameter (ADR-192 §4).
* **Whether a Nikaia function type should be able to say `AsyncFn`**; nothing in
  the surface changes for the lowering (ADR-187 §4).
