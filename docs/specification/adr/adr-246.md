# ADR-246: A Type That Holds Itself Holds Itself Through a Box the Compiler Writes

**Status:** Accepted · **Built:** D1-D4 in 0.0.236; D5 item 1 in 0.0.306; D5 items 2 and 3 are not built
**Date:** September 27, 2026
**Target Version:** Nikaia 0.0.236
**Answers:** `open-decisions.md`, *how a type holds itself* - the owner chose
option 1, *the compiler puts the indirection in*
**Related:** Part I 4.4 (enums), [ADR-094](adr-094.md) D4 (*the `&` is the
compiler's to write*), [ADR-137](adr-137.md) (patterns), [ADR-242](adr-242.md)
(a `match` over a place lends), [ADR-195](adr-195.md) D1 (the toolchain is
written in the language)

## 1. Context

`enum Expr { Add(Expr, Expr) }` and `struct Node { next: Node? }` passed the
check and lowered as written, and the language below said *recursive type has
infinite size* about a file nobody wrote: a value that holds a whole value of
its own type inline would be larger than itself. 0.0.234 refused them in this
language's words (`NK1192`) and asked the owner how a type should hold itself.

It is the question that stood between Nikaia and a parser written in Nikaia:
the compiler's parser is already written in the grammar language Nikaia's
`grammar` blocks lower to, and its actions build a syntax tree, which is a type
that holds itself. The three options were the compiler writing the indirection,
a written indirection type in `std`, and no new form. The owner chose the
first, which is the rule the language already follows for references - the
reference a call needs is the compiler's to write - applied to the one other
thing Rust makes a program spell for the machine's sake.

## 2. Decisions

### D1 - A field on a ring of types that hold each other inline is boxed below, and the program does not say so.

A field is on a ring where what it holds **inline** reaches back to the type
that declares it: the type itself, or one that holds it, through any number of
types between. Inline is the type itself, nullable or not, a tuple's parts and
an array's element; a view, a function, a list, a map or anything this compiler
cannot see through is an indirection already and breaks no ring. Such a field
is `Box<T>` below, where `T` is the field's own lowered type - so `next: Node?`
is `Box<Option<Node>>` and `Add(Expr, Expr)` is `Add(Box<Expr>, Box<Expr>)`.

Both edges of a ring through two types are boxed (`Expr` holds a `Call` that
holds an `Expr`). That is one allocation more than the least that would do, and
it keeps the rule a property of a field rather than of a choice among a ring's
edges that a reader could not predict.

`NK1192`, the refusal of 0.0.234, is **withdrawn**: the walk that found such a
type is the walk that finds the fields to box.

### D2 - A boxed field reads as the field it declares.

A read of a boxed field is `(*base.field)` below: a place of the field's
declared type, which is read, lent, moved out of an owned value and assigned to
exactly as the unboxed field would be. A read through `?.` reaches the same
place inside the closure it lowers to.

A name a `match` binds out of a boxed part is taken out of the box at the head
of the arm, through `std`'s `boxed::open`: a `Box<T>` taken by value is a `T`,
and a `&Box<T>` lent is a `&T`, so the arm reads the name as the pattern's type
says whether the `match` took the value or lent it.

### D3 - A boxed field is built in its box.

A struct literal, a `with` and a variant's constructor put the value for a
boxed field in `Box::new(…)`, around whatever else the value is written with -
`Box::new(Some(tail))` for a node handed to `next: Node?`, and `Box::new(None)`
for a `null`.

### D4 - A pattern that looks inside a boxed part is refused by name, for now.

`Expr::Add(Expr::Num(n), b)` asks a question of the part inside a box, and the
language below matches no pattern through one. `NK1193` refuses it and says
what works today: bind the part to a name and `match` on the name in the arm.
Rewriting the nested pattern into that second `match` is the lowering's to do,
and D5 carries it.

### D5 - What is not built, and in which order.

1. **A nested pattern at a boxed part**, rewritten into a `match` in the arm
   rather than refused. *Built at 0.0.306*: the part is bound to a fresh name,
   the arm's guard asks whether it has the shape (`matches!` over
   `nikaia_std::boxed::peek`), so the next arm is tried where it does not, and
   the arm takes it apart with a `let … else` before anything else. Such an arm
   covers no variant on its own for `NK1151`, as a guarded one does not. One
   level per arm and outside an `|`; a pattern that looks deeper, or a guard
   that reads a name bound in there, is still `NK1193`.
2. **A guard reads the boxed binding as the box.** The names are opened at
   the head of the arm, and a guard runs before it; a method or a field reached
   through the name still works by the language below's own deref, and a
   comparison with the unboxed type does not.
3. **`Option<Box<T>>` for a nullable field.** D1 boxes the whole field, so a
   `null` costs an allocation. Boxing inside the option makes a `null` free, and
   needs the reads D2 makes into places to become reads of an option of a view,
   which is a larger change to the same three sites.

## 3. Consequences

* A syntax tree is written as the tree: the miniature compiler written in
  Nikaia to measure self-hosting builds its `Expr` directly, where it needed a
  list of two children before.
* **What it costs:** an allocation per boxed field built, which the declaration
  shows by where the recursion is. A tree allocates a node per node, which is
  what a tree is.
* Two defects that a syntax tree meets on its first line are closed beside this
  (0.0.236): a literal handed to a variant's text part is built into text of its
  own, and a number bound out of a lent `match` is the number.

## 4. What this does not decide

* A written `Heap[T]` beside the box the compiler writes, for a program that
  wants the indirection where there is no recursion. Nothing has asked for one.
* What a boxed field costs in a type that crosses to C
  ([ADR-147](adr-147.md)); no foreign type holds itself yet.
