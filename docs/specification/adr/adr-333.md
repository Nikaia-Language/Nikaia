# ADR-333: A Type Declares Value Parameters in Its Brackets, Beside Its Type Parameters, as `Array[T, N]` Does

**Status:** Accepted
**Date:** October 7, 2026 (#121)
**Answers:** whether a program can declare a type that takes a value - a
header's name, a decimal's scale - and how it is written
**Related:**
[ADR-332](adr-332.md) D3 (`Header["X-Api-Key"]`);
[ADR-330](adr-330.md) (a type as an argument);
[ADR-318](adr-318.md) (a default is a build-time value);
Part I 4.5 (`Array[T, N]`), 4.6, 5.1

## 1. Question

**Can a type a program declares take a value, as `Array[f64, 3]` takes its
length - and where is the value written?**

`Array` is the one type with a value in its brackets; a program cannot declare
another. A header's name on the wire, a decimal's precision and scale, a
buffer's capacity are values a type is made with.

## 2. How others do it

| | Values in a type |
| :--- | :--- |
| Rust | `const` generics, declared: `struct Buf<const N: usize>` |
| C++ | non-type template parameters, declared |
| Zig | any build-time value; a function returns the type |
| Idris, Lean | dependent types |

From memory, not checked against a version. What transfers: declared value
parameters, the common case in Rust and C++.

## 3. Options, weighed

| Option | Why it lost |
| :--- | :--- |
| A function that returns a type while building (Zig) | a type nobody sees without running code; a signature that checks nothing; a ledger that must carry code; identity of computed types ([ADR-323](adr-323.md) §3) |
| Values in round brackets, `Header("X-Api-Key")` | `Type(…)` is a constructor call, and since [ADR-330](adr-330.md) a type may stand where a value does |
| Only `Array` | a program could not say what `std` says |

## 4. Decision

### D1 — A value parameter is declared in the brackets with its type.

```nika
pub struct Decimal[precision: i64, scale: i64; rounding: Rounding = Rounding::HalfEven] { … }
pub struct Header[name: String; T = String] { … }
```

A bracket holds type parameters, `T`, and value parameters, `name: Type`.
Those after `;` are named at the use and have a default, as a function's
options do (Part I 5.1); a type parameter there has a type as its default.

### D2 — An argument is a build-time value, and two uses are one type when their arguments are equal.

`Decimal[10, 2]` and `Decimal[10, 2]` are one type, `Decimal[10, 3]` another.
An argument that is not a build-time value is refused as a `comptime`'s is.
Inside the declaration a value parameter is a constant.

### D3 — `Array[T, N]` is such a type.

It needs no change: it was the first.

## 5. Consequences

* A package says with a type what it used to say with a value beside it:
  `Header["X-Api-Key"]`, `Decimal[10, 2]`.
* **What it costs:** a type's identity includes values; the ledger writes them
  as build-time values cross.

## 6. What this does not decide

* **Value parameters of a function** beyond its type parameters.
* **Arithmetic on value parameters in a type** (`Array[T, N + 1]`).
