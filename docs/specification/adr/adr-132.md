# ADR-132: `else if` Is an `else` Whose Block Is One `if`, and It Is Written Without the Braces

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 19, 2026
**Target Version:** Nikaia 0.0.10
**Related:** [ADR-301](adr-301.md) (a condition is an ordinary expression, and the brace rule), [ADR-276](adr-276.md) (what a keyword costs), [ADR-276](adr-276.md) (a function that never returns)

## 1. Context

`if a { … } else if b { … } else { … }` was a parse error — *expected `{`,
found `if`* — and every language a reader comes from has it. The examples
worked around it with nested blocks and sequential `if`s (`http`'s
`status_line` is three `if`s in a row that mean one), which reads as three
decisions where there is one. Nothing in the language argued against the
form; it was never written down.

## 2. Decisions

### D1 — After `else`, an `if` may stand where a block would.

```nika
let grade = if score >= 90 {
    "A"
} else if score >= 80 {
    "B"
} else {
    "C"
}
```

An `else if` is an `else` whose block holds exactly one `if` expression, with
the braces of that block left out. Nothing else is added: the chain **is** an
`if` inside an `if`, so every rule of `if` holds at every link — the
condition is an ordinary expression with the brace rule of
[ADR-301](adr-301.md) D4 (an expression that starts with `{` is
parenthesised), the branches of a chain whose value is taken agree on one
type and the chain ends with an `else`, and a `return` inside a branch leaves
the function (Part I 3.1).

A chain may be as long as it likes. `else if` is two words with whitespace
between them, not a keyword: no word is added to the language.

### D2 — Lowering is Rust's own `else if`, and the formatter keeps the chain flat.

The emitter writes `else if` where the `else` block holds one `if` and
nothing else, so the generated Rust reads as the source does; an `else`
whose block holds an `if` **and** other statements stays a block. `nikaia
fmt` writes `} else if cond {` on one line, and never unfolds a chain into
nested blocks or folds nested blocks into a chain — the author chose one.

## 3. Consequences

* One decision reads as one decision.
* No keyword, no new rule about conditions or values: the chain inherits
  every one from `if`.
* **What it costs:** one alternative in the parser's `else` rule, and the
  emitter's flat form.

## 4. What this does not decide

* **`else match`**, or an `else` followed by any other expression than `if`.
  Those stay a block with the expression inside.
* **An `if` without `else` as a value**, which Part I 3.2 already answers.

## 5. What is built

**All of it that has somewhere to be built.** The `else` rule has a second
alternative — `else` followed by an `if`, which becomes that `else`'s block with
one statement in it — so the chain reaches the rest of the compiler as the `if`
inside an `if` it is, and every rule of `if` holds at every link with nothing
asked of any of them. The emitter writes Rust's own `else if` where the `else`
block holds one `if` and nothing else, and an `else` whose block holds an `if`
**and** other statements stays a block. `examples/http`'s `status_line` is one
decision rather than three `if`s in a row.

*The braced form comes first in the rule*, and that order is a statement about
reading rather than a trap: `{` cannot begin an `if`, so the two alternatives
cannot both match, and putting `else { … }` first keeps the common form the cheap
one.

*Nothing was added to the language, which is the claim worth checking.* `elseif`
is a **name** — the grammar is scannerless, so a word it has no rule for is read
as one — and `NK1117` says nothing declares it. A test pins that, because an
`elseif` that quietly became the keyword would be a second spelling nobody
decided on.

**What D2 asks of the formatter has nowhere to go yet.** `nikaia fmt` is named on
Part III's tool page and does not exist — the CLI has `build`, `run` and
`lower-std` — so *writes `} else if cond {` on one line, and never unfolds a
chain into nested blocks or folds nested blocks into a chain* is a rule for the
formatter to be born with rather than an unbuilt step of this record.
[#101](https://github.com/Nikaia-Language/Nikaia/issues/101) carries the formatter itself.

*Four tests* in `crates/nikaia/tests/else_if.rs`, and the first one **runs**: a
three-link chain compiled by the same `rustc` that built the test, printing
`ABCF`. The value and not the shape, because *the branches agree on one type and
the chain ends with an `else`* is what a chain carrying a `let`'s value has to
hold, and the only way to say it held is to run the program.
