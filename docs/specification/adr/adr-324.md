# ADR-324: A Package Links a C Library by Name, as Data the Compiler Acts On — There Is No Build Script, and a Package Brings No C Sources Yet

**Status:** Accepted
**Date:** October 6, 2026 (#483)
**Answers:** what a package does that needs a C library, after
[ADR-321](adr-321.md) D15 left no way for a package's code to run while a
program is built; Part III 13.4's `build.nika`, which described one
**Related:**
[ADR-302](adr-302.md) (a call into C, and what crosses);
[ADR-321](adr-321.md) D9, D14-D15 (no foreign code runs while a program is built);
[ADR-287](adr-287.md) D14 (build-time code touches nothing);

## 1. Question

**How does a package whose Nikaia code calls a C library get that library
linked, in every program that uses the package, without the program's author
doing anything and without anything of the package running while it is
built?**

A package such as a SQLite driver declares `extern "C"` functions and offers a
Nikaia interface over them. The functions live in a library the linker has to
find. Today nothing says which: a program passes `-l sqlite3` to `rustc`
through `RUSTFLAGS` by hand.

## 2. How others do it

| Tool | How a C library is linked or built | Does the package's code run while building? |
| :--- | :--- | :--- |
| Cargo | `build.rs` calls `pkg-config`, `cc`, `bindgen`; `system-deps` reads a table but still needs a short `build.rs` | yes, with every right, for every dependency |
| Zig | `build.zig` is Zig code that builds a graph (`linkSystemLibrary`, `addCSourceFiles`) a runner executes; Zig compiles C itself (`zig cc`) | yes: `build.zig` may do anything, and every dependency's runs |
| Go | directives in the source (`#cgo pkg-config: sqlite3`, `#cgo LDFLAGS: -lsqlite3`); `go build` compiles the package's C files; `go generate` is never run by the build | no; and after CVE-2018-6574 (`-fplugin` in `#cgo CFLAGS`) only flags on an allow list pass, `pkg-config`'s output included |
| SwiftPM | `Package.swift` is Swift; `.systemLibrary(pkgConfig:)` | yes, in the operating system's sandbox on macOS |

From memory, not checked against a version. What transfers: Go's split - the
package says *what*, the build tool decides *how* - and its allow list of
flags. What does not: a build script in any language, which Zig shows is as
powerful as Cargo's however its own language reads.

## 3. Options, weighed

| Option | Why it lost |
| :--- | :--- |
| `build.nika`, a program run before the build with a `std::build` API | Cargo's `build.rs` again: a package's code running with every right while a program is built, which [ADR-321](adr-321.md) D15 rules out |
| A script that only builds a graph (Zig) | still a program that may do anything; declaring the graph needs no program |
| Flags the package writes freely | a flag can load code into the compiler or linker (`-fplugin`, `-Wl,-plugin`, `-specs=`) |
| Prebuilt binaries per platform in the package | machine code nobody reviews, shipped into every program that uses the package |
| C sources in the package, compiled by the build | see D5 |

## 4. Decision

### D1 — There is no build script.

No `build.nika`, no `std::build`, no program of the package run before or
during a build. What a build needs from a package is data.

### D2 — A package names the system libraries its `extern "C"` blocks need, and the compiler links them, in every program that uses it.

A program that depends on the package links the libraries the package named;
its author writes nothing for it. Where the name is written - beside the
`extern "C"` block, in the package's manifest, or both - is not decided here.

### D3 — The compiler finds a library through `pkg-config` where the package gives a `pkg-config` name, and by its name otherwise.

The compiler runs the machine's `pkg-config` with arguments it forms from the
package's data, never with arguments the package writes; without a
`pkg-config` name the library is linked as `-l` and its name. A library that is
not found refuses the build with `NK1224`, naming the package, the library and
the `pkg-config` name it looked for.

### D4 — Only flags on a fixed list reach the linker.

From `pkg-config --libs`: `-l`, `-L`, `-pthread`, and on macOS `-framework`
and `-F`. Any other flag is refused with `NK1225`, naming it and the package
whose library returned it. Nothing is compiled from C (D5), so no compiler
flag is taken at all.

### D5 — A package brings no C sources, for now.

Compiling C runs nothing of the package where the build chooses the flags: the
preprocessor has no way to start a program. But it reads: `#include` with an
absolute path reads any file the compiler may read, and shows it in its error
message; C23's `#embed` puts it into the object file; a computed
`#include MACRO` cannot be found by reading the source first. No switch of GCC
or Clang forbids it, so a build would read past [ADR-310](adr-310.md). Where the
machine that builds is not the one that runs - a CI job with secrets - that is
new reach. And a C compiler is no security boundary against a hostile source.
This is reopened when what a C compilation reads can be bounded.

## 5. Consequences

* A package needing a C library is used with one line in a manifest; nothing of
  it runs while the program is built.
* SQLite is linked as a system library: present on most Linux and macOS
  machines, to be installed on Windows.
* A database reached over the network (MySQL, PostgreSQL) needs no C at all: a
  driver speaks its protocol in Nikaia, as Go's and `sqlx`'s do.
* A Rust `-sys` crate (`{ type = "rust" }`) still brings its `build.rs`; that is
  Cargo's, [ADR-321](adr-321.md) §6.
* **What it costs:** a library that is not installed is the user's to install;
  no external generator (`protoc`) runs as part of a build - its output is
  generated by hand and committed, or the format gets a grammar in Nikaia; no
  C library with its own build system (CMake) is built from source.

## 6. What this does not decide

* **Where a library's name is written** (D2).
* **Finding a library when the target is another machine**: `pkg-config`
  answers for the machine that builds.
* **Finding a library on Windows**, where `pkg-config` is rarely present.
* **C sources in a package** (D5), and with them which C compiler a build would
  run.
