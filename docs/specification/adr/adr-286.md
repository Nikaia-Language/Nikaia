## 1. Question

**What is the unit a Nikaia program is divided into, how does a name written
in one unit reach a declaration in another, and how does a unit arrive from
somewhere else?**

Part I 9.1 once said *every file is implicitly a module*, and nothing existed
behind it: `use` parsed and lowered to a comment. Without an answer a program
is one file, a library cannot exist, privacy has no boundary to stand on, and
every name the compiler cannot place is left to `rustc`, whose message is about
a file nobody wrote ([Part III C.1](../30-nikaia-tooling.md)). The answers came
in nine records, each fixing one edge of the same mechanism; this record states
them as one.

## 2. How others do it

Condensed from the superseded records' own comparisons; the claims are theirs
and were not checked again here.

| Language / tool | Its answer | What it costs there | Source |
| :--- | :--- | :--- | :--- |
| Java, Go, Rust | The boundary of privacy and publication is **above** the file (package, crate) | — | ADR-047 D1 |
| Python | The boundary is the file; `__init__.py` re-offers names by hand | A front door maintained by hand, forgotten names and all | ADR-047 D1 |
| Rust, Python, Elm | A glob import exists | Rust lints it, Python's style guide forbids it, Elm discourages it for libraries | ADR-046 D2 |
| Java, Python, Rust, Haskell, Elm, OCaml | A selected import (`use a::{B, C}`) exists and is withdrawn nowhere | Two spellings of every imported name; Haskell's practice moved toward qualified names | ADR-046 D2 |
| Go | No import selection; every name qualified | Fifteen years without serious movement to add it | ADR-046 D2 |
| Go | The fetch location is the package's identity | Years without a registry | ADR-047 D2 |
| Rust, JavaScript | Registries built early | Decisions made when there were three packages | ADR-047 D2 |
| Cargo | An index, a semver grammar, a lockfile, `git` with a `tag`, and `package = "…"` renaming | — | ADR-103 §1 |
| Rust | A trait must be **in scope** before its methods are called | The backend asks for an import Nikaia cannot write | ADR-095 §1 |

What does not transfer: a separately maintained re-export layer (Python), and a
registry of Nikaia's own before there are libraries to put in it.

## 3. Options, weighed

| Option | What it is | Why it lost | Record |
| :--- | :--- | :--- | :--- |
| File = module, plus a re-export form | Keep 030 D1, add a way to offer a sibling's name | A new form in a language that had just withdrawn two; upkeep on every library author forever; a library's file layout stays its public surface | 047 D1 |
| A glob import | `use pool::*` | Regretted everywhere it exists | 046 D2 |
| A selected import | `use pool::{Conn}` | Two spellings of one name across the whole surface — exactly what [ADR-041](adr-041.md) D1 withdrew. Not irreversible: adding it later breaks no program | 046 D2 |
| A rule for which of two same-named units wins | — | A rule a reader must know to read a line | 046 D5 |
| `nikaia.toml` lists the modules | As Cargo lists crates | A second place to forget; the `use` already names the unit | 030 §5 |
| A ledger per file | — | `sync` inference would depend on which file was read first | 030 §5 |
| Privacy re-implemented in the compiler | Instead of emitting `pub` | Two enforcers of one rule disagree eventually; `NK1110` is a message, not a second enforcer | 030 §5 |
| Every package flattened into one crate | 047 as first built | The transitive module is at the root, so rule 2 breaks silently and two packages can want one `mod` name | 053 §1 |
| One crate, modules named by package identity | Key becomes an alias | The leak stays; [ADR-046](adr-046.md) D4's check must widen to qualified names; pulls the registry question forward | 053 §1 (a) |
| One crate, nested modules | `mod b { mod c }` | A package reached through two parents is two modules: breaks 047 D2 rule 3 | 053 §1 (b) |
| An index of Nikaia's own | — | A second place to publish; not ruled out, since the compiler reads a directory | 103 §3-4 |
| A Rust `path` kept verbatim | `../../../../../shim` | A number derived from a build layout that already changed once unnoticed | 197 D2 |
| A path head refused on absence | Refuse any unknown head | A module of a package, an item of a foreign crate and an undescribed name look alike from inside the checker; it would refuse correct programs | 183 §1 |

The measurement that made D31 answerable: instrumenting the path arm over the
whole corpus found seven distinct paths used as values and **not one** whose
head the compiler had not read ([ADR-183](adr-183.md) §1). The shape of D19
was built by hand as four crates and run before it was decided — the
transitive crate does not resolve (`E0433`), the overflow check reaches a
library crate, a crate not on the list wraps, and the diamond unifies
([ADR-053](adr-053.md) §3).

## 4. Decision

### What a package is

### D1 — A package is a directory, and its files share one namespace.

The files in it see one another with no `use` at all; a name declared in any of
them can be written in any other. What the package offers outward is whatever
says `pub`, in whichever file it is declared. A consumer writes `use http` and
names the **package**, never a file inside it; a `use` naming a file of the
same package is refused. A library's internal file layout is therefore not its
public surface: moving a declaration between files breaks no consumer, and
there is nothing to re-export. A package is a directory **of a project** — what
a `nikaia.toml` declares; outside one a `.nika` file is compiled on its own
([ADR-260](adr-260.md) D2).

*Was ADR-047 D1. It displaced ADR-030 D1 (a module is a file beside the entry,
named by one word) and D2 (every module a `mod` at the crate root): one
namespace here is one crate root below, with no `mod` and nothing to resolve.*

### D2 — Privacy is per package, and `pub` is emitted as `pub`.

A declaration is private to its **package** unless it says `pub`, an item and a
field alike, and `pub` on a field parses. The rule is put where the language
below can act on it rather than re-implemented.

*Was ADR-030 D3, as narrowed by ADR-047 D1 (the boundary moved from the file to
the package).*

### D3 — `NK1110`: privacy in Nikaia's words, before `rustc` is asked.

Reaching a private item or field of another package — a call, a field read, a
field given in a struct literal — is `NK1110`, naming the package that keeps
it. Only a name written `prefix::item` can come from another package, so the
checker needs only to know which prefixes are packages. A field's `pub` is
carried in the ledger, because a consumer needs it and nothing in the package
does.

*Was ADR-030 D4, with the field half as ADR-047 §5 built it once the boundary
was the package.*

### D4 — A name denotes one thing, and the second declaration is refused.

`struct Foo` beside `fn Foo`, two `struct Foo`s, two `fn f`s: `NK1148`, the
caret on the **second** declaration and the note naming the first. Two of a
kind are the same rule and the same message. The rule holds whichever way the
build was started, because it is asked by the checker every build runs.

*Was ADR-144 D1.*

### D5 — What declares a name: `fn`, `struct`, `enum`, `trait`, `grammar`.

Those five and nothing else. A method belongs to its type, a grammar's rule to
its grammar (`Json::value`); a field, a variant, a type parameter and an `impl`
declare nothing at this level. `struct Foo`'s constructor and `fn Foo` collide
here, where a reader reads, even though the ledger keys them apart.

*Was ADR-144 D2.*

### D6 — Across files the same rule keeps its own message.

Two **files** of one package declaring one name is refused by the module layer,
naming both paths; it counts the same five kinds and leaves the one-file case
to D4.

*Was ADR-144 D3, which completed ADR-047 D1's "two files of one package may not
declare the same name".*

### D7 — One ledger per package, inferred over all its files at once.

`sync` is a fixpoint over the call graph, and a graph that stopped at a file
boundary would answer differently depending on which file was read first. The
inference graph is the package; its ledger is written in its own root, modules
in name order.

*Was ADR-030 D5 (one ledger for the project), as narrowed by
[ADR-100](adr-100.md) D1-D2 (the unit is the package, and a consumer reads a
dependency's ledger rather than deriving it).*

### D8 — The cache key holds every file, and a hit means nothing is parsed twice.

The parse is what tells the compiler which files the program is, so
[ADR-021](adr-021.md) D13's *on a hit nothing is parsed* is narrowed to
*nothing is parsed twice*; a hit still saves lowering, checks and inference. A
single file's key is unchanged.

*Was ADR-030 D6.*

### D9 — The source map records which file.

Each unit is emitted with offsets of its own and the driver stamps them as it
joins the text, so a `rustc` message about one file is traded back for a place
in that file.

*Was ADR-030 D7.*

### What `use` does

### D10 — `use` makes a package reachable, and does nothing else.

Every name from it is written with its prefix, at every use: in a type, a call,
a struct literal, nested in another type. The prefix falls where a name is
**written**, not where a value is used — `d.id` carries none. `use std::fs` is
the one `use` with a path in it, and names a module of the standard library.

*Was ADR-046 D1, as narrowed by ADR-047 D1 (the unit is a package, not a file);
ADR-030 D1's "one segment, and `std`'s path the only path" survives here and in
D11.*

### D11 — No name is brought in: not by a glob, not by a list, not one at a time.

`use pool::*`, `use pool::{Conn}` and `use http::server` are each refused with a
sentence of their own that names `use pool` and the qualified spelling. Taken on
[ADR-041](adr-041.md) D1's ground — one form, not two spellings of it — and
firm because it is reversible: a selected form added later breaks no program.

*Was ADR-046 D2.*

### D12 — `use pool as p` shortens the prefix, once, in one place.

It also settles a collision: two packages that both want to be `http` are the
consumer's to name apart. The alias is resolved away in the file that wrote it,
and a diagnostic names the package, not the alias.

*Was ADR-046 D3.*

### D13 — A prefix must be introduced.

`pool::Conn` without `use pool` is refused, so a file lists what it depends on
at the top; `use http` where no dependency is called `http` is refused, naming
where a package is declared.

*Was ADR-046 D4.*

### D14 — One name per file.

Two units under one name in one file — by alias or by collision — is an error,
not a rule about which wins. The alias counts.

*Was ADR-046 D5.*

### How a package arrives

### D15 — A package is depended on by path, and five rules come with it.

`http = { path = "../http" }` generalises how `std` already arrives
([ADR-002](adr-002.md) D4). A library needs no `main.nika`.

1. **The manifest key is the name** `use` writes; the path says only where it
   comes from.
2. **Transitive dependencies are not visible.** If A depends on B and B on C, A
   does not see C. Structural since D21.
3. **The same path is the same package; a different path is a different
   package**, identical contents included.
4. **A dependency's `[build]` is ignored, and the compiler says so** once per
   build: a package is built with the settings of the program that uses it
   ([ADR-045](adr-045.md) D1).
5. **A Nikaia dependency is part of the program, not a foreign package**: the
   overflow checks of [ADR-043](adr-043.md) D6 reach it. Generated since D22.

*Was ADR-047 D2, with rule 2 as made structural by ADR-053 D3, rule 5 as
generated by ADR-053 D4, and "by nothing else yet" widened by ADR-103, whose decisions are D23-D27 here.*

### D16 — A `path` in `nikaia.toml` is relative to `nikaia.toml`, for both arms of `[dependencies]`.

`../shim` means the directory beside this project's, for a Nikaia package and
for a `type = "rust"` crate alike.

*Was ADR-197 D1.*

### D17 — The generated manifest carries a resolved `path` absolute.

That is the one narrowing of [ADR-002](adr-002.md) D1's verbatim passthrough:
everything else in a Rust entry — `version`, `git`, `tag`, `features`,
`default-features`, a `package` rename — reaches Cargo untouched. It is how the
generated manifest already names `nikaia-std`.

*Was ADR-197 D2.*

### D18 — What a `path` is relative to is a property of the file, not of the ecosystem.

One rule for both arms, because the old difference was about which generated
file happened to hold the value.

*Was ADR-197 D3.*

### D19 — A Nikaia package is generated as its own Rust crate.

A build emits a Cargo workspace, always: the entry package as the binary crate
and every package it depends on, transitively, as a library crate beside it,
each with its own `Cargo.toml` under its own manifest keys. A dependency's files
are still **read** — for its ledger and the checks — and emitted by its own
member. A type's identity is the package's directory, not the key a consumer
reached it through, so a diamond unifies in the checker as in Cargo.

*Was ADR-053 D1.*

### D20 — The manifest key is the crate's local name for the package, and nothing more.

A dependency is emitted in Cargo's renaming form, `c = { package = "…", path =
"…" }`, so two packages under one key are in two crates and never meet, and one
package reached through two parents is one crate (D15 rule 3).

*Was ADR-053 D2.*

### D21 — Rule 2 is structural.

A transitive package is not a dependency of the crate that would name it, so
naming it fails to resolve below, reported against the `.nika` line. D13 does
not have to widen to qualified names.

*Was ADR-053 D3.*

### D22 — Rule 5 is generated.

Each generated Nikaia crate is named on the program's side of the profile,
`[profile.release.package.<crate>] overflow-checks = true`, beside the rows that
turn the checks off for foreign packages.

*Was ADR-053 D4.*

### D23 — A published Nikaia package is a crate named `nikaia_<name>`; the package's own name is `<name>`.

The prefix is the index's business: no `.nika` file, `use`, diagnostic or
ledger entry ever carries it.

*Was ADR-103 D1.*

### D24 — A version resolves through Cargo, and the generated manifest writes the rename.

`http = "1.2"` becomes `http = { package = "nikaia_http", version = "1.2" }`;
`"1.2"` is Cargo's semver; `{ git = …, tag = … }` is the same arm without an
index; the path arm stays. The resolved version is recorded in `nikaia.lock`
([ADR-021](adr-021.md) D2). A key is an identifier, because it is a `use` name.

*Was ADR-103 D2.*

### D25 — Cargo finds and fetches; the compiler reads what it finds.

A published crate holds `nikaia.toml`, `src/*.nika`, `nikaia.contracts` and a
stub `Cargo.toml` that exists for the resolver only. Nothing lowered is
published; the consumer reads the sources and ledger from where Cargo put them
and emits the package as a member (D19). The stub is never linked.

*Was ADR-103 D3.*

### D26 — A crate under the prefix that is not a Nikaia package is refused by name.

One without `.nika` sources or without `nikaia.contracts` is *not a Nikaia
package*; one with both is read like any package ([ADR-100](adr-100.md) D3).

*Was ADR-103 D4.*

### D27 — A fetched package's own dependencies resolve in the same resolution and stay invisible.

The stub lists them, so Cargo fetches the graph at once; a path dependency's
`nikaia.toml` is followed the same way. What the consumer may name is unchanged
(D21).

*Was ADR-103 D5.*

### D28 — The emitter writes a `use` for every trait an `impl` in this unit names with a package in front of it.

`impl http::Handler for Fixed` makes the emitter import `http::Handler`, so its
methods are callable: Rust needs the trait in scope, and D11 gives the program
no way to write the import. The path written is the import; nothing resolves it.

*Was ADR-095 D1.*

### D29 — Qualified is the whole of the test.

A `::` in the trait's name is what says it is in another crate. A trait of this
package, and one the compiler reads (`impl Error for …`,
[ADR-023](adr-023.md) D3), carry none and are left alone.

*Was ADR-095 D2.*

### D30 — The import carries `allow(unused_imports)`.

A program may implement a trait and never call it; a warning about a line
nobody wrote is not one to show.

*Was ADR-095 D3.*

### What may stand in front of `::`

### D31 — A path's head is one of five things.

A **type** declared here or recorded by either ledger; a **module of this
package**; a **package the manifest declares**; a **crate a description
covers** ([ADR-104](adr-104.md)); a **`std` module**. A head that is none of
them is refused, `NK1181`. `NK1171` is the other half: a member a known type
does not have.

*Was ADR-183 D1.*

### D32 — A ledger that records anything under `head::` answers for the head.

A described crate is a list of its items, with no line for the crate's own word,
so the last question is a prefix. Without it `nikaia describe`'s output would be
refused by the compiler that asked for it.

*Was ADR-183 D2.*

### D33 — The way out names a file, three times over.

A `.nika` file beside this one, a `[dependencies]` line, or
`nikaia describe <head>` — each a file the reader writes
([Part III C.2](../30-nikaia-tooling.md)).

*Was ADR-183 D3.*

### D34 — It fails open.

The list is of permissions: the refusal fires only where all five are silent.
A missing refusal costs a `rustc` message; a wrong one costs a correct program
([ADR-010](adr-010.md) D1's polarity, applied to a refusal).

*Was ADR-183 D4.*

### D35 — A head the package's other files declare is a head.

D1's one namespace, read off the other files' **item trees** rather than a
ledger, so a private `enum` in a neighbouring file counts.

*Was ADR-183 D5.*

## 5. Consequences

* **A program is a package and its dependencies, one crate each.** A library
  that uses a library exists; a transitive package cannot be named because
  nothing at the root reaches it; the overflow checks reach every Nikaia crate
  because the generated profile names each.
* **Every written name says where it comes from.** The cost is a prefix at
  every written name from another package, landing where the language already
  asks for a type; the alias (D12) keeps it short. What is bought is that no
  edit elsewhere changes what an already-written line means.
* **Names the backend used to report are this compiler's sentences**: a
  duplicate declaration (`NK1148`), a private item or field (`NK1110`), a head
  nothing declares (`NK1181`), a trait a package publishes that was not callable
  (D28) — [Part III C.1](../30-nikaia-tooling.md) closed for each.
* **Part I 9.1-9.2 state D1-D6 and D10-D14; Part III 13.3 states D15-D17 and
  D23-D24.**
* **What the version arm gives up** is a name space of Nikaia's own: a package
  lives on crates.io under a prefix, and a squatter can take `nikaia_foo` — D26
  makes it useless as a package, not free. Reversible: the compiler reads a
  directory, and where it came from is D25's business.
* **An absolute path in a generated manifest is not portable**, and need not be:
  `target/nikaia/build/` is never shipped.

## 6. What this does not decide

* **Re-export.** D1 removes the question inside a package; offering another
  package's name stays unanswered.
* **A selected import form**, if a program of real size shows the prefix to be a
  real cost (D11's reversibility).
* **A `nikaia publish` command, yanking, ownership, and `--locked` over a moved
  git tag** — Cargo's answers until a program meets a case where they are wrong
  ([ADR-103](adr-103.md) §4).
* **A trait implemented for a foreign type**, and whether the emitted trait
  import should be narrower than the file ([ADR-095](adr-095.md) §4).
* **What may stand after a known head** — `io::wobble` is the ledger's question
  ([ADR-140](adr-140.md) D5) — and a package named like a `std` module.
* **A name that shadows one `std` publishes**, overloading, and a `let`
  shadowing an item ([ADR-144](adr-144.md) §4).
* **Build time** under one crate per package: a guess, not a measurement
  ([ADR-053](adr-053.md) §4).
* **Whether the generated build directory's layout is stable** — nothing an
  author writes depends on it any more (D16-D17).
* **What D31's "module of this package" and D33's first way out mean under
  D1**, where a `.nika` file beside this one joins the same namespace rather
  than becoming a module named by its file: carried as ADR-183 wrote them, and
  open.
