# ADR-123: `crosses` Says *No* as Well as *Yes*

**Status:** Accepted · **Built:** yes, except `nikaia describe` writing it — see §5
**Date:** September 16, 2026
**Target Version:** Nikaia 0.0.8
**Related:** [ADR-045](adr-045.md) (the crossing verdict, and its three
answers), [ADR-039](adr-039.md) D3 (`locks`, three-valued for the same
reason), [ADR-104](adr-104.md) (a described crate, whose describer fills the
column), [ADR-005](adr-005.md) §1 Group B, Part III 13.5

## 1. Context

Whether a value may cross a thread has three answers — *may*, *may not*,
*undecided* — and two refusals, built and tested, fire on *may not*. The
ledger's `crosses` column has two values: `true`, which is *may*, and absent,
which is *undecided*. So at the destination the refusals guard, no described
type can answer *may not*, and the refusals have never fired.

The type that needed the answer arrived: `examples/foreign-runtime/`
describes a crate whose handle holds an `Rc<String>`, a value that provably
does not cross a thread — the point of that experiment — and the file could
not say so. `locks` met the same shape and became three-valued, because
reading *nothing said* as *no* refuses correct programs and reading it as
*yes* is a promise that fails open.

## 2. Decisions

### D1 — `crosses` has three values: `true`, `false`, and absent.

`crosses = true` is the claim *a value of this type may cross a thread*, as
it was. `crosses = false` is the claim *it may not*, and is what produces
*may not* at the destination a task goes to. Absent stays *nothing recorded*,
which is not permission. Every ledger already written keeps its meaning.

### D2 — The describer fills it where a field reader can see it.

`nikaia describe` writes `crosses = false` for a type whose fields hold a
thing the language below marks as not sendable — an `Rc`, a raw pointer, a
`Cell` — which a field reader can see and a reviewer can check; `true` where
every field is sendable; nothing where it cannot tell. That is
[ADR-104](adr-104.md)'s second step with one more column in it.

## 3. Consequences

* `NK2501` and `NK2502` can fire, for the first time, on a described foreign
  type that does not cross — which is the message the reader was owed.
* One column's type, its parse and its render, and the few readers of it.
* No ledger changes meaning; a file that never said `false` says what it
  said.

## 4. What this does not decide

* Inferring `crosses` for a Nikaia `struct`, which walks its fields and needs
  no column.
* A `crosses` that depends on a type parameter (`Box[T]` crosses where `T`
  does); a single value per type is enough for every entry the corpus has.

## 5. What is built

**D1, D2, and §3's first consequence.** *`NK2501` and `NK2502` can fire, for the
first time, on a described foreign type that does not cross — which is the
message the reader was owed*: that runs from a **program** now, and
`crates/nikaia/tests/describing.rs` is the chain. A Rust crate with an `Rc`
field, `nikaia describe` writing `crosses = false` from that field, the
description merged into the ledger every analysis reads
([ADR-104](adr-104.md) D1), and a `spawn` refused on the `.nika` line with a way
out and no word of `rustc`'s in it.

`nikaia describe` reads a `pub struct`'s fields and writes the column from
them: `false` where a field holds an `Rc` or a raw pointer, `true`
where every field is a scalar, a `String`, or one of those inside a container
that changes nothing, and **nothing** for everything else — which is the common
answer rather than the exception, and the honest one. `examples/foreign-runtime`'s
`LocalHandle` gets its `crosses = false` from the command now, where it used to
be the one line of that file a hand had written.

*And D2's own list needed one correction, which a field reader is where it
shows.* D2 names *an `Rc`, a raw pointer, a `Cell`*. The first two are `!Send`;
a **`Cell` is not** — it is `!Sync`. A `Cell<T>` may be *moved* to another thread
exactly when its `T` may, and what Rust forbids is looking at one from two
threads at once. A draft that wrote `crosses = false` for a `Cell` would put a
claim in the file that is false, and a reviewer would have to undo it — the
opposite of what D5 asks a review to do. So `Cell` and `RefCell` are not on the
list the describer reads, and the two the record named that are `!Send` are.

*The `true` half is narrow on purpose*, because a promise is what a refusal is
withheld on: an `Arc<T>` is `Send` exactly when its `T` is `Send` **and**
`Sync`, which is two questions a field reader does not have, so it falls to
silence. A field of another crate's type does too, and so does a tuple struct,
whose body this does not read — *nobody looked* is not *it holds nothing*.

**And the rest of D1, which came first.** `contracts::Crosses` has the three values,
the ledger writes and reads both claims and stays silent for the third, a third
spelling is **refused** rather than guessed at (`iterates`' precedent: reading
it as either value would put a claim in the file that nobody wrote), the
crossing verdict answers *may not* off `crosses = false`, and
`examples/foreign-runtime/`'s three descriptions say it for the handle over an
`Rc<String>`. `NK2501` and `NK2502` have their first end-to-end tests in
`crates/nikaia/tests/send.rs` — the first either code has ever had, because
until now no type the records name could answer *may not*.

**One asymmetry the record did not name.** D1's claim is about the type and not
about its arguments, which is why `crosses = true` on a type *with* arguments is
not read as permission. `crosses = false` **is** read, arguments or not, and the
difference is the polarity rather than an oversight
([ADR-010](adr-010.md) D1): a promise is withheld where the line might not have
spoken about the `T`, and a restriction is kept, because nothing a value is
wrapped in makes it crossable.

**And one hole the claim exposes rather than makes.** `NK2502` asks its question
of a call **nothing** describes, which is [ADR-038](adr-038.md) D7's own wording,
so a *described* foreign call is not asked — and no column says whether a
described foreign function puts what it is given on a thread.
`examples/foreign-runtime/crossing` is exactly that shape: its handle now says
`crosses = false` and it is handed to `hyper_shim::across_a_thread`, which the
description names. So that program is still refused by `rustc`'s `Send` bound
against the `.nika` line, exactly as it was, and
`a_described_foreign_call_is_not_asked_about_crossing` asserts the silence so
that nobody has to rediscover it. That is a column somebody will want, and it is
not this record's.

**What is left is `nikaia describe` writing the column**, which is D2's *who*
rather than its *what*: the command is [ADR-104](adr-104.md)'s step 2 and does
not exist. Until it does, the line is hand-written like the rest of the
description — and the file says which part of the crate was read for it,
`inference = "described-from-signatures+fields"`, because `crosses = false` is
the one claim there that no signature could give.

the issue tracker carries the remainder.
