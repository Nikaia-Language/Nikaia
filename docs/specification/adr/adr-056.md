# ADR-056: Every Substituted Name Is Put Back, and a Translation That Collapses a Distinction Is an Internal Error

**Status:** Accepted · **Built:** yes — see §5
**Related:** Part III C.1 (the Iron Rule this restores, and the internal-error path
it already names), [ADR-010](adr-010.md) D5 (the `TrustedMap` substitution that
was undone), [ADR-312](adr-312.md) D1 (`Shared[T]`, the one that was not),
[ADR-005](adr-005.md) D7 (the diagnostics contract)

## 1. Context

The emitter writes type names the program does not: `TrustedMap` for a map whose
input the operator chose, `Rc` or `Arc` for a `Shared[T]`, and — as the language
grows — a deferred-parameter DSL's shadow struct, a grammar's generated types,
`nikaia_std`'s own names. A relayed `rustc` message can name any of them.

**Two were decided one at a time, in opposite directions, and there was no rule.**
`TrustedMap` was put back, on the criterion that the substitution was *"a name and
not a translation"* — same table, same API, same equality. `Shared[T]` was
deliberately left in Rust's words, on the ground that `Rc` and `Arc` are different
types and *"expected `Shared[T]`, found `Shared[T]`"* would hide a defect in this
compiler rather than translate one of Rust's words.

So a third substitution would arrive and nothing would notice — and the criterion
for it would have to be invented again.

**But the second decision had only two options where there are three.** Leaving
`Rc<Conn>` and `Arc<Conn>` standing does not serve the reader either: they wrote
`Shared[Conn]`, the page has no word `Rc`, and Part III C.1 says outright that
*"an untranslated backend (rustc) error reaching the user is a Nikaia compiler
bug"*. It does not leave the reader with a choice between a confusing message and
a hidden defect; it names the third way in the next sentence — *"if an unmapped
error surfaces, the compiler reports it as an internal error ('this is a Nikaia
bug, please report') — never as normal output"*.

The case here is the neighbour of that one: the mapping **succeeded** and produced
a message that cannot be about the program. The answer is the same.

## 2. Decisions

### D1 — Every name the emitter substitutes is put back, and there is no list.

`Rc<T>` and `Arc<T>` become `Shared[T]` like `TrustedMap` becomes `HashMap`. The
per-name question — is this a name or a translation? — is not asked, because the
answer it was protecting against is covered by D2.

Nested hulls come through whole: `Arc<Vec<Rc<Conn>>>` is `Shared[Vec<Shared[Conn]>]`,
because the brackets are matched rather than searched for.

### D2 — Where putting a name back makes the message say the same thing on both sides, it is an internal error.

*"expected `Shared[Conn]`, found `Shared[Conn]`"* is not a fact about the program.
It means this compiler emitted two different Rust types for one Nikaia type, which
is a defect of its own — so it is reported as one, in Part III C.1's words: **this
is a Nikaia bug, please report it**, together with the sentence `rustc` actually
wrote, shown to the reader and appended to a log beside the generated Rust.

**Detected by comparing the two, which is what makes it general.** A message
`rustc` itself wrote that way is its own business — two types of one name, from
two crates, is a real thing to say about a real program — so the rule is not *"a
message that names one thing twice"* but *"a message that only became that way
here"*. A substitution added later needs no entry anywhere: it is the **collapse**
that is noticed, not the name.

**And the reader is told whose mistake it is.** The message says their program may
well be fine. A diagnostic that looks like a refusal and is really a compiler bug
costs somebody an afternoon of reading their own correct code.

## 3. Consequences

**The open item this closes was the general rule**, and it turned out not to need
a list. *"A third will arrive without anything noticing"* is now *"a third arrives
and says so"*: whatever name is added to the substitution, a collapse it causes is
caught by the same comparison.

**One decision is reversed and its test with it.** The test that asserted
`Shared[T]` stays in the backend's words now asserts the internal error. That is
the point of writing a test per decision: the decision changed and exactly one
test had to change with it.

**A build that hits this fails, as it did before.** Nothing about which programs
compile changes — only what the reader is told about one that does not.

## 4. What this does not decide

* **Whether `Rc` and `Arc` can diverge for one value at all.** The reference-count
  inference is what decides ([ADR-312](adr-312.md)); this record says what happens
  if it is ever wrong, and says nothing about whether it can be.
* **The other half of C.1's sentence** — the internal-error path for an *unmapped*
  backend error. That is specified and still unbuilt; this builds the neighbouring
  case and the message it prints is the shape that one wants.

## 5. What is built

**Both decisions.**

`diagnostics::shared_names` puts the hull names back, with matched brackets;
`both_sides_the_same` and the comparison in `translate_units` mark the collapse; a
`Diagnostic` carries the backend's original words where it happened, `render`
prints the internal-error form with them, and `log_internal` appends them beside
the generated Rust with the build naming the path.

Three tests: the collapse is an internal error carrying both original names, a
message `rustc` itself wrote that way is left as a message about the program, and
a nested hull is translated whole.
