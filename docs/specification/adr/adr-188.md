# ADR-188: The Escape Set Is The Language Below's, Written Down Once And Refused Here

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 22, 2026
**Target Version:** Nikaia 0.0.139
**Closes:** [#197](https://github.com/Nikaia-Language/Nikaia/issues/197) (*the escape set is
Rust's, and no page says so*)
**Related:** [ADR-012](adr-012.md) (the source map that puts a backend refusal
on the right `.nika` line), [ADR-017](adr-017.md) (escaping in a template, a
different question one word away), [ADR-073](adr-073.md) D5 (the build-time
decoder that reads these escapes)

## 1. Context

Measured at 0.0.113, while building a decoder for build-time text. The parser's
`STR_CHAR` takes `\` and **any** character and keeps both; the emitter writes a
`.nika` string literal into the generated Rust verbatim. So what a `\` means has
always been decided by `rustc`, and no page of the specification said so.

Two things followed, and only the second was a defect.

**The set itself was never the problem.** A literal that goes into the generated
file as it stands has the language below's escapes whether anybody writes that
down or not, and writing it down is **describing**.

**What an unknown escape was told is the problem.** `println("a\qb")` was
refused on the right line — [ADR-012](adr-012.md)'s source map holds — in
`rustc`'s vocabulary, ending *for more information, visit
doc.rust-lang.org/reference/tokens.html#literals*. A Nikaia program was sent to
the Rust reference to find out what it may write, which is
[Part III C.2](../30-nikaia-tooling.md)'s *in the compiler's own words* not met
and [C.1](../30-nikaia-tooling.md)'s class besides.

**The entry disagreed with itself about whose sentence this is**, and that is
worth recording because it is what held it open: it said *writing them down is
describing rather than deciding*, and four paragraphs later that *which escapes
this language has is a decision even where the answer is Rust's*. The first is
the better reading and it is the one this record takes — the same bargain
[Part I 2.2](../10-nikaia-light.md) already makes about numbers, where the widths
are the machine's and the page says so.

## 2. Decisions

### D1 — The set is Rust's, and Part I 2.5 says which.

`\n \r \t \0 \\ \' \" \xNN \u{…}`, in a `"…"`, an `f"…"`, a `'…'` and a
template alike. `\xNN` names a byte below `\x80`, because that is what the
language below allows inside a string; a character above it is `\u{…}`.

**Describing and not deciding.** Borrowing the backend's escapes costs one
sentence and keeps the two readings of a literal — this compiler's and the
generated file's — from ever parting company. Deciding a set of our own would
mean decoding every literal and re-encoding it, which is
[ADR-073](adr-073.md) D5's work done twice for no reader's benefit.

### D2 — One table, with two readers.

`build_time::one_escape` is the table. `decoded` reads it to turn a literal into
a value while the program is built; `an_escape_nothing_names` reads it to say
which escape a literal has that the set does not name.

**Two walks would be two sets.** The decoder already held its own copy, and a
second copy beside it would drift — and the one that drifted *open* would refuse
a literal the other decodes, which is a correct program refused
([C.4](../30-nikaia-tooling.md)). The refusal is safe precisely because every
escape it refuses is one the decoder cannot read and `rustc` refuses one file
later: what moves is who says it, and in whose vocabulary.

### D3 — The refusal is `NK1184`, in the checker, naming the set.

At every literal that keeps its body as written — `Expr::LitStr`,
`Expr::LitInterpolated` and `Expr::LitChar`. The message names the escape as
written, one clause saying what is wrong with it, and the set.

**In the checker and not in the parser.** A `fail` arm inside a lexical rule is
not fatal in this parser — *an error that got further still wins, progress
before priority* — so where the rest of the file parses, as it does here, the
message would be discarded with the attempt. The literal reaches the checker
with its body intact, which is all this question needs.

### D4 — The way out is read off the escape.

A malformed `\x` or `\u{…}` was *meant* as a character, so the help names the
form it should have had: `\u{80}`, `\u{1F600}`. Anything else is a backslash
that was meant literally, and the help writes the literal back with its
backslashes doubled.

[C.2](../30-nikaia-tooling.md)'s rule, applied rather than quoted: **a way out
that cannot be taken is not one**, and telling someone who wrote `\x80` to
double the backslash would be one.

## 3. Consequences

* **One C.1/C.2 hole closes** for every literal in the language, and the corpus
  is untouched: a sweep over every `.nika` in the tree refuses none of them.
* **Part I 2.5 gains the set**, so the page a program is written against says
  what a literal may hold.
* **The build-time decoder got shorter and safer**, which is D2's real dividend:
  it stopped carrying a second copy of the table.
* **What it costs:** one walk per string literal, at check time.

## 4. What this does not decide

* **What a template's escapes are.** `dsl html { … }` is markup and its
  escaping is [ADR-017](adr-017.md)'s, a different question one word away; what
  this record covers is the string literal a program writes.
* **A raw-string form.** `r"…"` does not exist in this language, and a program
  that wants a backslash writes `\\`. Whether the regular expressions in
  [Part I 2.5](../10-nikaia-light.md)'s own example deserve one is a question
  nobody has asked twice.
* **Whether the set should grow.** It is the language below's; a set of our own
  is D1's rejected alternative and would come back as a record of its own.

## 5. What is built

All four, at 0.0.139.

* `build_time::one_escape`, the table, with `decoded` rewritten to read it and
  `an_escape_nothing_names` beside it; `build_time::ESCAPES`, the set as a
  message prints it.
* `Checker::an_escape_nothing_names` → `NK1184`, at the three literals.
* [Part I 2.5](../10-nikaia-light.md)'s table, and Part III 16's row.
* `crates/nikaia/tests/literals.rs`: the refusal, the whole set accepted and
  lowered, the character and interpolated shapes, the two ways out, and a test
  that holds the decoder and the refusal to one answer.
