# ADR-177: A Grammar Runs While the Program Is Built by **Compiling the Parser It Generates**

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 21, 2026
**Target Version:** Nikaia 0.0.124
**Answers:** [#178](https://github.com/Nikaia-Language/Nikaia/issues/178), which carried this as
work and as the argument against the other way of doing it
**Related:** [ADR-026](adr-026.md) Q4 (the second compilation, named as a cost),
[ADR-072](adr-072.md) and [ADR-116](adr-116.md) D2 (`asset("…")`, where the

## 1. Context

Part II 10.2 promises **one grammar, two stages**: the same syntax and the same
meaning at build time and at run time. The run-time half has worked since
grammars did. The build-time half — `comptime CONFIG = Json::value(asset("config.json"))`
— had nothing behind it.

There is an obvious way to build it, and it is the wrong one.

## 2. Decisions

### D1 — A grammar is **not** interpreted here, and the reason is not the size of the work.

The compiler holds the grammar tree already. Walking it and matching against
the input is the short path, and it is refused.

`winnow-grammar` is a code **generator**: its model crate parses the grammar
language, validates it and analyses it, and hands the result to a macro that
writes a parser. Its own summary says so — *intended to be used by procedural
macros that generate parsers*. There is no interpreter in it to borrow.

So interpreting here would be a **second implementation of the same
semantics**, and the two would have to agree exactly. Part II 10.2's promise
would stop being a property and become a hope. The disagreements would not land
where anybody looked for them; they would land in the corners — implicit
whitespace, repetition bounds, the commit point, frames and resynchronisation,
interning, spans — and would present as *this file parsed while the program was
built and fails while it runs*, for the same file and the same grammar.

### D2 — What happens instead is that the **generated** parser is compiled and run.

The compiler writes a small Cargo project holding the grammar's own lowering,
the types its rules produce and a driver, builds it, and runs it over the
bytes. Then there is one implementation of the grammar language and the
agreement is a tautology rather than a claim.

**It needs no new security model.** A grammar's action blocks are Nikaia and
[ADR-287](adr-287.md) already says what a build-time body may do; the bytes come
from `asset("…")` and [ADR-072](adr-072.md) already bounds which. What is new
here is neither the permission nor the input.

### D3 — The cost is a second compilation, and the cache is what makes it bearable.

[ADR-026](adr-026.md) Q4 named this cost. The sub-project is keyed on the
program text that went into it — the grammar's lowering, the types, the dump —
so it is written and built when the grammar changes and reused otherwise. The
compiler already emits Rust and already drives Cargo, so the machinery is not
new.

### D4 — The result has to **cross**, and a result that cannot is refused by name.

What a `comptime` hands the program is a value the build carries and the
language below can write ([ADR-079](adr-079.md) D1). A build-time value is a
whole number, a `bool`, text, a list and a `struct` — five shapes — so a rule
that hands back a float or an `enum` variant has nothing to arrive as.

**Refused before a parser is compiled**, from the rule's **declaration** rather
than from what it produced: there is no point building a parser to learn that
its answer has nowhere to go. `NK1178` names the type and says which of the
five it is not.

### D5 — Invalid input fails the build, in the parser's own words.

Part II 10.2 A says it and this keeps it literally: the parser's diagnostic is
**relayed whole** rather than re-worded. It is in the grammar's own vocabulary
and counts its line and column against the bytes that were parsed, which is the
one place they mean anything.

## 3. Consequences

* **Part II 10.2 A is a program.** `comptime` says *when*, `asset("…")` says
  *where the bytes come from*, and the call says *what is done with them* — the
  three words [ADR-116](adr-116.md) D2 named, all three built.
* **The parse leaves nothing behind.** What reaches the generated file is the
  answer, and no parser runs while the program does.
* **A grammar inside a grammar is refused.** The inner run would have this
  compiler start a second compiler inside the first, which is a build that does
  not end rather than one that is slow.
* **What it costs**: a Cargo project per grammar, built once and reused; a
  generated encoder and a decoder that reads it, held together by tests that
  run programs.

## 4. What this does not decide

* **Which results cross.** D4 refuses whatever a build-time value cannot be,
  and that set is [ADR-079](adr-079.md)'s rather than this record's. The float
  and the `enum` it refused at 0.0.124 are crossings at 0.0.125, by that record
  and not by this one; what is still refused is a `Vec` **inside** a result,
  which wants a type this language cannot spell
  ([`open-decisions.md`](../../open-decisions.md)).
* **The database driver's narrow half** ([[#89](https://github.com/Nikaia-Language/Nikaia/issues/89)](https://github.com/Nikaia-Language/Nikaia/issues)
  [#89](https://github.com/Nikaia-Language/Nikaia/issues/89)), whose first step is a grammar declaring what columns a query returns.
  It wants a flat list of declarations, which is a shape D4 already crosses.

## 5. What is built

All of D1 to D5, at 0.0.124. `crates/nikaia/src/grammar_run.rs` writes the
sub-project, builds it, runs it and reads the answer back;
`crates/nikaia/tests/grammar_at_build_time.rs` **runs programs**, because a test
that compared the emitted `const` against a string would pass for a parser that
read the file wrongly, and one that asked the checker would pass for a parser
that never ran.

**Measured, and it is the finding worth keeping.** At 0.0.124 neither grammar
in the corpus produced a result that crossed. `examples/json/src/main.nika`'s `Json` is
an `enum` with `Vec` payloads and `examples/config/src/main.nika`'s `Section` holds a
`Vec[Setting]` — a field that owns memory, which a `const` cannot hold. So the
mechanism ran and the **crossing** was what stopped both, refused by name with
the reason. Part II 10.2 A's own example is in that set: it reaches `NK1178`
rather than `NK1127`, which is this record working and
[ADR-079](adr-079.md) D1 being the next question.

*And it was the next two.* [ADR-179](adr-179.md) D1 spelled `&[T]`, so a rule
handing back a `Vec[Setting]` now reaches a `comptime` declared `&[Setting]` —
which is the shape a configuration file has and the one the tests here run.
D3 is what makes it work at all: a parser **builds** a `Vec`, so the
sub-program owns what the program views, and the dump — generated from the
*program's* declaration — reads a run either way.

**`examples/config/src/main.nika` still does not cross, and that is not a gap.** It
parses a file the **user** names on the command line, so what it holds has to
be built while the program runs and `Vec[Setting]` is the right declaration for
it. The crossing is for a file the **build** names ([ADR-072](adr-072.md)),
which is a different program.

**What §4 left open was answered one package later.** 0.0.125 gave a build-time
value a float and an `enum` variant ([ADR-079](adr-079.md) §5), so D4's two
refusals became crossings: the dumper writes `(f 1.5)` with `{:?}`, and for an
`enum` it writes a `match` with an arm per variant emitting `(v Ty Variant …)`.
A variant with **named** fields is still refused by name, and the sentence says
what it is — a payload this compiler carries by position, which is a shape
nobody has decided rather than one the language below lacks.

*The decoder had one defect and it is the kind this format invites.* A variant's
tag is **two words**, and the reader took the second from where the first ended
— so `(v Shade Odd)` came back with an empty variant name and the payload loop
met an `O`. The encoder is generated and the decoder is written by hand, which
is two halves of one format; what caught it was a test that **ran** a program,
which is the same thing this record says twice above.

**And the feature did not work in a project build at all**, which is the finding
that matters most here. It shipped able to lower a loose `.nika` file and unable
to build the shape anybody would write it in. The cause was a **second**
lowering: `Project::report` rebuilds the source map whenever the backend had
anything to say — and *anything* includes a warning, which the generated crate
emits for the `grammar!` macro's `cfg` — and it rebuilt with `Reads::none()`. So
that pass evaluated the `comptime` to nothing and the emitter refused an item the
build had already written a `const` for; what reached the user was this
compiler's own internal sentence in place of the program running. One function
now answers *what may this build read, and where does it compile a parser* for
both lowerings, and `crates/nikaia/tests/project.rs` builds and runs a grammar
project, because every unit test passed throughout.

What does cross, and what the tests run, is a rule handing back a list of
`struct`s whose fields are text — which is the shape a configuration file has
and the shape the database driver wants.
