# ADR-184: A View Is Spelled `ref X`, and Text Has One Noun

**Status:** Accepted · **Built:** D1 and D2 at 0.0.133 — see §5
**Date:** September 21, 2026
**Target Version:** Nikaia 0.0.133
**Supersedes the spelling of:** [ADR-282](adr-282.md) (`&str` as *the assertion
that it is a view*), [ADR-094](adr-094.md) D2 (`&T`), [ADR-302](adr-302.md) D5
(`&mut T`, `&[T]`), [ADR-179](adr-179.md) D1 (`&[T]`). **None of their
decisions changes** — only the characters they are written with
**Related:** [ADR-298](adr-298.md) (the reserved words), [ADR-296](adr-296.md)
D2 (the generated file says what the program said), [ADR-152](adr-152.md) D4
(an array carries its length)

---

## 1. Context

`&` appears 98 times in the 2 847 lines of Nikaia in this repository. **82 of
them are a *type* spelling and 53 of those 82 are `&str`** — only 16 are a
borrow a program writes by hand, because [ADR-094](adr-094.md) D1 already made
a parameter the body only reads a view **without the word**.

So the character a reader meets most is not a borrow operator at all. It is
part of `&str`, and `&str` is the one place this language has **two nouns for
one type**: text is `String` ([ADR-282](adr-282.md)), `str` is not a type a
program may write anywhere else, and that record had to explain the gap in
prose — *`&str` is the assertion that it is a view*.

**The assertion can be a word instead.** That is the whole of this record.

## 2. Decisions

### D1 — `ref X` is a view of an `X`, wherever a type may stand.

`ref String`, `ref Array[T]`, `ref Reading`, `ref mut T`, `ref self`, and
`ref value` for the borrow an expression writes. One word, one meaning, and a
reader who has met the rule once knows every case of it.

**It is reserved** ([ADR-298](adr-298.md)'s list gains its thirty-seventh
word), and the corpus is not what decided it. Counting `ref` over every `.nika`
file gave **zero** uses — which says the word is free, and it is not: a call
written `ref(x)` is a borrow of `(x)` to the grammar and a call to a function
named `ref` to its author, in the same characters. A word that is a name in one
position and an operator in the next is worse than a reserved one, because the
reading nobody meant is the **silent** one, which is
[ADR-010](adr-010.md) D1's polarity.

**What found it is a test and not a reading.** This record was first written
saying `ref` needed no reserving, on exactly the argument above about every
position wanting a type or an expression after it.
`crates/nikaia/tests/reserved_below.rs` writes each word in **every** position
a name may stand and compiles the result; `ref(x)` came back as *this returns
`ref i64`, and the function declares `i64`*. A count over the corpus cannot see
a collision the corpus does not write, and a generated program can.

### D2 — Text has one noun, and `str` is not a name the language has.

`ref String` is what a program writes and what a message prints. `str` stays
the **compiler's** word for a view of text, because the language below spells
it that way and the emitter writes name for name ([ADR-296](adr-296.md) D17) —
but it does not reach a program, a signature, a ledger or a diagnostic.

**Normalised at both doors and not at one.** A type arrives from the AST
(`Ty::from_ast`, what a signature declares) or from text (`Ty::parse`, what a
ledger carries), and a view of `String` becomes the text view in both. With it
in only one, the checker held `ref String` and `ref String` as **two types**
and said so: *`greet` takes `name: ref String`, and this call passes
`ref String`* — a message that prints one spelling twice and claims they
differ, which is worse than the `rustc` sentence it replaced.

### D3 — `Array[T]` is an array of **any** length, and the position says where the length comes from.

`Array[T, N]` writes the length down and is laid out inline
([ADR-152](adr-152.md) D4). `Array[T]` leaves it open — *beliebig, aber fest*:
arbitrary, and fixed for each use. Where that use gets its length is what the
position decides.

**In a parameter the call says which.** `fn total(xs: Array[i64])` takes an
array of any length, and every call knows its own — so the type has a size
there and the function is generic over it. The language below has the same
shape and the same name for it, a `const` parameter, so the function is written
once and monomorphised per length. Two arrays in one signature are two lengths:
`fn zip(a: Array[i64], b: Array[i64])` takes any two and not two of the same.

**Under a `ref` the pointer carries it.** `ref Array[T]` is a view of a run —
Rust's own `&[T]` — and needs no length in the type at all, because a view of a
run is a pointer and a count. That is not a second rule: *owning* needs a size
and *viewing* does not, which is [ADR-282](adr-282.md)'s own arrangement for
text one type over, where the compiler picks the state per use.

**In a field or a result it is `NK1182`**, because there is no call to ask and
the two readings left are both something else. A struct generic over its length
makes two `Section`s of different lengths two **types**, which is exactly not
what a parser produces — [ADR-179](adr-179.md)'s own motivating case is a field
whose run differs per value. A result's length would be bound by nothing. The
message names **three** ways out, because which was meant is not something this
compiler can know: `Vec[T]` to own and grow, `ref Array[T]` to view, and
`Array[T, N]` to write the length down.

**Without that refusal the language below answers**, with *the size for values
of type `[i64]` cannot be known at compilation time* about a file nobody wrote,
which is the sentence [ADR-182](adr-182.md) D2 had just finished removing one
construct over.

### D4 — `&` leaves the language, and the bracket form with it.

Two spellings for one idea is what this record exists to remove, so `&` goes
from the grammar and `ref [T]` goes with it — `ref Array[T]` is the run's one
spelling (D3). `&&` stays what it is, a program's *and*, and the generated file
keeps Rust's `&` throughout: D2's own line is that the compiler's word and the
language's are allowed to differ, and only one of them is the language.

**A program written with `&` gets a way out and not just a verdict.** The
grammar's own *found unexpected token `&`* is true and helps nobody, so the
parse error carries a note naming the word and the three shapes it writes
([Part III C.2](../30-nikaia-tooling.md)).

**A ledger still reads the old spelling**, and that is the one exception: a
`.contracts` file is a machine format this compiler reads, not a program a
person writes, so `&str`, `&[T]` and `&mut T` all parse back — as the types
their new spellings name. Tolerance there costs nothing and a stale checkout
keeps building.

## 3. Consequences

* **One rule replaces two nouns and a punctuation mark**, and the rule is
  stated once in [Part I 6.5](../10-nikaia-light.md).
* **The ledger reads it too.** `Display` and `parse` are a matched pair and
  `.contracts` is that format, so the files on disk say `ref` — which is the
  surface a reviewer reads ([ADR-290](adr-290.md)).
* **No decision moves.** What a view *is*, when the compiler writes one, what
  it may not outlive — all of that is [ADR-094](adr-094.md),
  [ADR-282](adr-282.md), [ADR-283](adr-283.md) and [ADR-302](adr-302.md), and
  every one of them stands. This record changes characters.
* **What it costs**, counted site by site before the work started: 87 in the
  corpus, 43 in the three pages, ~120 in the Rust string literals that carry
  Nikaia source or an expected message, 21 in `.contracts` (18 of them in the
  hand-maintained `std.contracts`), and the parser, the type printer and the
  emitter's one name. **The ADRs are not rewritten**: a record says what was
  decided when it was decided.

## 4. What this does not decide

* **Whether `&self` should exist at all.** [ADR-094](adr-094.md) D1 already
  makes a parameter the body only reads a view without the word, so
  `fn mean(self)` may already say what `fn mean(ref self)` says. That is a
  second language change and it is not this one; here the receiver is spelled
  `ref self` and means exactly what `&self` meant.
* **A name for the owned dynamic run.** `Vec[T]` is what a program writes and
  nothing here changes it.

## 5. What is built

**D1 and D2 at 0.0.133; D3 and D4 at 0.0.134.**

* The parser reads `ref` in all four positions — a type, a `mut` type, a
  receiver, an expression — beside the `&` it replaces, and the word is on
  [`RESERVED_WORDS`](../../../crates/nikaia/src/parser/mod.rs) and in the
  grammar's `RESERVED` rule.
* `Ty::from_ast` and `Ty::parse` normalise a view of `String` to the text view;
  `Display` prints `ref` and prints `String` for it.
* The emitter writes `&str` for a view of `String`, which is the one place the
  compiler's noun and the language's differ.
* The corpus, the three specification pages and the four `.contracts` files
  that carried a view are written in the new spelling.
* `Array[T]` fits from an `Array[T, N]` and not the other way, a `const`
  parameter per open length, `NK1182` where no length can come from, and the
  run's one spelling in all four writers that had the bracket form — the type
  printer, the emitter, the C boundary and the call that makes the address.
* **A third printer of a written type**, found by a message that said
  `name: &String` after the other two were fixed: `views.rs` writes the AST's
  type itself, because what a message quotes back has to be what the program
  wrote.
