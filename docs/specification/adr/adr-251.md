# ADR-251: The Ledger Is the Contract, What It Was Derived From Is Beside It, and It Speaks Nikaia Where Nikaia Can Say It

**Status:** Accepted · **Built:** yes — see §5; ADR-288 D31 (`sync(f)` in the
source) is the next package
**Date:** September 29, 2026
**Target Version:** Nikaia 0.0.253
**Supersedes:** [ADR-307](adr-307.md) D5 (*the ledger carries the prose*)
**Narrows:** [ADR-100](adr-100.md) D3 (the hashes a ledger is believed by move
to the record beside it; the rule is unchanged)
**Related:** Part III 13.5, [ADR-288](adr-288.md) D31 (`sync(f)`),
[ADR-020](adr-020.md) (a package's ledger is committed), [ADR-290](adr-290.md)
D5 (a description records its crate's sources), [ADR-294](adr-294.md) (the
ledger's reader is on the road to Nikaia)

## 1. Context

The owner asked, before the ledger's reader moves to Nikaia, whether the format
is right. Read against the five ledgers in the repository and Part III 13.5, it
is two files in one, it speaks a second language beside Nikaia's, and the
specification describes a file that is no longer written.

**Two files in one.** `nikaia.contracts` is what a caller's compiler reads about
a body it cannot see, and it also carried what the entries were derived from:
`toolchain`, `inference`, and `[sources]` with the SHA-256 of every unit.
Those decide whether a consumer may *believe* the contract (ADR-100 D3); they
never say what the contract *is*. Kept in one file, a compiler upgrade or a
comment edited in a source changed the published contract's diff while no
contract moved.

**Prose in the contract.** ADR-307 D5 put a `pub` item's `///` into the ledger
as `doc`. The compiler never read it, and `--locked`, which compares the file
byte for byte, failed on a changed sentence.

**A second language.** The contract wrote `returns = "borrows(self)"` where
Nikaia writes `ref(x)` (Part I 2.1); `(ref Scan, c: char)` plus
`mutates = true` where the source wrote `ref mut self`; `$T` where Nikaia
writes `fn hand[T](x: T)`; `sync = "from(f)"` for a promise the language had
no word for.

**And the specification had drifted.** 13.5's table did not name `keeps`,
`mutates`, `threads`, `provenance`, `compares`, `iterates`, `variants` or
`ends_by_length`; it named `tethered` on a `[struct."…"]` that is written
`[type."…"]`; its example said `version = 1` where the files said `2`.

## 2. Decisions

### D1 — What a contract was derived from is a file of its own, beside it.

`nikaia.contracts` holds the contract; **`nikaia.derived`** beside it holds
`toolchain`, `inference` and `[sources]`, with the same stem for a
description: `contracts/<crate>.contracts` and `contracts/<crate>.derived`.
Both are generated, both are committed, and `--locked` compares both - the
record is what a consumer believes the contract by, so it travels with it.
ADR-100 D3's rule is unchanged: a contract is believed while its sources hash as
the record beside it says, and a contract with no record beside it is not
believed.

### D2 — The contract carries no prose.

`doc` is withdrawn (ADR-307 D5 is superseded). The parser still reads `///`
(ADR-307 D4), and `std.contracts`, which is written by hand, keeps its
sentences as `#` comments above the entries they are about. Whether a
dependency's documentation needs a way to travel is answered later, over
larger dependency graphs, by something that addresses the contract's entries
rather than living in them.

### D3 — `sync` keeps its three written states in the contract, for now.

`sync = true` (the source promised), `"inferred"` (the body implies it) and
the lambda form stay contract, although a caller reads the first two alike:
ADR-288 D28 already makes the difference matter across a package boundary, and
dropping it now would be a decision taken back later.

### D4 — The contract writes Nikaia's syntax wherever Nikaia has one.

* **A signature is written as the source writes it**: `self`, `ref self` and
  `ref mut self` for a receiver, where it wrote `ref Scan` and a separate
  `mutates = true`;
* **what a result points into is written `ref(a | b)` in the result**,
  `-> ref(self) String`, where `returns = "borrows(self)"` stood beside the
  signature;
* **a type parameter is declared in brackets before the parameters**,
  `[T](x: T) -> T` and `[H: handler::Handler](h: H)`, where `$T` stood;
* **a promise about a lambda is `sync(f)`** (ADR-288 D31), where `"from(f)"`
  stood.

### D5 — The contract says more than the language, in words of its own, and spells them in Nikaia's grammar.

`keeps`, `touches`, `locks`, `crosses`, `threads`, `provenance`, `compares`,
`iterates`, `ends_by_length`, `sharing`, and the types `Seq`, `Par`, `Seen`
and `?` stay: each says something a caller has to know that no Nikaia program
writes. What a key's value spells - a type, a parameter, a list - is spelled as
Nikaia spells it.

## 3. Consequences

* A build writes `nikaia.derived` beside `nikaia.contracts`, and `nikaia
  describe` writes `contracts/<crate>.derived` beside the description; the
  build cache stores the record as a third artifact.
* A contract's diff is a contract that moved. A compiler upgrade, a comment in
  a source and a reworded `///` change the record or nothing.
* `crates/nikaia-std/src/tools/nikaia.contracts` goes: it was what
  `nikaia --input` leaves beside a file lowered by hand, committed by accident at
  0.0.169, overwritten by the next hand lowering, and read by nothing.
* The ledger format is version 3.

## 4. Considered and rejected

**The record in `nikaia.lock`**, which already holds per-unit hashes. The lock
is written for the project a build runs in, is not committed in the examples,
and has no counterpart for a dependency or a description; the record has to be
beside each contract it describes.

**The record in the build directory, uncommitted.** A consumer believes a
dependency's contract by it; uncommitted, every fresh checkout would derive
every dependency again, which is ADR-100 D3's cost without its reason.

**Prose kept for `pub` entries only.** The compiler reads none of it; the
question is where documentation travels, and it is answered by D2's later
record rather than by keeping it where it breaks `--locked`.

## 5. What is built

Built at 0.0.253: **D1, D2 and D3.**

* `Ledger::render` writes the contract, `Ledger::render_derived` the record,
  `Ledger::read_beside` reads both; `derived_path` names the record's file. A
  project build, a package member's build, `nikaia --input` and `nikaia
  describe` write both, the cache keeps both, and `--locked` compares both.
* `doc` is gone from the contract's reader and writer: a ledger with one is
  refused as a key nothing reads. `std.contracts`' 249 sentences are comments
  above their entries.
* The three committed descriptions of `hyper_shim` are split into contract and
  record; the stray `tools/nikaia.contracts` is removed and ignored.
* Tests: `doc_comments.rs` holds D2 (a `pub` item's prose renders nothing, and a
  `doc` key is refused), `dependency_ledger.rs` that the hashes are the
  record's and a contract is believed through it, `project.rs` that a
  package's build writes both files, `described.rs` and `describing.rs` that a
  description's hash is in its record.

Built at 0.0.254: **D4 and D5.**

* `contracts::spelling` is the one place that knows the file's spelling:
  `spell` writes a signature the compiler keeps (receiver as a type, `$T`, what
  the result points into beside it) as Nikaia writes it, and `unspell` reads it
  back. The reader still takes the spelling before it, so a ledger written by an
  older compiler reads unchanged. *(Both are Nikaia now: `unspell` became
  `tools/ledger.nika`'s reader at 0.0.292, and `spell` moved beside it at
  0.0.333, #125.)*
* `returns` and `mutates` are written only where the signature has no place for
  them: five `std` entries whose result is a sequence read out of a text, and
  no entry at all for `mutates`.
* `std.contracts` and the three `hyper_shim` descriptions moved to the spelling
  line by line, their comments kept, and each reads to exactly the contract it
  was before - checked by parsing the old file and the new one and comparing.
* A declared type parameter with no bound is no longer recorded as a bound with
  nothing in it; the brackets declare it, and every reader asked for bounds.
* `tests/ledger_spelling.rs`: a receiver, a result's `ref(a | b)`, a type
  variable in brackets, and `std`'s ledger in the spelling, each written, read
  back to the same contract and written again to the same bytes.
* Found and recorded, not fixed: `keeps` names a `ref` receiver a body only
  reads ([#173](https://github.com/Nikaia-Language/Nikaia/issues/173)). Filtering `ref` parameters out is not the fix -
  a parse keeps the text its result views (ADR-186 D1).

Fixed at 0.0.257: **what [#173](https://github.com/Nikaia-Language/Nikaia/issues/173) found.**

* A receiver written `ref self` or `ref mut self` is not kept: it is a
  reference by the author's word, and a use that would need it whole is
  `NK1131`'s. An argument written `ref` keeps as before (ADR-186 D1).
* A `match` over an argument written `ref` does not keep it; the
  over-approximation that arm makes is for a parameter the lowering could
  still lend.
* A receiver a method takes by value that copies is not moved out of:
  `c.to_ascii_lowercase()` leaves the caller its `char`.
* Not a defect, and left as it is: `State::Quoted(c)` keeps a `char` it is
  given. The column says what a body does, and what keeping a copied value
  costs is the emitter's question (`tests/keeps.rs`).
* `template.nika`'s ledger names no kept parameter now.
