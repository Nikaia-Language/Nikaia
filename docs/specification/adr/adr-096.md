# ADR-096: A Type Nothing Declares Is Refused Rather Than Lowered

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 15, 2026
**Target Version:** Nikaia 0.0.8
**Related:** [ADR-051](adr-051.md) (`NK1117`, the same rule for a **value**),
[ADR-011](adr-011.md) D2 (the emitter writes a name for a name, which is how an
unknown one reached `rustc` intact), [ADR-064](adr-064.md) (which fixed one such
name by building it and left the class), [ADR-054](adr-054.md) D1 (`OFFERED`,
Part I 2.2's own set, which this reads)

## 1. Context

```nika
fn main() {
    let x: Widgit = 3
}
```

lowered to `let x: Widgit = 3;` and came back as `rustc`'s *"cannot find type
`Widgit` in this scope"* — [Part III C.1](../30-nikaia-tooling.md)'s class,
about a file nobody wrote.

**A value nothing declares has had `NK1117` since [ADR-051](adr-051.md)** —
*"nothing declares `q`"*. A type had nothing, so C.1's rule held for one half of
this language's names and not the other. [ADR-064](adr-064.md) fixed
`SharedMut` by **building** it and left the class untouched; every misspelling
took the same route out.

## 2. Decisions

### D1 — A written type name nothing accounts for is `NK1135`.

At the name, in this language's words, with the misspelling named.

### D2 — The known set is built from what the compiler already knows, not from a list.

`OFFERED` is Part I 2.2's own set and already answers *"does `as` name a type
this language has"*; the ledger's `types` map is every type this program and
`std` declare, under both the qualified key and its last segment, because a
library writes the module in front and a caller writes the suffix; and the
declaration around the name contributes its type parameters. A list maintained
beside those would be a second thing to forget, and forgetting it refuses a
correct program.

What is left is a short table of names the **emitter** writes that no ledger
declares — Part I 2.2's numeric surface beyond `OFFERED`'s four, the collections
the prelude provides, and the hulls.

### D3 — A qualified name is somebody else's question.

`http::Response` names a package's type, and whether this build can see that
package is [ADR-046](adr-046.md) D2's, with a message of its own. Saying
*"nothing declares it"* about a name a dependency does declare would be
[Part III C.4](../30-nikaia-tooling.md) — a correct program refused — so this
walk is silent about every name with a `::` in it.

### D4 — A walk of its own, beside `dsl`, `views` and `traits`.

It asks about a written **name** rather than about a value's type, so it needs
the item tree and neither the scope stack nor the inference. Every position a
type can stand in is read: a parameter, a result, a struct's field, an enum
variant's payload in both shapes, a trait method's signature, an `impl`
method's, a `let`'s annotation, and every argument nested inside any of those.

## 3. Consequences

**The corpus was clean, and the sweep was not — which is the measurement.**
Nothing in `examples/`, `tests/samples/` or `crates/nikaia-std/src/` is newly
refused except one line, and the specification sweep moved by six blocks. Both
findings are real:

* **`examples/fortunes.nika` wrote `List[Fortune]`** — a type name this
  language does not have. Part I 2.2's prose calls the concept *List (Vector)*
  and every program writes `Vec`, which is what `std`'s `ListExt` is implemented
  for. The file never built for another reason (the issue tracker, *`fortunes.nika`
  waits on two runtime pieces*), so it never said so.
* **Five specification blocks stopped lowering, and every one of them was
  already `error[E0425]` below** — *"cannot find … in this scope"*, from
  `rustc`, about the generated file. The refusal moved from the backend into
  this compiler, which is the whole of what C.1 asks for.

  They are three different things, and only the first is the sweep's own doing:
  `impl User` and `-> Config` declare their type in a **neighbouring** block,
  which the sweep compiles separately; `NotFound(Path)` and `-> List[Row]` name
  types the specification writes and `std` does not publish, which is the same
  finding as `fortunes.nika`'s one line arrived at from the page's side —
  `fs::map`'s parameter is `?` precisely because Rust's is `impl AsRef<Path>`;
  and `fn total(p: &Player)` names a type the specification declares **nowhere
  at all**, as do `Object` and `SqlParser`.

The sweep's floor moves from 52 to 48 for the first time, with the reason
written beside it: these are not programs turned back into fragments, they are
fragments the compiler had been accepting because it could not read a type name.

**the issue tracker's entry closes** — *a type nothing declares goes into the
language below untranslated*.

## 4. What this does not decide

* **What the specification should do about `Player`, `Object`, `SqlParser`,
  `Path` and `List`.** The first three it declares nowhere; the last two it
  writes as types `std` does not publish, which is
  [`spec-promises.md`](../../spec-promises.md)'s kind of question rather than a
  defect in the compiler. The sweep records what it finds and the page is the
  owner's.
* **A type parameter's *bound*.** `fn f[T: Summarize]` names `Summarize` where a
  trait stands, not where a type does, and a trait nothing declares is
  [ADR-078](adr-078.md)'s question rather than this one's.
* **The `as` position.** `NK1122` already refuses a cast that leaves the eight
  types ([ADR-054](adr-054.md) D1), and two refusals on one token would be two
  messages about one mistake.
* **A field's type on a type whose fields the ledger does not record.** Silent,
  and deliberately: the type resolves and the field cannot be looked up, which
  is a different absence with a different answer.

## 5. What is built

`crates/nikaia/src/types.rs` — `check`, `known_names`, `BUILT_IN`,
`parameters_of`, the item and block walks, and `nothing_declares` — run from
`check_program` beside the other three walks. Exercised by six programs in
`crates/nikaia/tests/undeclared_type.rs`: the reproduction, ten positions a type
stands in, a nested argument, eleven kinds of name that must stay silent, the
qualified case, and a sweep of every `.nika` in the corpus.
