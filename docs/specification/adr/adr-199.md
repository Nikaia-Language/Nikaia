# ADR-199: A Readiness Wait Is a Registration, Not a Worker

**Status:** Accepted · **Built:** yes
**Date:** September 22, 2026
**Target Version:** Nikaia 0.0.165
**Builds:** [#90](https://github.com/Nikaia-Language/Nikaia/issues/90)'s second step — *the socket
layer that keeps registrations rather than answering one readiness question at a
time*
**Narrows:** [ADR-038](adr-038.md) D3's readiness half — the mechanism, not the
surface
**Related:** [ADR-121](adr-121.md) D1 and D4 (the bell, and readiness as
something awaitable), [ADR-009](adr-009.md) D4 (*measure before choosing a
shape*, and this is what that is for), [ADR-006](adr-006.md) D5 (the drain this
had to keep)

## 1. Context

A readiness wait was a [`worker::Op`]. The descriptor was duplicated, handed to
an I/O worker over a channel, and the worker **blocked in the poller for the
whole of the wait**.

`io-workers` is **1** by default — [ADR-038](adr-038.md) D4's *one I/O thread
always runs*. So a wait that had not answered blocked every other wait in the
process.

**That is not a slowness; it is a ceiling on the default configuration.**
Measured before anything was written: two readiness waits at once, the second on
a pipe that already had a byte in it. The second did not get a turn in two
seconds. A server waiting on `accept` while a connection waits on `read` is that
shape exactly, so an HTTP server could not have been built on it.

## 2. Decisions

### D1 — One poller for the process, one thread inside its `wait`, and arming happens on the calling thread.

Registering is an `epoll_ctl`. It does not block, so there is nothing to hand to
anybody: the caller arms and gets a future. When the kernel answers, the thread
fills the slot, wakes the waker and rings the bell.

**Nothing occupies a thread while it waits for something that has not
happened**, which is the whole of what was wrong.

### D2 — The numbers chose this shape, and they said the poller was never the cost.

[ADR-009](adr-009.md) D4 asks for a measurement before a shape is chosen. It was
taken, and it moved the design:

| | per wait |
| :--- | ---: |
| a poller built per wait, which is what the worker did | 7.4 µs |
| one poller, `add` and `delete` around each wait | 2.5 µs |
| a registration kept and re-armed | 1.2 µs |
| **the whole round trip through a worker** | **35 µs** |

§2.6's own words for this step were *keep registrations*, and keeping them is
worth **6.2 µs of 35**. The hop was worth 28. So the step is not what the line
said it was, and the line was written before anything had been measured — which
is the case that rule exists for.

**After**: `rt::io::waiting`, which is what a server uses, goes from **35.4 µs
to 6.6 µs**. `rt::io::wait`, the blocking one nothing hot uses, goes from 35.3
to 29.2 — it is a condvar round trip with the readiness thread and stays one.

### D3 — A registration is *outstanding*, exactly as a worker operation was.

`Runtime::pending` counts them and [ADR-006](adr-006.md) D5's drain waits them
out. That is not a new promise: it is the one the worker path made, kept through
a different mechanism. The park asks *is anything outstanding* before it sleeps,
and the drain asks it before it lets a program go.

### D4 — The bell stays, because a `Waker` does not reach a parked executor.

[ADR-121](adr-121.md) D1's bell is what wakes a thread asleep in
`io_uring_enter` or on the condvar, and neither watches an alarm. So the
readiness thread rings it as a worker did, and the waker it also wakes is for
the executor that honours one.

### D5 — A cancelled wait costs nothing.

Dropping the future deletes the registration. For a socket that is a connection
the program stopped caring about, and it is the case a server meets most.

## 3. Consequences

* **§2.6's step 2 is done**, and what is left of that order is the HTTP/1.1
  server and `nikaia serve [dir]`.
* **`worker::Op::Readiness` and `poll_one` are gone.** The worker enum is back
  to what it is for: operations that *do* something, where blocking a thread is
  the work rather than the waiting.
* **A test that needed an operation which never finishes** now uses a FIFO
  nobody writes to, because opening one blocks until a writer appears — a
  property of the thing rather than a sleep somebody had to choose a length for.
* **A registration that leaves has to wake the drain**, and not noticing that
  cost 30 seconds in a test binary: a drain asleep on *has the set emptied?* is
  woken by an answer arriving and was not woken by a slot going away.

## 4. What this does not decide

* **Keeping a registration across waits.** The measurement says that is worth
  1.3 µs of the 6.6 that are left, and it wants the *socket* to own the
  registration and deregister on close — a lifetime coupling between
  `net::Connection` and the registry that buys less than this step did.
* **Waking one task instead of everybody.** The bell rings and the executor
  polls every pending future, which at one thread is a handful. A server with a
  thousand connections is the measurement that would move it.
* **What a timeout does to a *server*.** Per-registration deadlines are here and
  nothing in `net` passes one; [ADR-194](adr-194.md) D5's caps are the server's.

## 5. What is built

All of it. `crates/nikaia-std/src/rt/readiness.rs`, both `rt::io` surfaces
routed through it, `Op::Readiness` and `poll_one` deleted, `pending` and the
drain carrying registrations, and
`a_wait_that_never_answers_does_not_block_one_that_would` in
`crates/nikaia-std/tests/sockets.rs` — which is the two-second stall, written
down so it cannot come back.
