# ADR-233: A Lambda That Pauses Is Handed to `std`'s Pausing Counterpart

**Status:** Accepted · **Built:** yes, in 0.0.219
**Date:** September 27, 2026
**Target Version:** Nikaia 0.0.219
**Answers:** `open-work.md` §2.1, *a lambda that pauses is refused where `std`
takes it* — under the owner's *Nikaia does not build walls, it takes them
down*, and *the special case pays, not the general one*
**Refines:** [ADR-055](adr-055.md) §6 (its remainder),
[ADR-172](adr-172.md) D3 (the trait for a sequence whose step pauses, which
waited for a second producer), [ADR-122](adr-122.md) D3 (a `std` entry's
lambda is a Rust signature's)
**Related:** [ADR-187](adr-187.md) D1 (Rust's `async` closure, measured),
[ADR-192](adr-192.md) D1 (a run parameter is `impl AsyncFn`), Part II 12.2
(no pause while a lock is held), [ADR-213](adr-213.md) D3 (`NK2105`)

## 1. Context

Nikaia has no `async` and no `await`: any function may pause, and the compiler
works out which do ([ADR-055](adr-055.md)). A lambda is a function, so this is
a correct program:

```nika
let sizes = urls.iter().map(fn(u) { fetch(u).len() }).collect()
```

It was refused by the lowering, *not something this compiler can build yet*.
`std` takes a lambda in ten places, and each entry describes a **Rust**
signature whose closure is synchronous: `Iterator::map` takes `FnMut`, and an
`async` closure handed to it makes an iterator of futures, which is another
program. [ADR-122](adr-122.md) and [ADR-192](adr-192.md) had already built the
shape for a parameter declared in this language; what was left was `std`'s.

## 2. Decisions

### D1 — `map` and `filter` of a sequence hand back a sequence whose step pauses.

Where the lambda handed to `Seq::map` or `Seq::filter` pauses, the result is a
`Seq[U] pauses` — the type `io::lines()` has had since
[ADR-172](adr-172.md) D1 — and everything that type already means applies:

* a `for` over it gives its thread up at each step;
* `collect`, `count`, `nth` and `join` walk it and pause with it;
* `map`, `filter`, `take`, `skip`, `step_by` and `zip` on it make another, and a
  lambda handed to them may pause or not;
* `rev` is `NK2703`: it has no back end, since its length is not known until
  the end (ADR-212 D1);
* it does not go where a sequence that does not pause is wanted — `NK1102`,
  by the fit ADR-172 D1 wrote.

Below, it is `nikaia_std::seq::Paused`, built on a `Step` trait whose `step`
is an `async fn`. That trait is the one ADR-172 D3 deferred *until a second
producer needs one*; this is the second producer. It is the crate's own, not
`futures_core::Stream`, for the reason D3 gave. The lambda is the language
below's `async` closure (`AsyncFnMut`, [ADR-187](adr-187.md) D1), with no box
and no `move`: `std` runs it, it does not keep it
([ADR-192](adr-192.md) D1).

**Nothing is walked where the `map` is written**, as with any `map`: the
lambda runs when something walks the result, and that walk is what pauses.

### D2 — The eager entries await the lambda where they would have called it.

`list::ListExt::map` (a list's own `map`), `Vec::sort_by_key`,
`Entry::or_insert_with` and `Entry::and_modify` run the lambda during the call,
so the call pauses. Each has a counterpart in `nikaia_std::seq` that takes the
`async` closure and awaits it where the synchronous entry calls its closure:
the same order, the same number of calls. `sort_by_key` works each key out
once rather than at every comparison — a key that pauses cannot be asked for
again and again — and sorts stably, as the entry does. The entry helpers serve
both kinds of map.

A list's `map` also resolves to its entry in the checker now, which it did not
(`Vec::map` was looked up and `ListExt::map` is the key), so its lambda's
parameter is typed and the list it takes is **taken**: reading it afterwards
is `NK2105`, where it was `rustc`'s *borrow of moved value*.

### D3 — A pause inside a door is `NK2202`, by Part II 12.2's rule.

The other four of the ten — `access` and `update` on `Locked` and
`SharedMut`, and `access_all`/`update_all` — run their lambda **while a lock is
held**. A pause there holds the lock for as long as the wait takes, which
Part II 12.2 forbids and nothing asked: the program reached the lowering's
*cannot build yet*, a reason that was never the real one. The checker now
refuses every call that may pause inside a door, and a `for` over a sequence
whose step pauses, with `NK2202`, saying what is held and how to move the call
out. It is counted on a tally line of its own, *a pause with a lock held*.

### D4 — Two small walls in the way of the first programs.

* **A view of a value that copies goes where the value is wanted.**
  `sort_by_key`'s lambda is handed a `ref i64`, and `slow(x)` into
  `slow(x: i64)` was `NK1102`. The copy out of it is a machine word, and the
  emitter writes the `*`. Asked of a name only: an operator over a view makes a
  value, and the checker now says so too (`0 - y` over a `ref i64` is an
  `i64`).
* **A view of a `String` is a view of text at a call**: an element of
  `words.iter()` into a `ref String` parameter was `NK1102` — *takes `ref
  String`, and this call passes `ref String`* — because one is `&String` and
  the other `&str` below, and into a `String` parameter the callee only reads
  it was refused with *write `.clone()`*, which ADR-207 D3 says it never needs.
  The language below lends the one as the other at a call, by itself.

### D5 — What pays is the lambda that pauses.

A lambda that does not pause is lowered exactly as before, to the entry's own
synchronous closure. The counterparts are chosen by the checker, per call, from
whether the lambda's body was seen to pause — which the checker already worked
out for [ADR-102](adr-102.md) D2 — and from the receiver's type, which the
emitter has none of ([ADR-028](adr-028.md)).

## 3. What is still refused

* ~~**A lazy walk of `io::lines()`**~~ — built by [ADR-234](adr-234.md).
* **A lambda handed to a method whose receiver nothing describes** —
  `par_iter()`'s, which has no entry (`open-work.md` §2.17). The lowering says
  so, naming this record.

## 4. Consequences

`open-work.md` §2.1 is closed and deleted. The README's row for *functions
have no colour* names only the lazy walk of `io::lines()`. Programs that
compiled before compile to the same Rust.

## 5. What is built

All of it, in 0.0.219:

* `crates/nikaia-std/src/seq.rs`: `Step`, `Paused` and its adapters, `then`,
  `then_filter`, `map_list`, `sort_by_key`, `or_insert_with`, `and_modify`,
  `Slot`.
* The checker: whether a lambda handed to a `std` entry paused; the
  counterpart per call; a pausing sequence as the result of `map` and
  `filter`; `NK2202` inside a door; a list's `map` resolved and taking the
  list; D4.
* The emitter: the `async` closure, the counterpart's call (a `mut` parameter
  handed to `sort_by_key` as the `&mut` it already is), the `*` of D4.
* `crates/nikaia/tests/pausing_lambdas.rs`: D1 to D4, each program run at both
  settings of `user_parallelism`.
