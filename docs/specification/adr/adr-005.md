# ADR-005: Ownership Without Annotations — the Borrow Model

**Status:** Accepted · **Built:** inference and ledger; Group B's structural
`Send` check; D8's CI tests and Group B.2 are not — see §5
**Related:** [ADR-297](adr-297.md) (cleanup, which depends on D6), [ADR-283](adr-283.md)
(works out D4), [ADR-300](adr-300.md) (where D7 is met),
[ADR-020](adr-020.md) (the ledger as built),
[ADR-037](adr-037.md) D2/D3 (the switch Group B's `Send` check may not consult),
[ADR-038](adr-038.md) D7 (which relies on that check for a foreign runtime)

## 1. The four-group taxonomy (normative)

Nikaia promises ownership without the pain while compiling through a toolchain
whose whole vocabulary for ownership is lifetime annotations and borrow-checker
errors. Every borrow situation a program can produce falls in exactly one group,
and the group decides who solves it.

**Group A — rustc already solves it, silently.** Transient borrows ending at
last use (NLL); `list.push(list.len())` (two-phase borrows); borrows held across
an I/O suspension point, which implicit async inherits free from `async fn`'s
self-referential state machines; single-input-reference signatures (elision);
2024-edition capture defaults. These are written into the spec as *guarantees*
(Part I 6.5), not left to chance — the code generator must preserve them.

**Group B — the compiler solves it, with no user-visible syntax.** Cross-function
contract inference (D3); conditional return of a borrow (D2); `Send`-ness checked
structurally in the frontend at *every* setting of `user_parallelism`, so a
library written at `0` cannot turn out un-compilable at `auto`; `Box::pin` for recursive
functions under implicit async.

> **Group B.2 is not solved today, and this list read as though it were.** The
> second member is the one thing in Group B that is still entirely a plan, and §5
> says so. What will solve it is the frontend desugaring named in D2 — not built.

> **Two notes on Group B's third member**, which is built (§5) and is where
> `NK2501` and `NK2502` come from.
>
> **The spelling `0`/`auto` predates [ADR-037](adr-037.md) D2** and is stale:
> the switch is `user_parallelism`, it is `no` or `yes`, and it is a permission
> rather than a count. The sentence is otherwise unchanged, and "*every* setting"
> is the load-bearing word.
>
> **"At every setting" is a claim about the verdict, not about the severity.**
> The check may not consult the switch, because a check that did would answer
> `yes` for a value whose expansion is safe at one setting and not at the other —
> which is the asymmetry this member exists to prevent. What the switch may
> decide is whether *this* build performs the crossing at all: at
> `user_parallelism = no` nothing the user wrote runs concurrently, so a crossing
> into a task does not happen and is reported as a lint rather than refused,
> which is what Part III C.3 asked for. A crossing into a **foreign** runtime's
> thread happens at both settings ([ADR-038](adr-038.md) D7) and is refused at
> both.

**Group C — inexpressible in safe Rust, so the language gets a construct.**
Stored slices (D4); scoped tasks borrowing from the parent (D5); lock guards
across suspension points (D6).

**Group D — a real bug, where only diagnostics help.** Mutating a collection
while iterating it is not a lifetime problem; it is undefined behaviour in C++
and a runtime surprise in Python. The answer is a named safe API for every known
anti-pattern (`retain`, `drain`, `entry`, `swap`) plus D7.

## 2. Decisions

### D1 — Nikaia source contains no lifetime annotations. Ever.

There is no lifetime syntax in the grammar and none will be added. All lifetime
knowledge lives in the compiler and in the generated ledger (D3). This is a
headline language guarantee, not a v0.x restriction.

### D2 — The taxonomy above is normative.

Every reference-related feature is classified A/B/C/D during specification,
before it is designed.

Group B's second member is worth naming: conditional return of a borrow (the
`get_or_insert` shape) is rejected by the stable borrow checker, and what solves
it here is **desugaring the known patterns onto entry-style APIs in the
frontend** — a Group B answer, with no user-visible syntax and no lifetime the
user writes.

**The desugaring is affordable because the corpus already writes it.**
`examples/1brc.nika` and `examples/access-log/src/main.nika` both want exactly this
situation — look a key up, add it if it is absent, keep using it — and both write
`.entry(k).and_modify fn { … }.or_insert_with fn { … }`, unprompted, because that
is the natural way to write it against Nikaia's own `HashMap` surface. So what
Group B.2 will be built from is the language's own idiom.

**The situation is reachable from Nikaia**, which is what keeps it on the list
rather than in Rust's issue tracker: thirteen lines — `let found =
self.entries.get(0)`, `if found.is_some() { return found.unwrap() }`, then `push`
and look again — lower to Rust the borrow checker rejects with `E0502`, and
nothing in the repository writes them
([`docs/history/nightly-cost.md`](../../history/nightly-cost.md) §3.3 has the program). Not
built; §5 says so.

### D3 — Borrow contracts are inferred whole-program and persisted in a ledger.

One region variable per reference position, constraints collected from bodies,
solved over the call graph SCC-wise with a fixpoint for recursion. This is
rustc's own intra-function region inference lifted across function boundaries.

Rust refuses to infer signatures from bodies for a good reason: it creates
action at a distance, where editing a callee surfaces an error three modules
away. Nikaia answers that with a **generated, committed file** rather than
in-source annotations. Each build diffs fresh contracts against it:

* unchanged → callers are not re-checked;
* changed, callers still valid → updated automatically, noted in build output;
* changed and a caller breaks → the error is built *from the diff* and names the
  contract that moved, the body edit that moved it, and the caller that broke.

That last line is the ledger's purpose: turning spooky action at a distance into
a narrated cause chain. A trait method stores one contract, the join of all
implementations, so dynamic dispatch has something to check against. The ledger
ships with published packages, so downstream builds get the same errors.

### D4 — Stored borrows are tethered slices.

> **Transient = borrow, stored = tether.** A slice used within a call tree stays
> a real `&str`/`&[u8]` at zero cost. A slice that *escapes* — into a struct
> field, a `@detached` lambda, or a return past its buffer's frame — is lowered
> to a buffer handle plus a `Range<u32>`.

Safe Rust cannot express a struct holding a buffer and a slice into it, and no
foreseeable feature changes that. The precedent decides it: async Rust abandoned
reference slices for stored data and standardised on `bytes::Bytes`. Nikaia
promotes that from library convention to language semantics.

One refcount per *buffer*, not per token, riding the existing `Shared`
mechanism (`Rc` at `user_parallelism = no`, `Arc` above it). The guarantee
inverts from "you may
not use this token after the buffer is gone" to "the buffer cannot die while a
token lives", which is why the user never sees a lifetime error.

This closes the question of user-visible `struct Foo<'a>` permanently: no, the
tether covers the case. The lattice and the escape analysis are
[ADR-283](adr-283.md).

### D5 — Scoped-task borrowing is sound per `user_parallelism`, and the spec says which.

`task::scope` with implicit borrowing in an async context is unsound in Rust —
a cancelled scope cannot synchronously stop children on other threads whose
borrows point into the dying frame. Hence no safe async scope in tokio.

* **At `user_parallelism = no`: sound.** Nothing the user wrote runs
  concurrently, so no child runs simultaneously with
  cancellation, and teardown collects children before the parent frame dies.
  This rests on two spec requirements: no `mem::forget` equivalent, and task
  futures are runtime-owned, never user-owned values.
* **Above `0`: sound only for `sync` children.** A blocking compute scope (the
  rayon `join` model) covers the real use case, data parallelism, and matches
  what `par_iter` already demands. **Async children with borrows are removed
  from the spec** above `0`; they use `@detached` and return via the handle.

A user will hit this without any Rust background, so the diagnostic says "a
background task may outlive the things it looks at" and states the fix.

### D6 — No suspension point while a lock is held, enforced statically by `sync`.

`access` and `access_all` require a **`sync` lambda at every setting**.

Part II 12.2's "no I/O while holding a lock" is Rust's "a `MutexGuard` must not
live across `.await`" in Nikaia words. Making it static rather than a runtime
reentrancy panic removes an error class from the happy path and shrinks the
divergence of `Locked[T]` between settings. The runtime check and lock poisoning
stay as backstops — `sync` does not rule out reentrant `access` on the same lock
through a chain of `sync` calls.

What a function must do to earn `sync` is [ADR-288](adr-288.md).

### D7 — A raw rustc error reaching the user is a compiler bug.

Nikaia intercepts every backend diagnostic and re-reports it against the `.nika`
line that caused it.

1. Every borrow/ownership/lifetime error class (E0382, E0499, E0502, E0505,
   E0506, E0597, E0716, E0621, …) has a translation with Nikaia vocabulary,
   Nikaia spans and a concrete fix-it, carrying an `NK` code (Part III,
   Appendix C). **`E0277`, a trait bound that is not satisfied, is in the list
   too**, and was missing from it: the seven original classes are all borrow,
   ownership or lifetime errors, and a trait bound is how `Send`, `sync` and
   every future marker rule surfaces from the backend. The experiment in
   [`docs/history/foreign-runtime.md`](../../history/foreign-runtime.md) is what found the gap —
   an illegal thread crossing reached the user as `error[E0277]` against a
   generated file. **`E0621`, a missing explicit lifetime, was missing too**,
   found by [`docs/history/nightly-cost.md`](../../history/nightly-cost.md) §3.3.2 on a
   `HashMap[&str, …]` whose key is stored: it is a lifetime error like the
   seven, so it belongs in the enumeration by the same argument, and nothing
   had put it there.
2. Ledger-diff errors additionally narrate the cause chain (D3).
3. An untranslated rustc error is an **internal compiler error**, never
   acceptable output. This inverts the burden of proof and makes diagnostic
   quality testable: the error catalogue *is* a test suite.
4. Group C and D diagnostics must be understandable with no systems-programming
   background and must say what to do next.

The mechanism is [ADR-300](adr-300.md): `rustc --error-format=json` is read back
and every message is placed against the `.nika` line that produced it, through
the source map the emitter writes.

**The position and the text are two different promises, and only the first is
kept for every class.** ADR-300's translator deliberately does not rewrite a
message, because the lowering is name for name ([ADR-296](adr-296.md) D17) and
"`xs` does not live long enough" is already a sentence about the Nikaia source
with only its place wrong. That argument holds for the seven borrow classes and
**fails for `E0277`**, whose every noun is a Rust type the author did not write.
So for a trait bound the place is translated and the text is not, and the gap is
closed from the other end: what the frontend can decide about a crossing it
refuses itself, in Nikaia words, with `NK2501`/`NK2502` (§5). Rewriting a
trait-bound message into Nikaia vocabulary is a second question and is still
open.

**`E0621` is the same open half, and worse.** Its text is
`help: add explicit lifetime 'a to the type of key` — a lifetime, a region name
and a type annotation, and [ADR-283](adr-283.md) D1 says the author writes none
of the three. So here too the place is translated and the text is not, and this
one cannot be closed from the other end the way the crossing was: what the
frontend would have to decide instead is *which* lifetime a stored view has,
which is ADR-283 D2's tether lattice and is not built.
[`docs/history/nightly-cost.md`](../../history/nightly-cost.md) §3.3.2 has the shape, the two
spellings that each refuse the other's program, and why a partial fix is worse
than none. Recorded, not solved.

### D8 — The ledger is a pure function of (source tree, toolchain), byte for byte.

Same tree, same toolchain, any thread count, any machine → a
byte-identical `nikaia.contracts`. The `Cargo.lock` standard, deliberately not
mere semantic equivalence.

This is cheap because the mathematics cooperates: the inference solves a
monotone constraint system over a lattice, so by Kleene/Tarski the least
fixpoint is unique and solving order cannot change the result. Nondeterminism
can only enter through implementation slips, and canonical serialisation costs a
sort. Byte equality also makes verification `git diff --exit-code` instead of a
custom comparer that can itself be wrong.

Every item below is a documented real-world nondeterminism source, and is banned
in any ledger-emitting path:

| Banned | Why |
| :--- | :--- |
| iterating an unordered hash map to produce output | randomised SipHash seeds per process; rustc's nondeterminism source #1, banned by its dev guide |
| consuming directory listings in filesystem order | `readdir` order differs across ext4/APFS/NTFS — sort every source-tree walk |
| internal counter IDs as ledger keys | not stable across runs; keys are source-derived (module path + name + signature hash) |
| absolute paths, timestamps, hostnames, environment values | standard reproducibility leaks; paths are project-relative |
| locale-dependent sorting | sort by code point, never by collation |
| thread arrival order influencing names or numbering | parallel solving is allowed; derived names come from source identity, never scheduling |

Sub-decisions: parallel solving is **allowed** (the requirement is purity, not
single-threadedness); stability across *toolchain* versions is explicitly **not**
required, or inference could never improve — the ledger records the toolchain
hash and the compiler says when a diff came from a bump rather than from your
code; **one** ledger serves every combination of the two switches
([ADR-037](adr-037.md) D4), because borrow structure is identical whatever the
machine and whatever runs at once. A check that depended on a switch would put a
build-time choice into a file that ships with a package.

Enforced by building twice with different thread counts and comparing bytes, and
by doing that on two operating systems. A mismatch is a red build, never a
flake: the risk here is not the mathematics but multi-year discipline, since any
new emit path can smuggle in a hash-map iteration.

The two builds are two **processes**, and that is the load-bearing half. A hash
map's iteration order is stable within one process and randomised between them,
because the seed is per-process — so a same-process comparison passes over the
one banned item that is easiest to write by accident.
`ledger_determinism.rs` runs every example the bootstrap compiler can lower
twice, in two processes, at one thread and at four. The second operating system
is not wired up: it would catch the `readdir`-order and locale rows rather than
the hash-map one, and it costs a second CI matrix leg.

## 3. Rejected alternatives

* **Implicit clone on conflict** — non-deterministic performance, incompatible
  with deterministic resource management. Nikaia never inserts a clone the user
  did not write; diagnostics suggest, the user decides.
* **In-source borrow annotations** (`-> &str @from(a, b)`) — the contract is
  derived truth and belongs in a generated artifact. A persisted, diffable
  contract explains a break better than a hand-written annotation, which can
  only mismatch.
* **User-visible struct lifetime parameters** — subsumed by D4, and viral: every
  collection, `Shared[…]` and trait impl inherits the constraints, producing
  exactly the errors Nikaia exists to prevent.
* **The full Rust lifetime model with hidden inference only** — keeps every hard
  error while removing the syntax needed to fix it.

## 4. Consequences

The frontend gains a region-inference engine and a diagnostic-translation layer.
Both are substantial and both are the direct price of the headline promise.

Ledger merge conflicts resolve like lockfile conflicts: regenerate.

## 5. What is built

D1, D3, D7 and D8 — the last except its second operating system. D4's lattice is
built as [ADR-283](adr-283.md) describes it and D6 as [ADR-288](adr-288.md)
does; the ledger under both is [ADR-020](adr-020.md). **Group B.2 is not built**:
D2 says what will build it, the frontend desugaring onto entry-style APIs, and
nothing of it exists yet. What follows is **Group B's third member**, the
structural `Send` check, which three records relied on and none had.

### 5.1 The rule, and why it is one answer

> A value may cross a thread only if it may cross **any** thread.

That is [ADR-038](adr-038.md) D7's first rule read as a property of the *type*
rather than of the crossing, and reading it that way is what makes it one answer
at both settings of `user_parallelism`. `contracts::send` walks a type
structurally and transitively — through a container's arguments, through a
`struct`'s `fields` as the ledger records them ([ADR-024](adr-024.md)), through a
type that holds itself — and gives one of **three** answers, not two:

| answer | what it means |
| :--- | :--- |
| **may** | every part of it may cross, and the compiler can see every part |
| **may not** | a part of it may not. **No type the records name answers this since [ADR-037](adr-037.md) D6** — `Shared` was the one, and D6 gives it a count that is atomic at both settings, so it is answered by what it holds like any other container. The arm stays for the next type whose expansion moves with the switch |
| **undecided** | nothing written down says. A Rust type whose parts this compiler cannot walk, a `?`, a lambda's captures |

**The third answer is the design, and `undecided` is not `may`.**
[ADR-010](adr-010.md) D1 — an analysis that fails open is a vulnerability
generator — forbids reading the absence of an answer as permission. But
`undecided` cannot be a refusal either, because Stage 0 knows the type of rather
less than half of what a program writes and Part III C.4's property is that the
compiler never rejects a program that is correct. So what the two non-`may`
answers cost depends on **who chose the crossing**:

* a crossing **the compiler chose** — the `task::both` that statement
  overlapping emits ([ADR-292](adr-292.md)) — is a step it was never obliged to
  take, so anything but `may` means it does not take it and the statements keep
  their written order. Fail-closed costs speed here and never a refusal, which is
  ADR-292 D3's own polarity applied to the crossing question;
* a crossing **the program wrote** is refused on `may not` and handed on on
  `undecided`. Handed on, not accepted: `rustc` still type-checks the emitted
  crate ([ADR-002](adr-002.md) §3), and D7's `E0277` translation now reports that
  refusal against the `.nika` line instead of against a generated file.

**A type whose parts are Rust can say so**, in one line of the ledger: `crosses`
on a `[type."…"]` entry is a promise about a body this compiler does not read,
written in the file that ships and reviewed like code — the same kind of line as
`sync = true` on a Rust function. Its absence is "nobody said", never "it may
not". `cli::Args` is the first: without the claim, the ten overlapping pairs
ADR-292 measured would have gone again, because `undecided` is not
permission.

### 5.2 Where the crossings are, and which are covered

| crossing | covered | how |
| :--- | :--- | :--- |
| `task::both` — statement overlapping's vehicle | yes | the result of each overlapped operation crosses back to the thread that started it, so it must be able to; anything else keeps the written order. The *captures* are empty by construction (`Accounted::NonLiteralArgument`), and this is the check to ask about each of them on the day that limit is lifted |
| `spawn` | yes, `NK2501` | every name the task's body mentions, looked up in the scope outside it. Part II 11.2's runtime integration is unbuilt, so the check runs ahead of the emitter |
| a scope's tasks | **no** | `task::scope` has no syntax in the grammar and no AST node. There is nothing to check yet; D5 and Part II 12.7 are what it will have to answer to |
| a value handed to a call this compiler cannot see the end of | yes, `NK2502` | [ADR-038](adr-038.md) D7's foreign runtime. A call no ledger describes may do anything with what it is given, and a thread of its own is among them |

### 5.3 What it does not reach, and what it costs

**It is enforceable only as far as a foreign crate is honest.** A Rust API that
writes `unsafe impl Send` about a type that is not puts a value on another thread
with nothing complaining, and a structural check in the frontend would not catch
it: the value is crossable *by declaration* where Nikaia can see it.
[ADR-038](adr-038.md) D7's first rule now says so, and
[`docs/history/foreign-runtime.md`](../../history/foreign-runtime.md) §3.5 is the program that
demonstrates it.

**Nothing in the language is refused today, and that is the point of the
ordering.** `Shared` is the only type the records make non-crossable and it is
unbuilt, so every value a Nikaia program can construct may cross. The check was
built first precisely because today's silence is free only while that is true:
`Shared` creates the first value that can get it wrong, and a program handing one
to a foreign call would otherwise be accepted at `yes` and refused at `no` with a
raw `E0277` as the only signal.

**One question is left for `Shared` itself and is not answered here.** A value
that may not cross at `no` may not cross at `yes` either, because the verdict may
not consult the switch — so `Shared` will not cross a thread at all, and Part II
12.2's shared counter is the program that wants to.
[ADR-037](adr-037.md) D3 already names the way out and leaves it open: "whether
the *choice between `Rc` and `Arc`* could be made per value rather than per build
is a real question and is not answered here". It has to be answered before or
with `Shared`, and this check is where the answer lands.

*(**[ADR-037](adr-037.md) D6 answers it, and it landed here as this section
predicted.** The way out taken is neither of the two this paragraph imagined: the
count comes off the switch altogether — atomic at both settings — so the verdict
still never consults it and `Shared` crosses. The two sentences above it are
therefore both still true and both now vacuous: nothing in the language is
refused a crossing, because `Shared` was the only type that was and it no longer
is. The `may not` arm is kept rather than deleted, for the reason §5.1's table
now gives. What still stands in front of Part II 12.2's counter is `Locked`,
whose representation does move with the switch and is D3's second half.)*
