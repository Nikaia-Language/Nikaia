## 1. Question

**What is a `grammar` in Nikaia - and what does the language promise about how
it reads its input, how a program enters it, when its parse may run on several
cores, how it reaches the language below, and what its actions may do?**

One record, because every answer leans on the first: the core parser keeps no
global token stream, so foreign syntax can be embedded (D1). That makes a
grammar a construct of the language rather than a library, so its entry is an
ordinary call (D24), its actions are ordinary code checked like any other
(D28, D35), and what it fails with is an ordinary named type (D38). And
because a grammar is already the file's specification, it is the one place a
format assumption may be written so that a parse can be cut blindly and run in
parallel (D9-D13).

Without the answers the compiler cannot verify a frame, cannot know which rule
a call enters, cannot tell a program what a parse threw, and leaves to the
backend's error - against a file nobody wrote - every defect in an action.

## 2. How others do it

| Language / tool | Its answer | Source |
| :--- | :--- | :--- |
| `winnow-grammar` (the backend) | parses `&str`/`&[u8]`, no token stream; uppercase rules lexical, lowercase syntactic; `=>` the cut; `recover(rule, sync)`; one function per **public** rule, no main rule; action blocks required, no auto-AST | D25; [ADR-001](adr-001.md) D2 |
| ANTLR | uppercase names are lexer rules | D33's neighbours, §6 |
| pest | a `WHITESPACE` rule steers implicit skipping; actions live outside the grammar | D22, §6 |
| Ohm | semantic actions kept outside the grammar | D33 |
| The fast reference implementations of the one-billion-rows workload | split the buffer blindly, repair the seam; find the separator a word at a time; hash a key from its first bytes, and some also *compare* only the first 8-16 bytes (unsound) | D11, D12, D14 |
| Rust `asm!` | register constraints in the core language - what D6 removes, because WebAssembly is a stack machine | D6 |

What transfers: the backend's model is adopted as the language's (D1, D25),
and the case convention, `WS` and the cut stay with their precedent (D33's
neighbours, §6). What does not: hand-written SWAR in user code, which is
unreadable and unportable - the grammar states the assumption and the compiler
exploits it (D12, D13).

## 4. Decision

### D1 — Scannerless parsing is a language guarantee, not an implementation detail.

The core parser keeps no global token stream. A grammar consumes the raw
character stream, and whitespace handling is a property of the rule. The
consequence is accepted: Nikaia can never adopt a token-stream frontend without
breaking `dsl`.

### D2 — A DSL block ends explicitly, with `} eod`.

The core parser cannot find the end of foreign syntax by counting braces, so it
scans for the marker, skips the body and parses the rest of the file while the
DSL parser works. A body that contains the literal `} eod` is read from a file
and handed to its grammar by a call (D24, D27), never by a configurable
terminator.

### D3 — One spelling at build time and at run time; *when* is said by `comptime`, *where the bytes come from* by `asset("…")`.

```nika
comptime CONFIG: Json::Value = Json::value(asset("config.json"))
let data = Json::value(user_input)
let query = dsl mysql { … } eod
```

A parse has one spelling at either stage, and its position never decides its
meaning: the same call reads its argument's text at run time, and at build time
only because `comptime` asks for it and `asset` names the file. A `dsl` block
is an expression. How a grammar runs while the program is built is
[ADR-177](adr-177.md); what a build may read is [ADR-310](adr-310.md).

### D4 — A hole binds in one of two ways, and the grammar author says which.

`meta::capture(id)` is **immediate**, resolved from the surrounding scope at
compile time (assembly: `$v = in(reg) val` means *this* `val`).
`meta::parameter(name, type)` is **deferred**, a named runtime parameter (a
prepared statement, which baking values in would destroy). It is the same
immediate/deferred axis as lambda capture and teardown
([ADR-297](adr-297.md) D5), and Part II 10.5 states it as a principle.

### D5 — A DSL with deferred parameters generates a shadow type.

The `:name` holes of a body become a type the call site is checked against: a
missing name is `NK1112`, an unknown one `NK1113`, on the `.nika` line. The
parameters are configuration, passed as named arguments after the subject -
`query.execute(db; target_age: min_age)`, or `stm.execute(target_id: 501)`
with no `;` when there is no subject ([ADR-133](adr-133.md) D3) - and a driver
receives them with the typed spread `...args: Self::dsl`, which keeps its `;`
in the signature. Following D17, the field types come from the call site (the
struct is generic and monomorphised where it is built), there is one struct per
parameter list rather than per DSL string, `Self::dsl` also names the result,
and a hole is found by scanning, so `SELECT ':id'` is read as one until a
grammar's `meta::parameter` says otherwise. The driver's own half, `args.values()`, needs a value type for the
parameters and is not decided further here. Flagged as the least proven
decision of the protocol.

### D6 — Hardware instructions leave the language core.

`unsafe asm`, its register-constraint table and `clobber` are removed.
Assembly is a library DSL, `dsl x86::Asm { … } eod` ([ADR-299](adr-299.md) D20), using D4's immediate capture.
A core construct that cannot be given meaning on WebAssembly, a stack machine,
is a defect in the core. `unsafe` stays reserved for FFI.

### D7 — Auto-AST and regex terminals are goals, not behaviour.

Actions are required (no generated structs for labelled sequences); fixed
built-in terminals meet the intent of regex terminals. Specification text
promises neither.

### D8 — Zero-copy is two mechanisms, and the grammar picks per rule.

Identifiers and keywords are interned `Symbol`s; bulk text (string literals,
comments, doc text, DSL bodies) is a tethered slice
([ADR-005](adr-005.md) D4, [ADR-283](adr-283.md) D11). The guarantee is stated
positively: the source buffer cannot be freed while a token points into it.

### D9 — `@frame` declares a resynchronisation unit, and the compiler checks it; it never rewrites the grammar.

```nika
rule NAME -> ref String = s:until(";" | frame_end) { s }

@frame(boundary: "\n")
rule MEASUREMENT -> Reading = name:NAME ";" => temp:TENTHS frame_end { Reading { name, temp } }
```

A frame can be found from any offset by scanning to its boundary. The frontend
walks everything the rule reaches; **safe**: a literal without the boundary, a
built-in whose alphabet excludes it, lookahead, an `until(t)` whose terminator
covers the boundary (`frame_end`, the boundary literal or a prefix of it,
`line_ending` for a newline); **rejected**, naming rule and pattern: a literal
containing it, a built-in that can consume it (`any`, `multispace0`), the
implicit whitespace of a syntactic rule, an `until` that does not cover it
(the message says `until(… | frame_end)`), and `recover(…)` - recover per
frame instead, `(item | until(frame_end)) frame_end`. `frame_end` names the
boundary of the frame the rule is reached from and resolves statically. The
attribute is keyed - `@frame`, `@frame(boundary: "\n")`,
`@frame(boundary: "\n", unchecked)` - and `unchecked` is the greppable
assertion for formats a byte string cannot cut (quotes, start markers,
escapes), each a future key. A frame ends in its boundary. A syntactic
(lowercase) rule the frame reaches skips whitespace before each element, so it
is refused unless the grammar declares its own `WS`, which is then checked as
part of what the frame reaches. The `par_fold` rule that folds the frames
skips no whitespace whatever its name - not at its entry, not at its start,
not between frames - so whitespace between frames is not a frame and fails at
any chunk count (D10).

### D10 — Parallel parsing is a frame plus a monoid: `par_fold`, written, never inferred.

`par_fold(ITEM, init, step, merge)` is `fold` plus a merge, over an `@frame`
item, and the whole body of its rule; the split, seam repair, per-chunk
accumulators and merge are generated, and the program writes
`Measurements::file(data)`. A written `par_fold` says *results from different
chunk counts are the same to me*. Chunk count changes neither what is accepted
nor what is rejected: a `par_fold` rule is lexical in all but name (D9). At `user_parallelism = no` it is a sequential `fold` - same accumulator,
same merge, same result - which keeps it compiling for `wasm32`.

### D11 — The lowering is a blind split, then a seam repair.

*n* equal byte ranges (*n* = `cpu::count()` by default); every chunk but the
first advances past the first boundary at or after its start, so each frame is
owned by exactly one chunk, the one that finds its end; the last runs to EOF,
an unterminated last frame is still yielded and no empty trailing frame is; a
frame longer than a chunk is not an error; errors carry absolute offsets, and
under `recover` one chunk's failure does not abort the others; chunk count
does not change results and is overridable for benchmarking. The driver takes
`Parallelism::Off | Pieces(n) | Auto`, `Off` identical to the plain parser, and
the cut and merge are public so the pieces can run on Nikaia's own pool.

### D12 — Scanning is a specified complexity: never one byte at a time.

A boundary or `until` terminator is found by a portable word-at-a-time (SWAR)
scan - no target feature, works on `wasm32`; SIMD is a layer on top, never the
baseline. Up to three fixed alternatives are one pass. The same primitive
serves `recover`'s skip.

### D13 — Fixed-width numeric parsing needs bounded repetition in the grammar.

`p{n,m}` (as in `digit{1,2}`) is the only route by which a fixed-width fast
path may be emitted; `digit+` says unbounded, and a compiler that assumed a
width would be inventing a constraint.

### D14 — Hash a view from its first bytes if you like; never truncate the comparison.

Hashing a view key from its first 8 bytes mixed with its length is sound;
comparing only a prefix on a probe hit is not. Equality on views is content
equality ([ADR-283](adr-283.md) D11). Which hash is used is chosen by
provenance ([ADR-010](adr-010.md)), never at the cost of this property.

### D15 — Teardown of a large read-only buffer may be skipped at process exit.

A read-only mapping with no `Cleanup` and nothing observable attached may be
left to the kernel at exit - the one relaxation of "cleanup always runs"
([ADR-297](adr-297.md)), by proof of non-observability, not by a flag. It is
an allowance; [ADR-014](adr-014.md) records that it is not taken.

### D16 — A grammar is parsed, not carried as text.

`grammar Name { … }` becomes a structure: rules, alternatives, patterns, the
commit point, repetition bounds, `fold`/`par_fold` with their expressions, and
the keyed `@frame`. Which rule a call enters, whether it is a `par_fold`, and
whether the grammar declares a frame are answered from the rules.

### D17 — The lowering is syntactic, and never guesses a meaning.

*Changed by [ADR-013](adr-013.md) D2: a step that calls a `&mut self` method returning nothing has its accumulator threaded by the emitter, found by a lookup in the program's declarations rather than guessed from the step's shape.*

Every action, every `init`/`step`/`merge` and every body is emitted as
written, name for name. Where Nikaia and Rust disagree about a name, the
emitted program fails to compile rather than the printer inventing semantics.
A step `fn(acc, m) { acc.record(m) }` with a `&mut self` method is not
threaded from the shape of its tail; that adapter is a typing question.

### D18 — `@frame` lowers key for key, and Nikaia does not re-implement its check.

`@frame(boundary: "\n")` becomes `#[frame(boundary = "\n")]`, `unchecked`
passes through, and the boundary keeps its escape text. The check that a
boundary cannot occur inside a frame lives once, in the backend: two
implementations would drift, and the harmful drift is Nikaia accepting what
the backend rejects.

### D19 — `user_parallelism` chooses the `Parallelism`, and nothing else.

A call to a `par_fold` rule lowers to the piece driver with `Parallelism::Auto`
or, at `no`, the identical call with `Parallelism::Off`; the two programs
differ in one token. A switch selects a build, not a dialect
([ADR-037](adr-037.md) D1). A rule that is not a `par_fold` gets its own
parser, run once over the whole input.

### D20 — A rule that is a `par_fold` gets its binding from the compiler; every other alternative carries an action.

A `par_fold` is the whole body of its rule, so its value is the rule's and
nothing is written after it. Everywhere else an action is required, and the
pattern ends where its action block begins (D33).

### D21 — A view takes the input's lifetime, and the struct holding it comes along.

A view in a rule's result type is emitted with the backend input's lifetime; a
struct with a view field carries the lifetime wherever it is named, named
inside the grammar module and elided in a function signature. Every view is
emitted as `Borrowed`; the tether-state lattice is not implemented here - a
named limitation.

### D22 — Comments are whitespace, and string literals are Nikaia's own.

`WS = (WSE | COMMENT)*` is where comment skipping is said. The compiler brings
its own lexical `STRING`, which keeps escapes as written, because the
backend's `string` does not know `\n` - and keeping them is what makes D18's
"the backend is handed the same `"\n"`" true.

### D23 — A grammar reaches the parser backend as a macro invocation.

The lowering emits `grammar! { … }`, name for name with the `.nika` file. A
`grammar` item is never dropped silently.

### D24 — A grammar is entered by an ordinary call, and the rule's name is the function's.

```nika
let data = Json::value(input)
```

`Json` is the grammar, `value` an `entry rule` in it, reached as every qualified
name is, by a path ([ADR-140](adr-140.md) D3; `Json.value(x)` is `NK1147`). A
call gets `?`, `catch`, being passed on and being chained for free. `dsl X
from e` is refused at the parse with the call in the message; `dsl` takes a
**driver** name and only that.

### D25 — Every `entry rule` is an entry, the compiler distinguishes none, and `pub` belongs to the grammar.

*Changed by [ADR-299](adr-299.md) D21: the author may mark one entry `main`.*

As the backend does: one function per entry. The compiler picks no rule as the
grammar's main one - such a pick chooses wrong silently - so there is no
*"grammar has no entry to enter through"* to refuse. The grammar's author may
say which one is main (`main entry rule`, ADR-299 D21); that is a decision
written down, not a pick. Naming a rule that is not
an entry has its own message.

Whether a rule is an entry and whether other packages may use it are two
questions, and each has its word. **`entry`** is a decision about the rule:
it was written to be entered on its own - a helper such as 1BRC's `NAME`,
whose `frame_end` means something only inside a frame, was not. So an entry is
never inferred from a call, which would make one out of a typo. **`pub`** is a
contract with other packages, and a grammar's contract is all its entries:
`pub grammar` offers every one of them, as a `pub enum` offers its variants,
and a rule is never `pub` on its own - `pub rule` is refused with both words in
the message. A grammar is entered only from its own file today, so `pub
grammar` is decided and not built, and refused as such.

### D26 — There is no `parse` alias.

A program that wants `Json::parse(x)` names its rule `parse`.

### D27 — Where the bytes come from is said separately, by `asset("…")`.

`comptime ROUTES = Routes::table(asset("routes.txt"))`: `comptime` says when,
`asset` where the bytes come from ([ADR-310](adr-310.md)), the call what is done with them.

### D28 — A fold's `init`, `step` and `merge` are walked by the ordinary expression walk.

They are expressions inside a pattern; they get every rule the language has -
`NK1117`, `NK1132`, `NK1128`, and whatever comes next.

### D29 — Inside the frame the rule's own pattern makes.

A binding beside the fold in the same sequence is in scope in its lambdas.

### D30 — Outside `expected`.

The rule's declared type is what an action builds; a fold's `init` and `step`
build the backend's running value, and holding them to the declared type would
refuse the arithmetic every fold is made of.

### D31 — One walk, not two.

A jump in a fold's step meets `NK1132` through the lambda path every other
lambda takes - *the nearest loop is outside this lambda* - and no second walk
of the fold's own exists beside it. [ADR-276](adr-276.md) D18's backstop in the
lowering stays. Measured: nothing in the corpus is newly refused.

### D32 — Part II 10.8 lists every element a grammar may write, and it is complete.

An element not on the page is not in the language; a built-in the engine
offers that the page does not name is unreachable from a `.nika` grammar.

### D33 — A rule's action is the block after its pattern, with no second arrow.

`rule pair -> Pair = key:string ":" => val:value { Pair { key, val } }`. The
one `->` is the result type. A bare `{` after a pattern begins the action; a
brace delimiter in the input is `{ p }` around a pattern, and a bound starts
with an integer against the brace (`digit{1}` is a bound, `digit { 1 }` an
action). The arrow form is refused by name, with the new form in the message.

### D34 — `tag` and `digit1` are not spelled.

`"x"` and `digit+`; either engine name is `NK1187`, carrying the spelling. The
emitter keeps writing the engine's own spelling.

### D35 — An action may not pause, and a call that can is refused where it stands.

`sync` is asked of every call an action makes and of every call a fold's
`init`, `step` and `merge` make; a call that can pause is `NK2209`, naming the
rule. A parse that can be cut and run on several cores (D10) is one whose
steps do not wait on the world. Refused only where the ledger answered, as
every `sync` rule is.

### D36 — So a grammar's entry is `sync`, and says so in the ledger.

```toml
[fn."Nums::number"]
sync = "asserted"
throws = ["ParseError"]
```

`asserted` because it is a rule of the language, not an inference; the entry
is a leaf of the `sync` fixpoint that holds, so a function whose body is one
call to it is `sync` again.

### D37 — What this does not restrict.

An action may **fail**, may call anything that does not pause, and a grammar
may be entered from a body that pauses; what is refused is a pause inside the
parse.

### D38 — A parse fails with `ParseError`, and every entry says so.

`throws = ["ParseError"]`. The type is `nikaia-std`'s, in the prelude, keyed
in `std.contracts` with no module in front, as `Overtaken` is. The lowering
wraps the backend's rendered message, so a program prints exactly what it did
before; what changes is the channel - with a second named member a caller's
set is a sum a program can `match` on ([ADR-280](adr-280.md)).

### D39 — It carries the message and nothing else.

Fields a program could read - line, column, expectation - are a second
question nobody has asked.

### D40 — A callee the `throws` graph does not hold still has a set.

A grammar entry is not an `Item::Fn`, so the fixpoint reads its set from the
ledger; otherwise what a parse throws would reach no caller.

### D41 — What a fold's step calls directly is written `#[inline]`.

The step is the loop body over the input, so it runs once per item, and what
it calls usually has that one call site. LLVM left 1BRC's `Summary::record` out
of line all the same, because hashbrown's insert path makes it too big for its
heuristic; no profile setting changed that (16 or 1 codegen unit, thin LTO:
319.1 instructions a row; fat LTO 317.0). With the hint: 300.1, the same output
([#433](https://github.com/Nikaia-Language/Nikaia/issues/433)). So a function
or method a `fold`'s or a `par_fold`'s step calls is written `#[inline]`, found
by name, because the step's receiver is the accumulator, whose type this
emitter does not know (D17). It is a hint LLVM may still ignore, and only
here: every function `#[inline]` would bloat the code and the build.

## 5. Consequences

* A reader learns the construct from Part II chapter 10: 10.1 (scannerless,
  actions), 10.2 (the entry and `comptime`), 10.5 (`dsl`, holes, the shadow
  type), 10.6 (zero-copy, recovery, failure names), 10.7 (frames and
  `par_fold`), 10.8 (the vocabulary); Part III chapter 16 (assembly as a DSL).
* Every analysis that reads a function body reads an action and a fold's
  lambdas the same way: names (D28), jumps (D31), pauses (D35), failures
  (D38, D40). An entry's `touches` and `locks` are derived over its grammar's
  actions, and what it keeps is [ADR-186](adr-186.md).
* The emitter stays a printer (D17, D18): a name it cannot place is the
  backend's error, positioned on the `.nika` line by
  [ADR-300](adr-300.md) and worded in Rust's words - bearable because the
  lowering is name for name.
* Accepted costs: no token-stream frontend, ever (D1); a body containing
  `} eod` must come from a file (D2); views emitted as plain borrows (D21);
  `NK2209` and `NK1112`/`NK1113` only where the ledger or the scan can answer
  (D35, D5).

## 6. What this does not decide

* The driver's half of D5: `args.values()`, a value type for the parameters,
  and `SqlAst[Signature = {…}]` as a spelling.
* Auto-AST and regex terminals as behaviour (D7); still to raise upstream, with
  error recovery that accumulates diagnostics.
* Chunk-count policy beyond `cpu::count()` (NUMA, heterogeneous cores, a
  container's CPU quota), and `par_fold` over a stream rather than a mapped
  buffer.
* Further `@frame` keys (`quote`, `start`, `escape`, `scan`) and inferring a
  boundary without a marker.
* The tether-state lattice for a grammar's views (D21).
* What a fold's lambdas' *types* are, and whether the rule's declared type
  reaches the fold (D30; [ADR-023](adr-023.md)).
* A word in place of the case convention, a `skip` declaration in place of
  `WS`, any change to `=>` and `# "…"`; and the engine built-ins 10.8 leaves
  out (`hex_digit1`, `oct_digit1`, `binary_digit1`, `space0`, `space1`,
  `count`, `lex`, `spaced`), each reachable the day a line is added to the
