# ADR-186: A Parse Keeps The Text Its Record Views

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 22, 2026
**Target Version:** Nikaia 0.0.137
**Closes:** [#140](https://github.com/Nikaia-Language/Nikaia/issues/140) (*a grammar's entry does
not say what it keeps*), and with it the last entry of that file's §1
**Related:** [ADR-082](adr-082.md) D1 (a `pub` rule is a ledger entry),
[ADR-140](adr-140.md) D3 (the entry is reached by name), [ADR-094](adr-094.md)
D2 (`keeps`), [ADR-008](adr-008.md) D2, D7 (the states a view is in),
[ADR-142](adr-142.md) D1 (an action may not pause),
[ADR-010](adr-010.md) D1 (absence read fail-closed)

## 1. Context

[ADR-140](adr-140.md) D3 turned a grammar entry into a call **by name**, and
that made its contract visible for the first time: before it, a grammar was
entered through a method whose receiver nothing resolved, and the analyses
answer nothing about a call they cannot name. What they read instead was
`..Default::default()` with a `throws` and a signature on it, because nothing
derived the rest.

Three of the four columns have been answered since. `sync` is
[ADR-142](adr-142.md) D1 asserted rather than inferred; `touches` and `locks`
are derived over the action blocks, with the grammar as the unit
([ADR-033](adr-033.md) D4's over-approximation). `keeps` was left absent, and
[#140](https://github.com/Nikaia-Language/Nikaia/issues/140) recorded the reason: *absent means nobody said, so the
caller does not lend*.

**That reading was wrong, and the code is what says so.** `keeps_its` reads
**an absent `keeps` on a present entry as *keeps nothing*** — the same
convention `std.contracts` uses for `sync`, said once more for a second column.
The entry is present. So the column was not being withheld; it was answering
*lends*, in the open direction, for every parse in the corpus. [#140](https://github.com/Nikaia-Language/Nikaia/issues/140)'s own
reproduction is the visible half of it: `read`, whose body is one
`Stock::file(data)`, lost `keeps = ["data"]` the day the entry became a call by
name, and the parse it calls hands back `Entry`, which holds a `ref String`
into the very text `data` names.

The entry also carried the question as if it needed a mechanism nobody had
built, citing a `Bytes` entry of [`open-decisions.md`](../../open-decisions.md)
that [ADR-179](adr-179.md) answered at 0.0.127 and that has not been in the file
since. It does not need one. The walk exists, the predicate exists, and what was
missing was an item kind.

## 2. Decisions

### D1 — A parse keeps its `input` exactly when its declared result may hold a view into it.

A grammar entry takes one parameter, the text
([ADR-082](adr-082.md) D1). A parse hands back views **into** that text — a
`ref String` field of a record it built is a view of the bytes it was given —
and a value that outlives the call is what `keeps` means
([ADR-094](adr-094.md) D2). So `Stock::file -> Vec[Entry]` keeps its `input`
where `Entry` holds a `ref String`, and `Calc::expr -> i64` keeps nothing.

**An empty column now means *asked and no*, where before it meant *nobody
derived it*** — and the two were written the same way, which is what made the
old state an answer rather than a silence.

### D2 — The rule's **declared result** decides it, and not the action blocks.

`touches` walks the actions, because what a parse *does* is in them. What a
parse can *hand back* is not: it is the rule's declared result type, and an
action that built something else would not type-check. The input is not a name
an action block can reach, so the only way the text leaves the call is through
the result.

That is also why this needs no fixpoint over the grammar the way `touches` does.
One rule, one declared type, one answer.

### D3 — A result this walk cannot see into **keeps** the text.

[ADR-094](adr-094.md)'s polarity, unchanged: a use this walk cannot account for
counts as keeping, because the two wrong answers are not symmetric. Saying
*kept* of a text only read costs a caller an owned argument, which is where
every caller already is. Saying *lent* of a text a parse holds views into is a
`&` on a value that outlives the call, and that is `rustc`'s words about a file
nobody wrote ([Part III C.1](../30-nikaia-tooling.md)).

So the walk answers *no view* only where it can account for **every** name in
the result: a type this package declares that holds none, or one
[Part I 2.2](../10-nikaia-light.md) offers, or a container whose arguments it
has already read. Anything else is a declaration it did not read.

### D4 — The same fact writes the `views` column, and the state is **Borrowed**.

An entry whose result may view gets `input: borrowed` and
`<result>: borrowed` ([ADR-008](adr-008.md) D7). The buffer is the **caller's**
text, which outlives the call — the same sentence `tether::of` already reaches
for a function with a view among its parameters, read off the shape of a grammar
instead of off a signature. Nothing in the corpus tethers, which the sweep over
the tree asserts.

**One predicate for both columns**, so the two cannot drift: a parse that keeps
its text is a parse whose result views it, and there is no third answer for one
of them to hold.

## 3. Consequences

* **`keeps` and `views` appear on every parse in the corpus that hands back a
  record** — seven of the twelve `pub` rules — and on none of the five that hand
  back a number.
* **The reproduction closes.** `read` carries `keeps = ["data"]` again, and
  `Stock::file` carries `keeps = ["input"]` and the two view positions it never
  had.
* **No lowering changes.** A grammar entry's `input` is typed `?`, and
  `keeps::lends` does not lend a type it cannot name; `read`'s `data` is written
  `ref String`, which the declaration lends whatever the column says. So this
  lands as [ADR-094](adr-094.md) §5's first step asks: the answer is in the file
  before a call site reads it.
* **the former backlog file is empty.** Every defect that file carried is closed.

## 4. What this does not decide

* **Which rule of a grammar views the text.** The entry is the unit here as it
  is for `touches`, and a rule whose own result holds no view still sits in a
  grammar whose records do. No column distinguishes them, and none needs to:
  the question is asked of the entry a caller names.
* **What a caller does with a kept text.** `keeps` is a restriction on lending
  and nothing reads it yet ([ADR-094](adr-094.md) §5). When one does, a parse is
  an ordinary entry with an ordinary column.
* **The tether itself.** A parse that views the caller's text is *Borrowed*, so
  the state that is not built ([ADR-156](adr-156.md) D4) is still not reached by
  anything in the tree.

## 5. What is built

All four, at 0.0.137.

* `contracts::INPUT`, so the three places that name a grammar entry's one
  parameter name it once.
* `tether::declared_in`, which reads a **package's** borrowing types and its
  declared type names in one pass — the package and not the unit, because a
  grammar is emitted into the file it stands in ([ADR-030](adr-030.md) §7) while
  the record it yields is a declaration of the package.
* `tether::a_parse_that_views`, D1's predicate with D3's polarity, read by
  `tether::infer`'s grammar arm for D4's column and by `keeps::infer`'s for D1's.
* `crates/nikaia/tests/keeps.rs` holds the reproduction from both ends — the
  entry and its caller — and the two negatives; `crates/nikaia/tests/tethers.rs`
  holds the states, and its sweep over the tree still finds no tether.
