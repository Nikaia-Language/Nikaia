# ADR-179: `&[T]` Is a Type of This Language, and It Is What a Run Crosses As

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 21, 2026
**Target Version:** Nikaia 0.0.127
**Answers:** [`open-decisions.md`](../../open-decisions.md)'s *may a build-time
value cross as a view into what the build allocated* — **Option A**
**Supersedes in part:** [ADR-147](adr-147.md) D1's *`&[T]` is refused outside an
`extern "C"` declaration*. The `&mut` half of that sentence stands; the run does
not
**Related:** [ADR-079](adr-079.md) D1 (which named `&[T]` as the crossed form of
a `Vec[T]` and could not spell it), [ADR-152](adr-152.md) (`Array[T, N]`, the
form that was built instead and carries a length),
[ADR-094](adr-094.md) D1 (the `&` a caller does not write) and D3 (the `mut`
that is a declaration), [ADR-107](adr-107.md) D3 (no copy the program did not
write), [ADR-177](adr-177.md) (a grammar's result, and the sub-program that
builds it)

---

## 1. Context

[ADR-079](adr-079.md) D1 says a build-time result crosses in its **view** form:
*`Vec[T]` arrives as `&[T]`, `String` as `&str`.* Half of that was built. Text
crossed as a `&str`, because `&str` is a type Part I 2.2 already gives; a list
crossed as an `Array[T, N]` ([ADR-152](adr-152.md)) — that record's §5 says so
in as many words, *the array is what the type language can already spell* — and
`&[T]` stayed unspellable.

**Which was fine until the length was not one number.** An `Array[T, N]` carries
its length in its type, so a **field** of a `struct` can be one only where every
value of that struct has a run of the same length. `struct Section { settings:
Vec[Setting] }` is the shape both corpus grammars produce, and it could not
cross: `Array[Setting, N]` cannot type a field whose `N` differs per value, and
a `Vec` owns memory a `const` cannot hold. [ADR-177](adr-177.md) §5 records the
measurement — *neither grammar in the corpus produces a result that crosses* —
and this is why.

**Two more things wanted the same missing type.** A **binary asset** has no
result type an `asset_bytes` could have ([ADR-072](adr-072.md) reads text and
refuses bytes that are not UTF-8), and `Bytes` ([ADR-156](adr-156.md) D1) owns
its run. Three absences, one type.

**And the spelling already parsed.** `&[T]` is in the grammar and reaches the
checker as `Ty::Pointed { slice: true, mutable: false }`, because
[ADR-147](adr-147.md) needed it for the C boundary — where it lowers to an
address beside a count. What that record added was a refusal away from the
boundary, on the reasoning that *a run of elements whose length the type does
not carry has no lowering here*. That was true of a **declaration** and was
never true of a **view**: `&str` is exactly such a run, and it is the type Part
I 2.2 gives text.

## 2. Decisions

### D1 — `&[T]` is a view of a run, and it is a type wherever a type may stand.

It lowers to Rust's own `&[T]`, a fat pointer that carries its length — which
is the half a `Vec` and an `Array[T, N]` also carry and a C declaration does
not. `.len()`, `xs[i]`, `xs[i].field` and `for x in xs` read one.

**Two writers for one spelling**, which is the arrangement
[ADR-147](adr-147.md) already chose and this is the second half of it arriving:
inside an `extern "C"` declaration `&[T]` is D1's address beside D2's count, and
everywhere else it is Rust's `&[T]`. `&mut [T]` and `&mut T` stay the boundary's
alone, refused with `NK1158` — a position this language may write through is
declared `mut name: T` ([ADR-094](adr-094.md) D3), and that half of ADR-147 D1
is not touched.

### D2 — What a body **owns** does not go into one, and the refusal says which line is which.

A `&[T]` points at a run somebody else keeps. A `Vec[T]` a body just built is
not one, and there is no `&` the compiler may write for it: a `struct` outlives
the expression that fills it, so the view would point at something already gone
([ADR-107](adr-107.md) D3 — no copy and no borrow the program did not write).

**A parameter is the case where the `&` *is* the compiler's**
([ADR-094](adr-094.md) D1): the callee reads and the caller keeps, so
`total(xs)` for an `xs: Vec[i64]` needs no word, exactly as `count(dna)` does
for a `String` against a `&str`. The two look identical on the page, which is
why the other one is **`NK1179`** and not a fit that quietly holds.

**And the value is spelled against the declaration.** The same computed list is
`[1, 2, 3]` against an `Array[i64, 3]` and `&[1, 2, 3]` against a `&[i64]`, and
nothing in the value says which — so the crossing walks the **type** beside it,
down through a struct's fields and a variant's payload, and writes the `&`
exactly where a slice was declared.

### D3 — At build time the sub-program **owns** what the program views.

A grammar runs by compiling the parser it generates ([ADR-177](adr-177.md) D1),
and a parser builds a `Vec`. So in the sub-program every `&[T]` field is written
back as the `Vec[T]` it is a view of, and the **dump** — generated from the
*program's* declaration — reads a run either way.

That is the crossing rather than a disagreement: the sub-program is
[ADR-079](adr-079.md) D1's growable side and the program is its fixed one, which
is the record's own sentence read at two ends of one build.

### D4 — A rule's **action** may not build a struct whose field is a view of a run.

The same rule as D2, at the one place where this checker knows nothing about the
value: an action's bindings come from the parse. So inside an action anything
that is not already a view is `NK1179`, and the way out names `Vec[T]` — because
*write a `&`* is not a thing anybody can do on a grammar line.

**What a rule may hand back is the run itself**, and that is the crossing the
corpus wanted: `pub rule file -> Vec[Setting]` reaching
`comptime SETTINGS: &[Setting]`.

## 3. Consequences

* **[ADR-079](adr-079.md) D1 is built as written**, four records later. `Vec[T]`
  arrives as `&[T]`; `Array[T, N]` stays what a program writes where it wants
  the length in the type.
* **`&[u8]` follows for free**, which is the byte buffer three things were
  waiting on.
* **One refusal is added** (`NK1179`) and one is **narrowed** (`NK1158`, to the
  `mut` half of [ADR-147](adr-147.md) D1).
* **`std` gains one impl**, `Get` for `[V]`, because `[V]` is neither a `Vec<V>`
  nor a `[V; N]` to the language below and a blanket one would overlap the map's.
* **What it costs:** a type in Part I 2.2 that every later analysis answers for,
  and the escape question it does not yet ask — see §4.

## 4. What this does not decide

* **`asset_bytes`.** The result type exists now and the read does not;
  [ADR-072](adr-072.md)'s three-part naming is what it would be written under,
  and that is a package rather than a line.
* **Where a view may travel.** D2 refuses the one shape that is certainly
  wrong — a body's own run in a struct's field — and the general question is the
  **escape analysis** (the issue tracker's Tethered entry), which is built and read
  by nothing. A `&[T]` handed out of a function is `NK2303`'s question the way a
  `&str` is, and nothing here changes that.
* **A struct with two layouts.** `Section` holding a `Vec` at run time *and*
  crossing as a `const` is the Tethered representation, not this. What this
  gives is the choice between the two forms, written down in the declaration.
* **`Bytes`** ([ADR-156](adr-156.md) D1), which owns its run and is the same
  question read from the other end.

## 5. What is built

All of D1 to D4, at 0.0.127.

* **The type**, away from the boundary: `types.rs` refuses the `mut` and lets
  the run through, and the emitter writes `&'a [T]` where `foreign_ty` writes
  `*const T`.
* **The crossing**: `rust_constant_type` gives `&[T]`, `crosses_as_fixed` takes
  a `Vec[T]` into one with no count to check, `declared_below` spells a run of a
  declared `struct`, and `written_below` walks the declaration beside the value
  so the `&` lands where a slice was declared and nowhere else.
* **The reads**: `Get` for `[V]` in `nikaia-std`, which is what `ROWS[0].name`
  and `for r in ROWS` go through.
* **The lending**: `Ty::Pointed { slice: true, mutable: false }` answers
  `is_a_view`, which is what makes `keeps::lends` true and the emitter write the
  `&` at a call.
* **`NK1179`**, with two sentences: one where the value's type is known and one
  inside an action, where it is not and the way out names `Vec[T]` instead of
  printing a `?` nobody can write ([Part III C.2](../30-nikaia-tooling.md)).
* **The sub-program's `growing()`**, and a `&[T]` arm in the dumper.

**The tests run programs**, because what a view points at is not a question a
string comparison answers: `crates/nikaia/tests/slices.rs` compiles and runs a
`const` of a run of `struct`s, a byte buffer, a lent parameter, and a grammar
whose result crosses.
