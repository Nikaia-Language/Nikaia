# ADR-194: Two Servers, Not One — The Standard One Is The Operator's And An Application's Is Its Own

**Status:** Accepted · **Built:** no — see §5
**Date:** September 22, 2026
**Target Version:** Nikaia 0.0.153
**Answers:** [`open-decisions.md`](../../open-decisions.md)'s *what does a Nikaia
program have to write to be a microservice, and who decides what is exposed?*
**Related:** [ADR-018](adr-018.md) (what a handler is given and gives back),
[ADR-069](adr-069.md) D1 and D2 (`http` is a package, and the subtraction that
put it there), [ADR-121](adr-121.md) D1 and D4 (the awaitable readiness this
rests on), [ADR-038](adr-038.md) §4.5 and D5 (the server's order, and what an
operating property is), [ADR-108](adr-108.md) (a path names its root at the
call)

## 1. Context

The ask was the ergonomics of `python -m http.server`: **one command line, no
ceremony, functionality reachable in a minute.**

The question that page carried forced a choice between *the program decides what
is exposed* and *the operator decides*, and offered four options to pick from.
**The owner's answer is that the choice is false**, and it is false for a reason
worth writing down: those are not two designs for one product. They are **two
products**, and each is right about itself.

## 2. Decisions

### D1 — The socket is `std`'s and the protocol is the package's.

[ADR-069](adr-069.md) D2's subtraction, carried one item further. That record
itemised what genuinely needs the compiler — a path's provenance, escaping by
type, a body that is bytes the program never allocated — and pushed *the
protocol and the framework* out of `std`. A **socket** is neither: it is an
operating-system resource of exactly the kind `std` already owns in `fs` and
`io`, and the runtime knows about it already — `rt::io`'s own words are *a
socket is **not** a file; `epoll` answers a socket exactly*.

And the `http` package is **Nikaia**, which cannot make a syscall. So the line
falls where the subtraction already put it: `std` lends the socket, the package
speaks HTTP.

### D2 — There are two servers, and they are different products.

* **The standard server** — `nikaia serve [dir]` — serves the current directory
  or the one it is given. It has no program behind it, so everything it does is
  **the operator's**: the directory, the port, the limits, whether it leaves
  localhost. Command-line options, and a configuration file where a deployment
  wants one. This is the `python -m http.server` half of the ask.
* **An application that serves** — a Nikaia program that builds a server and
  routes it. Everything about it is **the programmer's**: it may read a
  configuration file of its own, hard-code what it likes, take its port from
  anywhere. Nothing here is the compiler's business and nothing is forced on it.

**Why this is the answer and not a compromise.** A standard server has no author
present at run time, so the only person who can decide anything is the one
starting it. An application has an author who decided already, and a tool that
overrode them would be taking away the reason to write the application. The
earlier framing — *exposure is an operating property, so the operator names the
routes* — is [ADR-038](adr-038.md) D5 applied where it belongs, which is the
first product, and it was wrong to reach into the second.

### D3 — It binds to localhost, and anything wider is asked for.

Both products. `python -m http.server` binding every interface is half of why it
is a footgun, and the fail-closed default costs one flag to leave.

**The flag is not silent.** [ADR-108](adr-108.md)'s shape is the precedent: a way
around a check is *recorded per site and listed by `nikaia --trust`*. Binding
past localhost is that shape — this record does not build the listing, and it
names it as where such a thing belongs.

### D4 — An application routes with `.route(…)`, and there is no `@route` yet.

[ADR-018](adr-018.md)'s own form, and it needs **no language change at all**:
measured at 0.0.152, the whole chain runs across a package boundary — a type
constructed through its package, a method chain over it, a function-typed
parameter ([ADR-102](adr-102.md) D1), and the `async` closure
[ADR-192](adr-192.md) D1 writes for a run parameter.

**No word on the declaration**, and no *every `pub fn` is a route*. The second is
refused outright and stays refused: `pub` is a **package** word
([ADR-047](adr-047.md) D2), and reading it as *the network may call it* would
give one word two meanings and make the dangerous one invisible at the
declaration — the polarity [ADR-010](adr-010.md) D1 exists for.

**And [ADR-018](adr-018.md)'s example is stale in one token.** It writes
`http::Server::new()`; `NK1149` answers *a type is constructed by its anonymous
constructor* since [ADR-140](adr-140.md) D2. The record is not rewritten, and
what is written is `http::Server()`.

### D5 — The MVP's protocol is the smallest one a microservice needs, and the parser is Rust until it is not.

`GET` and `POST`, bodies by `Content-Length`, `Connection: close`, no chunked
transfer and no TLS. That is [ADR-038](adr-038.md) §4.5's own order read as a
scope: a socket layer that **keeps registrations**, then a minimal HTTP/1.1
server on it, then the parsing moved into Nikaia, then `rustls`, then HTTP/2.

**The parser is written in Rust, in `nikaia-std`, and moving it into a Nikaia
grammar is a later step of that order** — self-hosting the protocol is not the
MVP, and saying so is the difference between a step deferred and a step
forgotten. *(That step is taken at 0.0.247: `nikaia-std/src/tools/http1.nika`
is the grammar and the rules, and `http1.rs` keeps the bytes.)*

**The limits are the operator's** in the first product and the program's in the
second: a body cap and a connection cap exist from the first commit, because a
server without them is a denial of service rather than a default.

## 3. Consequences

* **The `http` package stops being a skeleton**, and what it gains is the
  protocol and the framework — which is what [ADR-069](adr-069.md) D2 said was
  left after the subtraction.
* **`std` gains a socket**, which is the first new operating-system resource
  since `fs`, and it is on [Part I 1.3](../10-nikaia-light.md)'s list like the
  others.
* **Nothing in the language changes.** That is the whole of what 0.0.152's
  measurement bought: the shape the record prints already runs.
* **What it costs:** a socket in `std`, a protocol in a package, and a command
  that is a file server — three pieces, and only the first is in the compiler's
  half of the tree.

## 4. What this does not decide

* **Whether a route may be refused by what its handler `touches`.** The ledger
  knows — a route onto a function that touches the filesystem is a different
  object from one that computes, and no other language's `http.server` has that
  column. **The owner has asked to be asked again**, with a fuller write-up,
  when the work reaches it. It is deferred on purpose and not dropped.
* **How arguments arrive** at a handler whose signature is not one
  [ADR-018](adr-018.md) D1 describes. The MVP routes only onto a signature that
  record already covers and refuses the rest with the signature it would need.
* **`--trust`'s listing of a wide bind** (D3), which is where
  [ADR-108](adr-108.md)'s shape would put it.
* **HTTP/2, TLS, keep-alive and chunked bodies**, each of which is a later step
  of [ADR-038](adr-038.md) §4.5's order.

## 5. What is built

Nothing of the server. What is built is the ground under it, and that is more
than the entry it answers suggested:

* **The runtime is ready** — [ADR-121](adr-121.md) D1 and D4, whose §3 names
  this need outright: *`rt::io::wait` is awaitable, which is the first thing the
  HTTP server's socket layer needs*.
* **The handler is decided** — [ADR-018](adr-018.md) D1 to D4.
* **The shape runs**, across a package boundary, in
  `crates/nikaia/tests/project.rs`.

The order of work is [ADR-038](adr-038.md) §4.5's, and
[`open-work.md`](../../open-work.md) §2.6 carries it.
