# ADR-013: Running the Flagship — `std`, Methods, and What Stage 0 Refuses to Infer

**Status:** Accepted · **Built:** yes
**Closes:** the fold-adapter question left open by [ADR-296](adr-296.md) D17, and
most of [ADR-296](adr-296.md)
**Superseded in part by:** [ADR-277](adr-277.md), which removes the `fn:` form
this record's D5 had recorded as a limitation to live with
**Related:** [ADR-296](adr-296.md) (the Stage 0 lowering),
[ADR-014](adr-014.md) (what D1's `fs::map` became),
[ADR-024](adr-024.md) (the type checker §4 predicted)

## 1. Context

[ADR-296](adr-296.md) got the flagship's grammar onto the parser backend and
named the rest: `impl` blocks, `throws`/`catch`/`??`, string interpolation, and
the `std` names the program calls. This is that rest, and the measure of it is
not that the constructs parse — it is that the file compiles and prints what the
benchmark asks for.

Two questions had to be answered rather than deferred: **where the meaning of
`fs::map` lives**, and **when the compiler may adapt a method it was handed**.

## 2. Decisions

### D1 — Nikaia's `std` is a crate, not a table inside the emitter.

`fs::map`, `cli::args`, `HashMap` and the list operations live in
`crates/nikaia-std`, and a program importing from `std` gets
`pub use nikaia_std::prelude::*;` in its preamble, so the names resolve as
written.

The alternative was a substitution table in the emitter — `fs::map(x)` prints as
`std::fs::read_to_string(x)`. Rejected, because it makes the semantics of the
standard library into strings inside a printer: unreadable, untestable, and
impossible to document. As a crate, every function has a doc comment stating
what it guarantees and what it does not yet do, in the place a reader looks.

**One name had to change.** `d.to_digit()` cannot be a method: Rust's `char` has
an inherent `to_digit(radix)`, an inherent method beats a trait method, and a
call that resolves to the wrong thing is worse than a name that reads
differently. It is the free function `digit_value(d)`.

### D2 — The fold adapter is a lookup in the program's declarations.

[ADR-296](adr-296.md) D17 refused to thread a fold's accumulator by inferring
from the shape of the step's body, because `acc.record(m)` and `acc.merged(m)`
look identical and mean opposite things, and said the answer waits for `impl`
blocks. It does not have to wait any longer:

```nika
par_fold(MEASUREMENT, Summary::new, fn(acc, m) { acc.record(m) }, Summary::merge)
```

`record` is declared `fn record(&mut self, m: Reading) sync` — it takes its
subject by mutable reference and returns nothing, so the accumulator must be
threaded and the emitter writes `|mut acc, m| { acc.record(m); acc }`. A method
that returns a new accumulator is left exactly as written.

A method name two `impl` blocks disagree about is left alone rather than
resolved by preference. The emitted code then fails to compile, which is the
right outcome for an ambiguity the compiler cannot settle.

### D3 — `throws`, `catch` and `??` lower to what they already mean.

* `throws` → `Result<T, Box<dyn Error>>`, boxed because Nikaia's own error types
  are not lowered yet ([ADR-023](adr-023.md)). A `return` inside such a function
  carries the `Ok`, and a function returning nothing ends in `Ok(())`.
* `catch` → a `match`, with the error bound to `error`.
* `??` → `unwrap_or_else(|| fallback.into())` — the `into()` because the
  fallback is written as the value it stands for, not as the type the option
  holds.

A lambda's `return` leaves the lambda, so it never carries the enclosing
function's `Ok`.

### D4 — The anonymous constructor is `new`, and the call site says which form it is.

An anonymous `pub fn(…) -> Type` has no name and Rust has no such thing, so it
is emitted as `new`. `Type(positional)` calls it; `Type(named: value, …)` is the
struct literal. They are told apart by requiring the named form's first field to
carry a value — otherwise `Stats(x)` would read as a struct with one shorthand
field.

### D5 — An implicit lambda takes the arguments its body uses.

The implicit names are `a`, `b`, `c`. Rust closures have fixed arity, so the
emitter takes the longest prefix of those names the body actually reaches for:
`fn { a.add(m.temp) }` becomes `|a| …`.

This decision also recorded that the expression-bodied form `fn: …` could not be
chained, as a limitation to live with. That was the wrong shape of answer, and
[ADR-277](adr-277.md) removes the form instead.

### D6 — An interpolated hole may say how it is written.

`f"{a}={s.mean():.1}"`. The first colon not inside a call or an index separates
the expression from the format spec; `Stats(min: 1)` keeps its colon, being
inside parentheses. `{{` and `}}` are literal braces. Without this, the
benchmark's own output format could not be written at all.

### D7 — Where Stage 0 does not infer, the source says it.

This is the decision the other six rest on: **the lowering stays syntactic, so
where a program relied on inference the compiler does not have, the program is
what changes.** The flagship's edits, and what each teaches:

| Change | Why |
| :--- | :--- |
| `sum: first` → `sum: first as i64` | Nikaia states no implicit numeric widening, so the conversion is written |
| `{s.min / 10.0}` → `{s.min as f64 / 10.0:.1}` | the widening again, and D6 for the decimal |
| `merge(&mut self, other: &Summary)` → `other: Summary` | the loop takes entries out of it, so the parameter is kept ([ADR-094](adr-094.md) D2) |
| `d.to_digit()` → `digit_value(d)` | D1 — a limitation, not a language statement |

Each of these is a sentence about the source rather than a workaround: a reader
learns that Nikaia does not widen integers silently. Whether an argument is lent
or kept is never the caller's to write — [ADR-094](adr-094.md) D1 — so no row
here puts a `&` at a call.

## 3. What this makes of the corpus

```text
$ nikaia --input examples/1brc.nika --backend rust
$ ./brc measurements.txt
{Bulawayo=8.9/15.5/22.1, Hamburg=-3.4/2.9/12.0, Palembang=38.8/38.8/38.8}
```

A test does exactly that on the real example: lowers it, compiles the result
with the same `rustc` that built the test, runs the binary over an input small
enough to check by hand, and compares the line. It also runs it against a
missing file, because the `catch` in `main` is part of what the example claims.

## 4. What was still not true here, and what closed it

* `fs::map` read the file rather than mapping it — [ADR-014](adr-014.md) D2.
* `Parallelism::Auto` ran the pieces in sequence — [ADR-014](adr-014.md) D3.
* `sync` was unchecked — [ADR-020](adr-020.md), and [ADR-288](adr-288.md) for
  what earns the claim.
* There was no type checker — [ADR-024](adr-024.md), with one half of the
  prediction here deliberately unfulfilled. The Nikaia-level messages arrived.
  The implicit widening did **not**, and will not: D7 says a conversion is
  written, so a checker that quietly widened an integer would be checking a
  different language. What the checker knowing the types bought was the
  diagnostic, not the coercion.
