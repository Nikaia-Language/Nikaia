# ADR-166: Cargo's Target-Info Probe Is Given an Empty Standard Input

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 20, 2026
**Target Version:** Nikaia 0.0.84
**Related:** [ADR-002](adr-002.md) D1 (the orchestrator and its `rustc`
wrapper), [ADR-003](adr-003.md) D2 (the generic half knows nothing about
`.nika`), [Part III C.1](../30-nikaia-tooling.md),
`docs/open-work.md` §3.1, which carried this for months

## 1. Context

`nikaia build` points `RUSTC_WORKSPACE_WRAPPER` at the `nikaia` binary itself,
so every `rustc` command line Cargo produces arrives here first
([ADR-002](adr-002.md) D1 §5). One of them is not a compile:

```text
rustc - --crate-name ___ --print=file-names --crate-type bin … --print=cfg
```

Cargo runs it once per build to learn what the target looks like. The `-` means
*the program is on standard input*, and Cargo writes nothing there — it wants
the `--print` answers, not a compiled program.

The wrapper passed that invocation straight through, standard input included.
Inherited, that standard input is **whoever started the build**, and anything
sitting in it is read as a Rust program. What the build said then was:

```text
error: failed to run `rustc` to learn about target-specific information
  --- stderr
  error: unknown start of token: `
   --> <anon>:1:16
  1 | warning: trait `Foo` is never used
```

— a parse error about text nobody offered as source, at `<anon>:1`, in a build
of a program that does not contain it.

**It took months to name because the contaminant is never the same.**
`docs/open-work.md` §3.1 recorded it as *the wrapper's stdin is the suspect*,
then recorded that suspicion **refuted** — `cargo test … < /dev/null` failed
identically three runs out of three. That measurement was right about what it
measured and wrong about what it concluded: closing the *outer* command's
standard input does not close the **test binary's**, and the harness is what
the nested build inherits from. The sighting that finally named it had another
process's rendered warning on the pipe, whole, which is what a shared harness
stream looks like from the inside.

## 2. Decisions

### D1 — An invocation that names `-` **and** asks a `--print` is handed `/dev/null`.

Both halves are required, and neither alone is the probe: `-` is what makes
`rustc` read standard input at all, and a `--print` is what says the answer is
something other than a compiled program. A real compile names a **file**, so
nothing that genuinely hands `rustc` a program this way loses one.

Every other invocation keeps the standard input it had.

**Why the wrapper and not the caller.** A build that fails because of what was
in the terminal's input is not reproducible, and a toolchain that is
reproducible only when invoked carefully is not reproducible. The probe has one
correct standard input — empty — and the process that knows that is the one
holding the argument list.

**And it is [C.1](../30-nikaia-tooling.md)'s class**, one step further out than
that section usually reaches: the message is about neither the program nor a
generated file, but about text the user never offered to anything.

## 3. Consequences

* `cargo test -p nikaia --test project` stops failing, which it did
  deterministically whenever the shell that started it had left something on
  the pipe — repeatedly, in the session that found this.
* **`docs/open-work.md` §3.1 is narrowed rather than closed**, and that
  distinction is the honest one. This mechanism is named and has a test that
  reproduces it on demand, which that entry never had. A **whole-workspace**
  run still fails the project tests, and the reproducer is now down to two
  binaries — `--test project --test one_name` — where what fails is
  `Blocking waiting for file lock on package cache` and a build that times out
  behind it. That is contention over one Cargo package cache between test
  binaries, which is a different thing from this and is what the entry carries
  now. *Closed in 0.0.215*: measured again, neither the lock contention nor the
  end-to-end test's flake reproduced - two full parallel `-p nikaia` sweeps,
  the first run after a rebuild, and the two-binary reproducer three times -
  and the test runs in every sweep again.
* **What it costs:** one predicate and one `Stdio::null()`.

## 4. What this does not decide

* **Whether the wrapper should narrow anything else it passes through.** It
  passes environment, arguments and the other two streams on untouched, and
  nothing has asked otherwise.

## 5. What is built

D1. Three tests: the probe's argv and a real compile's told apart, neither half
alone counting as a probe, and — the one that holds it closed — the **real**
probe through the **real** wrapper with a rendered diagnostic written onto its
standard input, asserting it answers `target_arch=` instead of trying to
compile it. Without D1 that test reproduces the original error exactly, which
is what makes it a test rather than a description.
