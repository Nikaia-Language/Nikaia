## 1. Question

**How is a loop left, and what is a jump?** Three loop forms or two; whether
`break` and `continue` exist, which loop they leave and whether they carry a
value; where a jump may not go; what type a jump has where it stands as an
expression; and whether its condition may follow it.

Each answer leans on another: a `loop` keyword is worth a word only if `break`
carries a value; whether `while true` can end a function that declares a type
depends on whether a `break` can leave it and on what the language below makes
of it; and a jump as an expression is safe only because a value after a `break`
is refused. So they are one record.

## 2. How others do it

| Language | Its answer | What it costs there | Source |
| :--- | :--- | :--- | :--- |
| **Go** | no `while` at all: `for { … }`, `for cond { … }` and `for … range` are one word in three forms | nothing: one word carries every loop shape | from ADR-070, not re-checked |
| **Rust** | `loop { … }` is an expression; `break value` hands its value back; a `loop` with no `break` diverges and is `!`; labels name an outer loop; `while true` draws the `while_true` lint | a second loop keyword and a second naming scheme for labels | the reference; the lint as measured in ADR-085 §1 |
| **Swift** | `guard cond else { return }` | a negated condition and a new word | from ADR-255, not re-checked |

What transfers is Go's: one keyword per loop shape is not needed. What does not
is Rust's case for `loop`, because it rests on `break` carrying a value (D2,
D13). Rust's types do transfer below the language: `while true { }` is `()`
there and `loop { }` is `!`, which decides D3-D5.

## 3. Options, weighed

| Option | What is written | Why it lost | Was |
| :--- | :--- | :--- | :--- |
| a `loop` keyword | `loop { … }` | a second spelling for a loop the language already has; its only argument is a `break` with a value, which D13 refuses | ADR-070 D1-D2 |
| no `break` or `continue` | a flag, or `return` | a `for` cannot be stopped: the flag stops the body while the loop turns on - 2,000,000 turns for 1,415 turns' work, unbounded in `n` | ADR-084 §1 |
| labelled jumps | `break 'outer` | a second naming scheme, invisible to every analysis that asks where a value goes; reopened only by a measurement on a real program | ADR-084 D2 |
| `break x` | `while true { … break x }` | a loop that is sometimes a value is the ambiguity `if` was spared; additive later | ADR-084 D3, ADR-151 D1 |
| an `#![allow(while_true)]` in the preamble | - | a blanket over every file, hiding a warning that was right | ADR-085 D3 |
| a jump stays a statement | `=> { throw NotFound }` | braces that hold nothing together and produce nothing | ADR-138 §1 |
| `guard … else` | `guard speed <= 250 else { return 250 }` | negates the condition and adds a word | ADR-255 §1 |
| a trailing condition on any statement | `x = 1 if c` | a reader would have to read every line to its end to learn whether it runs | ADR-255 D2 |

## 4. Decision

**The unconditional loop**

### D1 — `while true { … }` is the unconditional loop, and there is no second spelling for it.

There is no `loop` keyword. One fewer keyword puts the whole of control flow on
one page; a keyword is the most expensive thing a language adds and the hardest
it removes.

*Was ADR-070 D1, restated by ADR-084 D7.*

### D2 — A `loop` keyword is reopened only by a `break` that carries a value.

Rust's `loop` earns its word because `break value` makes it an expression.
Here `break` carries nothing (D13), so the case is empty. Should that change,
the question comes back, and `while true { … }` whose `break` hands back a value
would read as a lie: the head says the loop does not end and the body says what
it ends *with*.

*Was ADR-070 D2's reopening condition, as ADR-084 D7 applied it once `break`
existed.*

### D3 — A `while` whose condition is the literal `true` is emitted as `loop { … }`.

This is name for name, not an exception to it: D1 says what the construct *is*,
and Rust's name for the unconditional loop is `loop`. The literal only - never
a name that happens to be `true`; `while running { … }` stays a `while`.

*Was ADR-085 D1 and D2.*

### D4 — The emitted preamble gets no `allow`; where the language below complains about emitted code, the first question is whether it is right.

A suppression in the preamble says *nobody will be shown this again*, about
every file, including cases nobody has looked at. An `allow` is the answer only
once the warning has been asked about and found wrong, and then it stands next
to the emitted construct.

*Was ADR-085 D3; it displaced ADR-084 §3's preamble `allow`.*

### D5 — The two forms differ in type below, so D3 is a prerequisite and not a nicety.

`while true { }` is `()` in Rust and `loop { }` is `!`. A function that never
returns can be built only out of the second, so no checker rule (D6) could have
stood while the emitter wrote the first.

*Was ADR-085 D4.*

### D6 — A body whose last statement is a loop nothing leaves does not answer for its type.

`fn forever() -> i32 { while true { … } }` is not `NK1104`. The tail check is
skipped rather than satisfied: there is no value, and inventing one would claim
something about a program that has none. An accept loop, an event loop or a
supervisor needs no unreachable `return`. That `return` stays legal.

*Was ADR-070 D3 and ADR-093 D1.*

### D7 — The test is the literal `true`, and no `break` bound to that loop.

The same literal D3 turns into `loop`, so the checker claims divergence in
exactly the cases the emitter delivers it.

*Was ADR-093 D2.*

### D8 — The walk over-approximates *a jump leaves this loop*, on purpose.

It descends into a lambda, where a `break` is not bound to this loop. A false
*yes* costs the unreachable `return` every program already had; a false *no*
would hand `rustc` a body that falls off its end. So it leans to *yes*.

*Was ADR-093 D3.*

**The words**

### D9 — `break` and `continue` are reserved words; `loop` is a name.

A program may not name anything `break` or `continue`. `loop` is reserved for
no construct (D1), so it is an ordinary name, and a `loop { … }` meets the
undeclared-name help, which says *write `while true`*. Reserving narrows what
parses and un-reserving widens it, so a word is reserved for a construct the
language may want and for nothing else.

*Was ADR-071 D1, and D3 as it stands with ADR-117 D1.*

### D10 — The reserved words are three alternations in the grammar, not one widened.

The alternation the grammar backend generates is a tuple with a maximum width;
the jump words went into a third part (`RESERVED_C`) rather than onto the end of
the second, whose width had already broken once.

*Was ADR-071 D4.*

**The jumps**

### D11 — `break` leaves the innermost loop around it; `continue` starts that loop's next turn.

*Was ADR-084 D1, which made them statements; D20 makes them expressions as
well.*

### D12 — There is no label.

A label is a second naming scheme, scoped to a construct and invisible to every
analysis that asks where a value goes: the six analyses that walk statements
each needed an arm for the two jumps, and every arm does nothing. Leaving an
outer loop is a flag or a `return`. **Reopened by a measurement** - the shape,
written out against the labelled form, on a program someone has.

*Was ADR-084 D2.*

### D13 — A loop is a statement and hands back nothing, so neither jump carries a value, and `break x` is refused rather than read as two statements.

Without the refusal, `break i` parses as `break` and then a statement `i`: the
program compiles and the value is dropped. `NK1133` says what is true - nothing
after a `break` or `continue` in the same block is reached. A construct that is
sometimes a value and sometimes not is the ambiguity `if` was spared by being an
expression always (Part I 3.1).

*Was ADR-084 D3 and ADR-151 D1.*

### D14 — `NK1133`'s help names the two shapes that carry a value out of a loop.

A `let` before the loop that the loop assigns, or a `return` where the function
has nothing left to do - the second is what a search loop is usually written
as.

*Was ADR-151 D2.*

### D15 — Admitting `break x` stays additive.

Every program that would use it is refused today, so admitting it later breaks
none.

*Was ADR-151 D3.*

### D16 — A jump does not leave a function; a `break` or `continue` whose loop is outside a lambda, a task, an `overlap` branch or a DSL fold's `init`, `step` or `merge` is `NK1132`.

Each of the four is a separate function below (a closure, an `async move`
block, an `async` block per branch, a closure handed to the fold driver), and a
branch cannot go to a label in another function. The message names which of the
four stands in the way; the help says *decide inside, act outside*. The same
rule is why a `??` whose fallback jumps is lowered to a `match` and not to
`unwrap_or_else`, which takes a closure.

*Was ADR-084 D4; the `??` lowering is ADR-138 §5's.*

### D17 — A `catch` handler is not one of them.

A handler lowers to a `match` arm, so `fs::read_to_string(p) catch { break }`
leaves the loop around it. A handler that jumps diverts, as one that `return`s
does, so the ordering analysis does not overlap the statement after it
([ADR-034](adr-034.md)) - except where the jump is bound to a loop written
inside the handler.

*Was ADR-084 D5, with its §3 on `diverts`.*

### D18 — The refusal is in the checker and in the emitter, and the emitter's is the guarantee.

`Flow::in_loop` is true in a loop's body and false where a lambda, a task, an
`overlap` branch or a function body begins; every statement is emitted through
one place, so a jump with no loop cannot be written whatever a walk reached.

*Was ADR-084 D6.*

### D19 — The jump rules stand last in the statement alternation.

A PEG alternation is an ordered list. Next to `return_stmt`, every statement
that is not a jump paid for two failed matches; last, only a block's closing
`}` reaches them. Both words are reserved, so no earlier arm can take one.

*Was ADR-084 D8.*

### D20 — `throw`, `return`, `break` and `continue` are expressions, and their type is never.

They may stand wherever an expression may: `find(id) ?? throw NotFound(id)`,
`else => throw OutOfRange(score)`. Never fits every expected type without
widening anything, so an arm that jumps sits beside an arm that hands back a
`&str` and the `match` is a `&str`.

*Was ADR-138 D1.*

### D21 — What a jump does is unchanged, and the statement forms remain.

A `throw` leaves the function and makes it `throws`; a `return` returns; a
`break` and a `continue` need a loop and do not cross a function boundary
(D16). A bare jump in statement position is the statement, as it was, so every
analysis that asks about a jump asks about the statement.

*Was ADR-138 D2, with its §5 on `expr_stmt`.*

### D22 — `NK1133` is unchanged, and it is what makes D20 safe.

A value written after a `break` is still refused, one position over, so D20
does not turn `break x` into a dropped value.

*Was ADR-138 D3.*

**A jump's condition**

### D23 — `return`, `throw`, `break` and `continue` may carry their condition after them.

`return 250 if speed > 250`, `throw TooFast(speed) if speed > 250`,
`continue if n % 2 != 0`, `break if done`. Each is `if cond { jump }` and the
tree the parser builds is that `if`, so every rule of `if` holds, and a
statement after `break if done` is reachable - `NK1133` does not apply.

*Was ADR-255 D1, with its §3.*

### D24 — Only after a jump.

After a jump the line says where control goes and the condition says when;
nothing else is guarded this way. `return if c { a } else { b }` is still a
`return` of an `if` expression: where a block follows the condition, the `if`
is the value. `return if done` is the bare `return`, guarded.

*Was ADR-255 D2.*

### D25 — The condition stands on the jump's line.

An `if` that begins a line is a statement of its own, as a `[` that begins one
is a list ([ADR-135](adr-135.md) D3).

*Was ADR-255 D3.*

### D26 — No new word.

`if` already guards a `match` arm (Part I 3.4); it means *only when* in both
places.

*Was ADR-255 D4.*

**The numbers that decided it**, method and full tables in
[`break-continue-cost.md`](../../history/break-continue-cost.md) and the old
records:

* a `for` that stops early: 2,000,000 turns with a flag against 1,415 with a
  `break` - unbounded in `n`; this is what decided D11 (ADR-084 §1).
* a `while` that stops mid-body: −25.0 % as first measured; with `&&` allowed
  in the head, a flag and a `break` cost the same to 165 instructions over two
  million turns - the −25 % had measured the head grammar
  ([ADR-086](adr-086.md) §3).
* `continue`: −1.0 %, shape and not speed (ADR-084 §4).
* compile time: about 740 instructions a statement and +1.28 % with the jump
  rules early, 665 a block and +0.13 % to +0.32 % with them last (D19,
  ADR-084 D8).

## 5. Consequences

* A loop is `while` or `for`; the unconditional one is `while true`, emitted as
  `loop`, and a function that ends in one that no `break` leaves needs no
  `return` after it. `NK1104` still fires on a `while` whose condition is a
  name, and on a `while true` a `break` leaves.
* `break` and `continue` cost no program a name: the words were reserved before
  they were constructs. `loop` is free for a program to use.
* Two diagnostics carry the jump rules: `NK1132` (D16) and `NK1133` (D13, D14,
  D22), in Part III C.3.
* A jump fits any expected type, so `=> throw NotFound` and `?? throw Missing`
  need no braces; a `??` whose fallback jumps is a `match` below, not a closure.
* An early exit is one line: `return 250 if speed > 250`.
* **What it costs:** leaving two loops at once is a flag or a `return`; a value
  out of a loop is a `let` or a `return`; a `while true` the walk wrongly thinks
  a jump leaves still asks for the `return` (D8).

## 6. What this does not decide

* **A labelled jump**, reopened by a measurement on a program that has the
  shape (D12).
* **`break` with a value**, and with it a `loop` keyword and a `while` as an
  expression (D2, D15).
* **A loop that is not the last statement.** The statement after a `while true`
  nothing leaves is unreachable; that wants its own diagnostic, not silence.
* **A function that never returns for another reason** - infinite recursion, a
  call that aborts. Nothing reads a call graph, and a `!`-valued call is not in
  the ledger's type language ([`open-decisions.md`](../../open-decisions.md)).
* **Refusing the now unnecessary unreachable `return`.** It stays legal; taking
  it back would break programs ([ADR-051](adr-051.md) D1's polarity).
* **A `never` a program can write** in a declaration.
* **`unless`, or a negated guard** - `if !cond` says it - and a guard after
  anything but the four jumps (D24).
