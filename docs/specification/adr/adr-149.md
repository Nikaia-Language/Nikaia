# ADR-149: A Channel Is `std`'s, and Only Bounded

**Status:** Accepted · **Built:** yes — see §5
**Date:** September 19, 2026
**Target Version:** Nikaia 0.0.31
**Related:** [ADR-141](adr-141.md) D2 (which marked the page *unspecified*),
[ADR-291](adr-291.md) (a `let` takes a flat tuple of names),
[ADR-123](adr-123.md) (`crosses`, and what may go to another thread),
[ADR-055](adr-055.md) (a task is a coroutine), [ADR-278](adr-278.md) (`T?`),
Part II 12.5

## 1. Context

Part II 12.5 writes `let (tx, rx) = channel::bounded(100)`, `tx.send(…)` and
`rx.recv()`, and [ADR-141](adr-141.md) D2 marked it *unspecified*. Nothing in
it needs syntax: two values, two methods, and the tuple `let` is built
([ADR-291](adr-291.md)). The questions are where it lives and what it
promises.

## 2. Decisions

### D1 — `std::channel`, with `bounded(n)` and nothing else.

```nika
use std::channel

let (tx, rx) = channel::bounded(100)
spawn fn { tx.send("done") }
let msg = rx.recv() ?? "nobody sent anything"
```

A module in `std` over the runtime's queue. No language construct: two methods
say everything the page's example says.

### D2 — `send` pauses when the channel is full, and the ledger says so.

`send` has no `sync` in its entry, so a `sync` body cannot send on a channel
and the compiler says which promise is in the way — without a rule about
channels, because the column is the rule. That is the point of a **bounded**
channel: back-pressure is a pause, and a pause is a thing this language's
ledger already talks about.

### D3 — `recv` hands back a `T?`, and `null` means every sender is gone.

Not a failure: a closed channel is the ordinary end of a stream, and `??` is
what reads it (Part I 3.5). A `for` over a receiver is the same loop one level
up and waits for [ADR-105](adr-105.md)'s `Seq` to have an entry for it.

### D4 — The value type must cross, checked where the sender moves.

A channel carries values to another thread, so the type must answer
[ADR-123](adr-123.md)'s `crosses`. It is checked where `tx` **moves into a
`spawn`**, as any move is — not at `send`, and not by a rule of its own:
the crossing analysis already asks that question at that place.

### D5 — There is no `unbounded()`.

A capacity is a promise about memory, and this language makes programs say
their promises. An unbounded channel is a memory leak with a name and a `send`
that never pauses, which is the one thing a program cannot reason about under
load. A program that wants *unbounded* writes a large number — and has said
it.

## 3. Consequences

* Part II 12.5's example becomes a program, and the *unspecified* mark leaves
  it.
* Back-pressure is visible in the ledger rather than in a comment.
* **What it costs:** one module in `std`, four entries, and the runtime's
  queue behind them.

## 4. What this does not decide

* **`select` over a receiver**, which is [ADR-292](adr-292.md)'s block and the
  shape that makes a channel worth having in a race.
* **A `for` over a receiver**, which wants a `Seq` entry
  ([ADR-105](adr-105.md)) and is one line the day that is written.
* **A rendezvous channel** (`bounded(0)`), which is a different promise and
  which no page writes.

## 5. What is built

All of it.

1. **The queue**, with the pause on a full `send` and on an empty `recv`, and
   the waker each end leaves for the other. A capacity below one is refused with
   its reason rather than quietly turned into something else: `bounded(0)` is
   the rendezvous channel §4 leaves undecided.
2. **`std::channel` and its four entries.** `send` carries no `sync`, `recv`
   hands back a `$T?`, and `bounded` hands back the tuple a `let` destructures.
3. **D4 is one row in a list.** `Sender` and `Receiver` joined the crossing
   analysis's containers, which is what makes *the value type must cross,
   checked where `tx` moves into a `spawn`* true — the analysis already asks
   that question at a move, so nothing about channels is written anywhere else.
4. **Part II 12.5's example as a test that runs**, and the mark off the page.

### Three things it found

* **A signature whose result has parentheses in it was read to the wrong
  place.** `Signature::parse` took `rfind(')')` for the end of the parameter
  list, and `channel::bounded` is the first entry in `std` to hand back a
  **tuple** — so the last `)` was the *result's*, the parameter list became
  everything up to it, and the whole signature was nonsense. Silently: a garbage
  parameter list still parses, and what it cost was every argument to the call
  being lent, because a parameter whose type is not known is one that moves
  ([ADR-094](adr-094.md) D1). It now counts.
* **`?? 0` needed an annotation nobody could write.** The fallback of a `??` is
  lowered with an `.into()`, because it is written as the value it stands for
  rather than as the type the option holds — which is right for `?? "none"` on a
  `String?` and wrong for a number, since Part I 2.4 already says a number
  literal takes the type its use asks for. Where the option's own type was still
  open the conversion had nothing to resolve from, and the reader got *"type
  annotations needed"* about a file nobody wrote (Part III, C.1).
* **D2 was not enforced for a method, and could not be.** `contracts::sync`
  resolves a **free** call by name and stops at a method, on the ground that only
  a type checker knows what `tx.send(1)` goes to
  ([ADR-288](adr-288.md)). So a function declaring `sync` and calling a pausing
  method lowered to an ordinary `fn` with an `.await` in its body, which is not
  Rust. `NK2202` is now raised from the type checker too — the same rule, from
  the only place that can ask it. Reachable before this record through
  `TaskHandle::join`, and found by D2's own sentence.
