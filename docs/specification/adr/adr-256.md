# ADR-256: Every `assert` Outside a Test Is Proved While the Program Is Built

**Status:** Accepted · **Built:** the MVP — see §5
**Date:** September 29, 2026
**Target Version:** Nikaia 0.0.271
**Supersedes:** [ADR-245](adr-245.md) D4's third row (*the condition is
checked at run time*) and D5 (a refutation is a warning), for every `assert`
outside a `test` block
**Related:** [ADR-245](adr-245.md) (what an `assert` is, D2-D3's purity, D6's
report), [ADR-255](adr-255.md) (a jump that carries its condition — what the
prover reads most), [ADR-010](adr-010.md) (data from outside the program)

## 1. Context

[ADR-245](adr-245.md) D4 made an `assert` a claim the compiler holds in one of
three ways — proved, refuted, or checked at run time — and built only the
third. A check at run time is a cost nobody wrote down and an abort nobody
planned for: a program that passes its tests can still stop in production on
a claim the compiler never looked at. The owner decided that a claim the
compiler cannot hold before the program runs is not a claim this language
accepts.

## 2. Decisions

### D1 — An `assert` outside a `test` block is proved, or the build fails

The compiler proves the claim from what precedes it, or refuses the program
with `NK1202`, naming the claim and what the prover knew. **No check is ever
emitted for it**: a proved claim costs nothing when the program runs, and there
is no fourth outcome.

### D2 — An `assert` in a `test` block is the test's verdict

A test exists to run code and look at the result (ADR-245 D1); its `assert`s
stay checks at run time, and a false one fails the test. D1 is about the
program, and a test is not part of the program `nikaia build` makes.

### D3 — A claim about a parameter is the caller's to establish

An `assert` at the top of a function's body that names only its parameters,
and that the body cannot prove on its own, is the function's
**precondition**. The body assumes it, and **every call proves it** with the
arguments in place of the parameters — or is refused with `NK1203`, where the
call is:

```nika
fn percent(part: i64, whole: i64) -> i64 {
    assert(whole > 0)              // a precondition: `whole > 0` at every call
    return part * 100 / whole
}

fn report(done: i64, total: i64) -> i64 {
    return 0 if total <= 0         // the guard proves `percent`'s precondition
    return percent(done, total)
}
```

Until the ledger carries a precondition, three places cannot have one, and an
unproved parameter claim there is `NK1204`: a `pub fn` (another package would
call it unchecked), a method, and a function handed on as a value instead of
called.

### D4 — A claim about data from outside the program is checked where it arrives

A value whose bytes someone else chose ([ADR-010](adr-010.md) D2: a socket,
a request, a database row) has no property a compiler can know. An `assert`
about it is refused with `NK1202`, saying where the value came from and naming
the way that works: check it with a guard where it arrives —
`throw BadInput(n) if n > 100` — after which the claim is proved from the guard
and costs nothing. The check that costs something is the one the program
wrote and handles.

### D5 — What the prover reads

* **Claims:** comparisons of whole numbers built from names, number literals,
  `+`, `-`, a unary `-` and a `*` by a constant; `true`, `false`, `&&`, `||`
  and `!`. A claim outside that is refused with a note saying so.
* **Names:** an immutable binding of a whole-number type — a parameter, a
  `let` given an integer type or a value of the shape above, and the binding
  of a `for` over a range. An unsigned type adds `x >= 0`.
* **Facts:** the branch an `if` is in; the condition a branch that always
  leaves has ruled out, which is exactly what `return … if c`,
  `throw … if c`, `break if c` and `continue if c` write ([ADR-255](adr-255.md));
  a `for` over `a..<b`'s bounds; a `let`'s value; the function's
  preconditions; and every claim proved before.
* **Numbers are integers without a limit.** A computation that would leave its
  type aborts before any comparison sees it (Part I 2.2), so what holds of
  unbounded integers holds of the program's.

### D6 — The procedure may fail to prove a true claim, and never proves a false one

Fourier-Motzkin elimination over the facts and the claim's negation, with the
integer tightening of each derived bound: a claim is proved when every case of
its negation contradicts the facts. It gives up past a fixed amount of work,
and giving up is a refusal. A later prover that proves more accepts more
programs and never changes what an accepted one does.

## 3. Consequences

* `nikaia --asserts` (ADR-245 D6) says for each claim *proved*,
  *precondition of `f`* or *checked by the test*.
* Part III 14.2 says so; ADR-245's header names this record.
* A program with an `assert` the MVP cannot read no longer builds. That is D1
  working: the claim was a check at run time before, and now it is either
  proved or written as the guard it was.

## 4. What this does not decide

* A precondition in the ledger, which lifts D3's three exclusions.
* Claims over text, lists, fields and calls (`xs.len() > 0`): the prover grows
  a theory at a time, each by its own record.
* A counterexample in the message, which is ADR-245 D5's other half.

## 5. What is built

`crates/nikaia/src/prove.rs`, run after the checker: D1-D6, with `NK1202` to
`NK1204`. `tests/prove.rs` holds each decision.
